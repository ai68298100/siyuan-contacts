## 为什么做这个插件

手机通讯录只存号码，商业 CRM 只为销售服务。**人脉是笔记内容的一部分**——会议记录里提到的人、聚会认识的朋友、日记里的往来，都应该长在你的知识库里，而不是锁在某个 App 中。

小驴人脉的答案：**每个联系人就是一篇普通的思源文档**（双链、搜索、同步一切照旧），结构化信息存进与文档绑定的[思源原生数据库](https://github.com/siyuan-note/siyuan)（思源 3.8+ 的"数据库"功能），插件负责把它变成好用的管理界面。

> 🔒 **数据主权**：联系人文档与数据库保存在思源工作空间，插件无遥测。AI 分析仅在主动点击时向用户配置的思源 AI 端点发送笔记内容。卸载插件不删除人物文档，但插件自管的互动记录应先单独备份；思源自身的同步设置仍由用户控制。

## ✨ 功能

| | 功能 | 说明 |
|---|---|---|
| 🗂 | **联系人管理** | 卡片/表格双视图、即时搜索、分组与标签筛选；支持**从已有笔记批量收编**为联系人（不动文档本身）；表格列显隐/顺序偏好（姓名列固定）；疑似重复候选检查（只提示不合并） |
| 🔍 | **组合筛选与保存视图** | 标签全部/任一、最近互动日期范围、从未联系；生效条件可视可清除；常用条件可命名保存为视图，应用时按当次名册重新求值 |
| 💼 | **vCard 导入导出** | 从 iOS/Google 通讯录等导出的 `.vcf` 一键导入（同名自动跳过）；全量名册导出为标准 vCard 3.0；逐项导入报告（成功/跳过/失败/待核对）与名册核对重试 |
| 🧑‍🤝‍🧑 | **人际关系** | 数据库 relation 字段双向关联（内核自动维护回链）；关系图谱支持直接/二度关系高亮、共同联系人及最短路径查询（当前图内），路径链式呈现并可导出 Markdown 说明 |
| 📝 | **从笔记捕获** | 会议/聚会笔记里 `[[链接]]` 联系人 → 一键识别参与者、记录共同交集（时间/地点/备注）、写入「参与人员」区块；可选 AI 抽取未链接的人名 |
| 🎂 | **生日提醒** | 公历/**农历**生日投影，首页近期生日与"久未联系"仪表盘；按人物自定义联系节奏或暂停提醒 |
| ✅ | **跟进事项与行动清单** | 日期型联系计划（推迟/完成/取消/重开），到期出现在今日行动清单；行动清单合并生日、节奏与跟进三源，逾期可批量顺延到今天；打开工作台显示当日摘要 |
| 📄 | **人物文档档案条** | 打开联系人文档自动显示资料条，编辑资料全字段可改；会面简报可导出 Markdown（资料/最近互动/未完成跟进/重要日期/相关人物/共同出席） |
| 📊 | **交往回顾报表** | 按月/自选区间的互动次数、同场活动数、联系人数与来源分布；Top 排行与上期对比，口径可解释 |
| 📝 | **互动时间线与模板** | 每批 20 条、搜索/来源/日期范围筛选、按月分组、历史上的今天；单条确认删除；备注模板（内置见面/电话/聚会，支持本地变量） |
| 🔌 | **人员服务桥** | 对其他插件暴露 `window.LvContacts`：搜索/创建联系人、记录共同交集（[接入文档](docs/BRIDGE.md)） |
| 🛟 | **备份与恢复** | 互动事件与跟进事项的 JSON 快照导出；恢复先预览差异明细（新增/跳过/删除标记影响）再确认合并；导出中心集中于设置页 |
| 📱 | **移动端** | 全屏弹窗与响应式布局，已有移动视口隔离回归；真机触控、软键盘与安全区仍待验收 |

## 📦 安装

- 集市提交暂缓，当前请使用手动安装：
  1. 从 [Releases](https://github.com/ai68298100/siyuan-contacts/releases) 下载 `package.zip`
  2. 解压到思源工作空间 `data/plugins/siyuan-contacts/`（保持目录名与插件名一致）
  3. 重启思源 → 设置 → 集市 → 下载 → 启用「小驴人脉」
- 要求：**思源笔记 ≥ 3.8.5**

## 🚀 快速上手

1. **初始化**：顶栏点击人脉图标 → 向导自动创建「人脉」笔记本、联系人总表与数据库（字段一次配齐）
2. **建人**：「联系人」页新建、「导入已有文档」批量收编存量人名笔记，或导入通讯录 `.vcf` 文件
3. **建关系**：详情面板里添加相关人（双向自动回链）；「关系图谱」页查看全景
4. **记交集**：会议/聚会笔记右键 → 人脉：捕获本文人员 → 勾选参与者、填日期地点
5. **看提醒**：「首页」近期生日（含农历）、久未联系一目了然
6. **备份互动**：「设置」导出互动备份；恢复时查看新增、跳过与删除影响，确认后合并。备份是 JSON 值快照而非文件字节副本，合并保留删除标记，不复活已删除记录。

从联系人数据库安全解绑不会删除人物文档或互动。时间线删除只删除当前人物的一条互动，不删除来源笔记或其他参与者的记录。

当前源码为 **v0.2.1**，`docs/PROGRESS.md` 已记录对应 GitHub Release：在 v0.2.0 的 16 项增量功能之上，修复首次引导初始化在真实宿主上必然失败、且重试撞「已存在同名笔记本」卡死的问题（写入端点返回体形状与数据库物化参数），并把初始化链改为幂等可续建——重跑向导只补缺失，不重复建、不删除已有内容。真实宿主、移动真机、多窗口和集市提交仍按文档分别验证或授权。

## 🛠 开发

```bash
pnpm install
pnpm dev            # 监听构建 + 思源内热重载
pnpm check          # tsc + svelte-check
pnpm test           # 域层单测 + 架构守门 + i18n parity
pnpm test:ui        # 桌面组件与服务链隔离回归
pnpm test:ui:mobile # 移动视口隔离回归（不等于真机验收）
pnpm build          # dist/ + package.zip
pnpm check:release  # 发布门禁
pnpm spike          # 隔离内核 API 验证（9 项）
pnpm spike:init     # 隔离内核：初始化续建/锚点还原实证（21 项）
node scripts/e2e/contacts-flow.mjs   # 真内核流程 E2E（10 项）
```

设计决策见 [docs/DECISIONS.md](docs/DECISIONS.md)，路线图见 [docs/ROADMAP.md](docs/ROADMAP.md)，更新日志见 [docs/CHANGELOG.md](docs/CHANGELOG.md)。
当前愿景与 16 项增量功能的分批计划见 [产品与开发总计划](docs/PRODUCT-PLAN.md)（F01–F16 已全部落地）；计划项与已发布能力的差异以更新日志为准。
