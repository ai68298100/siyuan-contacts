# 关系图谱与思源双链接入研究（2026-10-12）

推荐保留一块占主要视区的图谱画布，采用“人物关系 / 思源双链”两个明确数据模式。人物关系表达用户维护的联系人与组织事实；思源双链读取同一工作区的原生引用索引。两者可互相跳回人物、组织和文档，但不能将引用、同组织或共同出席推断为人物关系。

本轮修正了一个实际副作用：之前的引用模式通过原生图端点传入固定配置，可能重置用户在思源原生图中设置的筛选与绘图参数。已改为只读 `refs`/`blocks` 文档投影；不借打开面板或暂存/恢复设置绕开这个问题。

## 本轮接入方式

`src/api/graph.ts` 保留现有服务的图形数据形状，但内部改用已实证的 `/api/query/sql`：

1. 全部登记文档：按最多 100 个登记源 ID 查询文档与引用，SQL 同时限制目标 ID 到同一登记集合，不做源×目标批次组合；保留可达的无引用登记文档。登记超过 10,000 时明确引导切换人物/组织中心，避免无界白名单请求。不会先取得整库图再过滤。
2. 本人、人物或组织中心：SQL 在分页前限制中心出链和回链的另一端到登记集合，并排除自引用；对端白名单按最多 10,000 ID 线性分批，超过 10,000 的登记集合仍可看局部。保留已核实中心与登记集合内的一度邻居。中心没有引用仍是可定位的单节点；中心已不可达则明确报错。
3. 相同文档内多个块引用同一文档，先按有向文档对聚合；画布再按无向文档对去重。文档引用与成员边、显式人物关系始终有不同来源。
4. 每页 200 个文档对，多取 1 条判断下一页。采用 `(root_id, def_block_root_id)` 复合游标，异常排序、重复页、越界行和畸形数据显式失败；不默默循环或显示空图。
5. 读取超过 50,000 个登记文档对会说明超限并引导选择人物/组织中心。普通笔记引用在 SQL 中排除，不占分页或读取预算，API 也校验两端范围。绘图的既有 800 节点预算仍由共用快照管理，读取预算和绘图裁剪分别说明。

服务层依旧验证登记集合、来源状态和稳定中心 ID；现有组件保留代次检查，迟到请求或已销毁实例不能覆盖新结果。引用读取走统一内核错误、权限和超时处理，不进行自动写入、补链、推断关系或配置保存。

## UI 推荐

- 图谱应是首屏焦点：主工具栏只保留模式、搜索、范围摘要与必要画布动作；分组、组织聚焦、来源说明和查询细节渐进展开。画布尽可能使用工作区宽度和剩余高度，不被多行统计卡和常驻长说明挤压。
- 选择节点后展示简洁的名称、身份/组织状态、连接来源与“查看详情 / 打开文档”。组织历史状态应保留连接而改变状态/线型，不能将毕业或离职解释为关系消失。当前 `domain/graph-query.ts#graphRegistry` 仍按 `status=active` 过滤组织投影，former 历史连接尚未补齐；这是已记录待办，应继续按 `ACTIVE-BACKLOG.md` 的历史组织关系任务完善事实、范围、查询和说明，不能声称本轮已经修复。
- 来源说明采用中文：“人物关系”“组织成员”“思源双链”。当前共用图快照经 `orderGraph` 进行无向合并，原始 ref 方向不再可靠，因此本轮引用边采用点线和“文档块引用（ref）”文字来源，暂不绘制箭头。后续若要显示引用方向，必须先调整快照契约并覆盖单向/双向引用测试；各边来源不仅靠颜色区分。
- 空结果分清未建联系人、没有匹配节点、单节点暂无引用和读取失败；各状态提供创建、清除条件、建立真实块引用说明或重试的对应出口。
- 文本视图、画布、导出共享同一快照；窄屏可选择画布或文本，均可回到中心、缩放/适应范围，并有键盘可达的节点入口。
- 原生图的可靠联动先提供“打开来源文档”，说明可从思源文档菜单打开原生关系图/反链。当前不放置宣称能直接打开原生图的无效按钮。

## 验证与限制

新生产读取隔离验证 **7/7**：启动版本、局部投影、超过一页的真实复合游标、登记全局投影、SQL 两端登记范围、白名单参数规模和宿主原生图配置保护。205 个出链文档与 1 个回链文档完整读回；同文档重复块引用合并，自引用/无关文档在分页前排除；全局保留 208 个登记文档，得到 206 个有向引用文档对。读取前后局部/全局 `dailyNote`、`type`、`d3`、`minRefs` 配置完全一致。

单次隔离实测，局部白名单 208 / 1,000 / 10,000 ID 的最大 SQL 分别为 10,829 / 50,429 / 500,429 字节，总读取为 15.20 / 17.13 / 105.41ms；后两组均 5 个 SQL 请求（2 页引用、3 页标题）。只有 208 个真实登记文档，其余过滤 ID 合法但不存在，故这组数据仅验证请求体积、解析开销和不产生批次组合，**不能当作真实 10k 联系人库性能**。耗时是本机单次结果，记录在隔离结果文件中。

API 专项 **8/8** 覆盖非法 ID/未登记中心/空登记集合、跨页完整读取、分批 SQL、失联中心、权限拒绝、异常行与游标停滞；新增模拟 50,001 条普通笔记出链及相同规模回链，局部/全局均只读 1 页、2 条登记边，验证不发生假超限。全局 10,001 ID 请求前拒绝，局部按两个线性白名单批次保留中心。既有图谱 UI 夹具同步改为只读 SQL 契约；最终 UI 门禁由本轮整体验证统一记录，不能用 API 通过代替视觉或宿主验收。

尚未承诺的能力：稳定公共 API 直接打开原生图面板；整个工作区所有笔记图的实时嵌入；多页 SQL 读取期间并发外部编辑的事务快照；真实用户大库耗时/内存和真机手势。组件代次保护会阻止旧结果覆盖页面，但切换/销毁尚未贯通 AbortSignal 到服务分页，已开始的读取可能继续下一页；目前以只读、请求超时和总预算约束，资源取消需要后续贯通统一请求链路。索引由思源维护，刚写入的块引用可能短暂滞后，可刷新核实。SQL 权限被宿主拒绝时保留失败与重试入口，不绕过权限或把失败伪装成没有引用。
