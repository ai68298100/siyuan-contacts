# 产品愿景与后续开发总计划

更新：2026-09-27。范围：基于当前源码、原型与现有契约梳理产品方向，并排入 16 项增量功能；这些计划项尚未实现。本轮不启动功能编码、不改版本、不对外发布。

## 1. 愿景与产品边界

**让用户在自己的思源知识库中，持续记住一个人、理解交往背景，并从记录自然走向下一次联系。**

核心定位沿用「一人一文档，数据库作主干」。人物不是另一个系统里的孤立名片：资料由原生文档和 AV 承载，会议、聚会、日记通过链接和互动连接到人物，插件提供查找、回顾、提醒与关系探索的工作台。

主要服务个人知识管理者的四类场景：整理已有的人物笔记；会后记录往来；见面前回顾背景；在生日或合适周期主动联系。它不是销售线索/商机 CRM，也不建设聊天平台、自动营销、抓取微信或未经确认的社交画像。

长期保留的边界：

- 人物文档与 AV 属于思源原生数据；互动、偏好和未来跟进事项属于插件自管数据。卸载并删除插件数据可能丢失后者，不能承诺「卸载后一切仍在」。
- 无遥测；思源同步由用户控制。AI 只在明确操作后向用户配置的端点发送相应内容，候选必须确认才能写入。
- 共同出席只是事实，不自动生成显式关系；最短路径只描述当前展示图，不表示关系强弱、引荐意愿或现实社交结论。
- 计划联系与已经互动分开存储。完成待办不自动伪造互动；记录互动也不应悄悄完成全部待办。
- 优先使用现有数据、既有 API 服务和本地计算。独立组织库、带方向/强度的关系库、新宿主接口另立项目，不挤入本期。

## 3. 产品目标与可检查的完成条件

以下是开发验收目标，不是已测得的用户效果，也不引入遥测：

| 目标 | 验收方式 |
|---|---|
| 找到人且不丢上下文 | 组合筛选后的列表、数量、选中态、Peek 前后翻阅一致；保存视图重开能恢复规则 |
| 记录往来足够顺畅 | 从 Peek 记录成功后保留当前人物，时间线与首页刷新；错误保留输入；重复点击不重复写入 |
| 提醒变成可执行行动 | 每条行动显示原因和日期，可查看人物、推迟或处理；完成计划与互动事实不混淆 |
| 用户能理解并带走自己的数据 | 导出前说明包含/不包含什么；备份预览零写入；恢复遵守删除标记和现有身份规则 |
| UI 在每批开发中兑现 | 每个变更页面有桌面/真实 390px、明暗主题、主要交互和异常状态证据；功能完成与视觉对齐分开记账 |
| 功能不依赖 AI 才能成立 | 关闭 AI 后查人、记录、回顾、跟进、导出全部可用；本期行动建议有确定性理由 |

## 4. UI 方向与原型的约束

保留当前架构：桌面左侧导航与内容区；移动端底部导航；联系人卡片/表格 → Peek → 完整文档；设置六分区。未来功能先放进现有入口，不为每个功能增加顶层菜单。「组织/建议」占位不等于承诺本期交付。

| 页面 | 应解决的问题 | 本期设计落点 |
|---|---|---|
| 首页 | 今天/本周应关注谁，原因是什么 | 行动清单、打开摘要、生日与久未联系保留；统计可下钻，不堆无行动的数字 |
| 联系人 | 快速定位某一群人并浏览 | 工具栏搜索/组合筛选/排序/保存视图；批量操作独立；卡片和表格主点击都打开 Peek |
| Peek | 这个人是谁、最近发生什么、下一步做什么 | 三个既有页签内加入简报、日期回顾、跟进事项；打开文档常可达；不将选中复选框与正在查看混同 |
| 图谱 | 解释已记录的连接 | 保留图内范围提示，路径结果可阅读/导出；结果与共同出席统计分开 |
| 设置 | 控制数据、提醒和隐私 | 导出中心、显示偏好、提醒偏好归入原有分区；数据去向说明与真实实现一致 |
| 导入/捕获 | 知道将写入什么以及实际成功了什么 | 识别/确认/结果，逐项原因与可恢复失败；AI 候选不直接写入 |

目前已有桌面/390px 明暗的 28 组隔离截图：五类工作台画面和设置通用/数据两区。它们能发现溢出和回归，但不是每个控件与原型一一核对的证明；全部表单、向导、空态、错误态和其余设置区仍需补覆盖。

不再安排「最后统一美化」。每批都执行以下 UI 质量线：

1. 原型先描述新增内容与状态，使用同一语义令牌、Lucide 图标、文字层级和间距规则。原型视觉意图要适配思源主题，不能靠硬编码颜色追求截图相似。
2. 桌面与移动同时设计、实现、隔离验收；检查真实 CSS 视口、页面横向溢出、长姓名/标签/提示、窄屏按钮可达性。
3. 加载、空结果、失败、重试、成功、忙碌、未保存各有明确行为。成功反馈可消失，错误与恢复操作保持可见；退出和切换不丢草稿，不绕过忙碌保护。空状态统一「三件套」：一句话定义＋填满后的示例＋单一具体行动（Basecamp/Linear 惯例）。
4. 模态框/移动全屏 Peek 管理焦点；桌面非模态 Peek 不锁住页面 Tab。Esc、关闭按钮、切人物、切页面遵循同一保存规则；移动滑动关闭尚不作为已实现能力。
5. 新功能同步中文/英文与无障碍标签；完整存量双语作为质量任务持续补齐。键表一致不代表全部界面已翻译。
6. 对照原型逐页记录「符合/有意差异及理由/待修复」，不能只用截图生成成功作为视觉通过。

## 5. 16 项不依赖实际宿主验证的功能计划

A 批 F01–F04、B 批 F05–F08、C 批 F09–F12、D 批 F13 已落地（2026-09-28，见 PROGRESS），F14–F16 状态为**待开发**。下面每项都是面向用户的增量功能；双语、测试、文档和视觉校准另外列为质量线，不计入 16 项。

2026-09-28 扩大外部调研（个人 CRM / 笔记生态 / 通讯录导入 / 思源集市与图谱 / 回顾提醒五路）结论：A、B 批方向全部得到印证；各家验证过的成熟细节已并入下表 MVP 与验收描述；新增候选与明确不吸收项见 [ROADMAP](ROADMAP.md)「外部调研候选池」与 [DECISIONS](DECISIONS.md) D-0018。

验证分两类：**L**＝纯本地投影/偏好及隔离浏览器；**S**＝复用现有服务，在隔离浏览器中替换存储或既有 API 响应并注入失败。两者都不需要打开实际思源、真实设备或实际宿主多窗口；S 不能证明宿主运行兼容性。所有新持久化都须先补 DATA-CONTRACT，再实现 normalize、写后回读、锁与旧版本兼容。

| F13 疑似重复人物检查 | 联系人「整理」按规范化电话/邮箱和姓名给候选、理由及并排资料；只跳转现有编辑入口，不合并/解绑/改写原生文档。修复入口带待处理角标；「合并/解散/展开预览」三操作（Google Merge & fix）为远期增强，需独立可撤销设计 | 现有名册；补匹配规则说明，无新存储；L | 同名不等同同人；空字段不匹配；号码格式差异、邮箱大小写等有固定样例；查看候选零写入；国家码不猜测补全 |

## 6. 执行顺序、质量任务与下一版范围

| 批次 | 功能顺序 | 同批必须完成的质量任务 | 退出条件 |
|---|---|---|---|
| A | F01 → F02 → F03 → F04 | Q01：既有草稿/忙碌离开路径、统一反馈；Q02：联系人/设置逐帧原型对照 | 四项验收成立；卡片/表格/设置桌面与移动明暗及失败态可复核 |
| B | F05、F06 → F07 → F08 | Q03：跟进契约、兼容与备份；Q04：首页/Peek 新状态原型；存量相关文案双语 | 能完整演示创建计划→到期显示→查看人物→记录/处理→刷新；不伪造互动 |
| C | F09、F10 → F11、F12 | Q05：时间/统计口径、导出隐私范围；互动与报表的键盘/长文本覆盖 | 模板、日期回顾、简报、报表显示和导出相互一致 |
| D | F13 → F14；F15、F16 可独立排入 | Q06：导入/捕获/初始化向导及其余设置区截图；完成存量双语与异常反馈核查 | 不因重复判断、重试、恢复或图谱结果误导用户；无未经确认的破坏性写入 |

Q 项是贯穿质量要求，不是另凑功能数量。Q01 中草稿保护先完成当前会话内安全退出；跨重启自动恢复属于另行候选，需独立隐私与存储设计。初始化只完善已有流程的状态/失败可恢复说明，不臆造恢复 API。

**下一稳定版候选最小范围：A 批 + B 批及其质量任务。** 这使下一版同时解决原型欠账与「下一次联系」闭环。C/D 是已排入的后续功能，不为了数量强塞同一次发布；若跟进存储安全或核心 UI 未收敛，不以完成数量替代质量。批次是执行顺序，不是承诺发版版本号或人日；旧 UI 估算不再用作剩余工期。

每项开工顺序：契约（如需）→ 原型状态 → 域逻辑/服务 → 页面 → 隔离验收 → 更新进度/提交。功能、视觉、隔离验证分别记录状态，不能一项完成代替另外两项。

## 7. 验证与延期边界

- 本期不启动实际宿主、真机或实际多窗口验证；这些项目标记「按要求跳过、未验证」，不当开发阻塞，也不写成通过。
- 新数据结构的 normalize、默认值、版本处理、删除/身份冲突先用纯测试；存储故障、并发和导入用隔离替身。浏览器锁的成功不外推到真实思源同步或多窗口。
- 每批按仓库协议跑 `pnpm check`、`pnpm test`；涉及界面跑桌面及真实 390px 隔离回归、受影响页面明暗截图；涉及构建/发布候选跑 `pnpm build` 与 `pnpm check:release`。本次只改规划文档，复查文档链接并跑基础检查，不重复截图或打包。
- AI/官方 Agent 注册、新内核端点、操作系统通知、真实跨插件联动、同步冲突保证、独立组织库/类型关系库及迁移均不在 16 项承诺范围。未来有确切需求与契约后再排。
- 版本变更、推送、Release、集市提交需另行授权。隔离验收完成只是候选交付就绪，不等于实际宿主兼容性已经验证。
