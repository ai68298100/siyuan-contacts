# 小驴人脉 · 全产品 UI 系统规范

> 这是页面结构、交互语言、视觉原则和原型验收的统一设计基准。可交互原型见 [ui-prototype.html](ui-prototype.html)，行为、数据和页面覆盖待办见 [FEEDBACK-BACKLOG.md](FEEDBACK-BACKLOG.md) 的 UX-03 与 UI-AUDIT-02。实际功能状态以源码和最新交付记录为准，原型不代表宿主或真机验收已经通过。
>
> 本规范从当前产品定位与工作区事实出发；候选能力不会因为出现在规划区就成为已承诺功能。涉及新存储、宿主 API、绑定关系或写入语义的改动，仍须先遵循 AGENTS.md 和 DATA-CONTRACT.md。

## 1. 产品定位与体验承诺

小驴人脉帮助用户在自己的思源知识库中，持续记住一个人、理解交往背景，并从记录自然走向下一次联系。联系人档案以普通思源文档和 AV 绑定行作为可见事实来源；互动、跟进和偏好遵循仓库既有的数据边界。

它是一款个人知识工作流中的人脉记忆工具。它帮助用户找回“这个人是谁、我们最近聊过什么、哪些共同背景有记录、下一步由我决定做什么”。它不做销售漏斗、社交评分、自动营销、外部社交资料抓取，也不把 AI 推测伪装成事实。

体验承诺：

1. **本地可控**：清楚说明联系人资料、互动和插件数据分别存在哪里；高风险写入可预览，取消后不写入。
2. **事实有来源**：区分用户录入、思源双链、组织成员和 AI 提名；能回到来源时提供入口，来源失效时明确说明。
3. **提醒不评判**：每条建议说明触发原因和日期；跳过或暂缓不改变关系事实，不用“亏欠”“落后”等施压文案。
4. **由浅入深**：列表先解决找人；Peek 给出下一步；完整文档保留资料和知识；高级筛选、来源和诊断按需展开。
5. **失败能恢复**：明确已完成、未完成、未知和可重试对象；保留安全草稿，不将读取失败显示为零条数据。
6. **核心不依赖 AI**：关闭 AI 后仍能建档、搜索、互动记录、跟进、组织管理、回顾和导出。

## 2. 设计状态与事实边界

原型、代码和用户可用状态分开记录。页面上若出现未来方向，必须附带以下其中一个状态：

| 标签 | 含义 | 允许的表达 |
|---|---|---|
| 当前已有 | 当前开发分支代码中存在；仍以进度记录区分隔离测试和宿主验证 | “已在当前分支实现”；不能推导为真实宿主验收通过 |
| 宿主待验 | 代码路径已存在，但思源接口、原生面板、真机或多窗口行为还未得到对应证据 | 显示具体待验边界和可用回退方式 |
| 设计目标 | 本文和原型明确用户体验，功能实现、数据契约或测试还未完成 | 作为待办，不写成现有能力 |
| 候选评估 | 方向尚未决定是否进入产品；须先有研究、隐私、维护成本和数据契约评估 | 仅放在候选区，不放进当前用户导航 |

本原型使用虚构样例。功能状态看源码与 PROGRESS；设计覆盖看本文与原型；真实宿主、真机和多窗口验证单独记账。历史 UI-01～UI-12 只作为过往任务记录，不能覆盖新的页面和状态基准。

## 3. 用户、主要任务与信息架构

### 3.1 主要用户任务

- 初次使用：确认数据将保存在哪里，安全初始化，只建一位联系人并完成第一次记录。
- 日常回忆：从首页知道哪些事情值得处理、为什么出现，然后决定联系、推迟或忽略。
- 查找与维护：通过姓名、联系方式、标签、分组、组织和互动时间定位人物；批量操作前理解范围。
- 理解一个人：看资料、互动时间线、跟进计划、共同背景和来源，再选择下一步。
- 记录现场：从笔记捕获已确认的人和事件，检查 AI 候选与将发生的写入。
- 管理群体：查看组织当前或历史成员，从组织与人物两侧维护一致的归属事实。
- 保障数据：运行只读体检、修复锚点、导入、导出或恢复，并看懂逐项结果。

### 3.2 工作台导航

桌面工作台主导航为：首页、联系人、关系图谱、组织、设置。人物详情作为共享 Peek 或当前原型中的独立检视页，不占主导航入口。笔记捕获、收编与文档档案条从上下文入口打开。初始化只在需要建立工作区时出现。移动端底部导航保留首页、联系人、图谱、组织、设置；次级工作流沿用全屏页面或对话框。

不在主导航放置 Agent、日历、收藏、温度评分、外部社交同步等候选能力。组织是当前产品页面，不得标为“二期占位”。关系图谱的自研关系图和思源原生引用图是两个明确模式，不得把宿主待验写成已完成验证。

### 3.3 主要对象之间的路径

首页提醒 → 人物 Peek → 记录互动 / 处理跟进 / 打开文档
联系人列表 → 搜索筛选 → 卡片或表格 → Peek → 完整人物文档
组织 → 成员与历史归属 → 人物 Peek → 组织背景
图谱 → 文本或画布结果 → 人物 / 组织 → 来源
思源笔记 → 捕获预检 → 候选确认 → 写入预览 → 逐项结果
联系人页 → 收编 / vCard / 粘贴 → 字段映射 → 冲突核对 → 逐项结果
设置 → 诊断 / 锚点 / 备份恢复 → 影响预览 → 明确确认 → 可核对结果

每个路径都保存来源上下文。返回时尽量恢复入口页、筛选、当前页、滚动位置、图谱范围和键盘焦点；无可恢复来源时，给出清晰的联系人页或首页出口。

## 4. 页面与功能规范

### 4.1 首页：今日工作台

**目的**：回答“今天有哪些人或记录值得我看一眼”，而非展示无法采取行动的数字墙。

- 页头以简短欢迎、日期和一条主要操作为主；主要操作优先“添加联系人”，次要操作为“记录互动”。
- 统计卡展示名册、待办、本月互动、资料整理等可下钻数据，并注明统计口径；卡片需可键盘访问。
- 今日行动按跟进到期、生日、用户设置的联系节奏排序；每一项显示来源、触发原因、相关日期和上次互动日期。
- 处理动作分清记录已发生互动、完成跟进、推迟、跳过和暂缓。完成计划不自动制造互动事实。
- 后续提醒和交往回顾位于次级区域；空间或桥连接状态不能喧宾夺主。
- 首次使用给“添加一位联系人 / 导入旧资料”的两个可理解入口。空列表不能展示统计为零后就结束。
- 模块读取部分失败时分块保留成功内容，并将故障模块标记为未知或失败；不显示成空列表。

### 4.2 联系人：查找、分组和整理

- 工具栏核心顺序：搜索、筛选、排序、视图方式、创建。低频的列设置、导出、重复检查和批量整理放在次级菜单。
- 搜索覆盖姓名、电话、微信、邮箱和标签；筛选包括分组、标签全部/任一、组织、互动日期及从未联系。每次过滤显示当前命中数。
- 保存视图应可看见名称、当前条件和结果数；修改/删除只影响视图，不影响联系人记录。
- 卡片承担快速识别：姓名、分组、组织或职业摘要、少量标签、最近互动和一个主要进入详情的动作。卡片不能把电话或私人字段无遮蔽地暴露在过密网格中。
- 表格承担密集比较：姓名、分组、组织、最近互动、跟进等用户可选列。小屏下允许横向滚动并固定关键识别列或提供卡片回退。
- 卡片与表格主要点击行为一致，进入同一人物详情；复选框只负责选择，不负责打开详情。
- 批量操作先显示当前页范围和全部筛选范围，执行前复核选中数、目标对象、动作和可逆性；部分成功保留失败对象选择。
- 疑似重复只给出候选和区分证据；同名不能自动合并。联系人新建允许渐进补录，不用完整度造成压力。
- 空名册给新建和导入；空筛选显示具体条件，并可清除或放宽；异常与权限问题不得显示为“0 人”。

### 4.3 人物详情：Peek、时间线与计划

详情头部固定显示姓名、分组/身份、最近互动和重要来源。编辑、打开文档、关闭/返回入口易发现；删除或解绑作为带影响说明的低频危险操作。上一位/下一位按当前名册范围移动，不悄悄改变筛选。

三项主 Tab：

- **概览**：人物事实、联系渠道、最近互动、未完成跟进、节奏设置、共同背景和事实型会前简报。每组信息标注来源或更新时间；无来源不可用时明示。
- **互动**：按时间倒序，支持加载更多、搜索、日期和来源筛选、历史上的今天及模板。互动是已发生的联系；创建、编辑或删除语义遵循现有数据契约。记录失败保留草稿。
- **相关人**：显示有记录的人物关联、组织成员、共同背景和来源状态。组织事实与人物关系在文案和图例中区分；不能将“未记录”表达成“没有关系”。

记录互动表单优先保持轻量：人物、可选模板和备注。当前手动记录接口按当前时间生成事件；互动类型和可编辑历史日期不在该表单的现行数据契约中。若要增加这些字段，先评估事件 schema、幂等键、时间线/联系节奏口径、导入导出、备份恢复和旧数据迁移，再更新 DATA-CONTRACT。捕获或导入中的历史日期只按其各自已定义流程处理，不由手动表单暗示支持。跟进表单明确计划日期、事项和提醒状态。完成、推迟、跳过、取消和重新打开使用不同动作和结果描述。

### 4.4 关系图谱：双模式与等价信息

- 模式清楚区分“关系图”和“思源原生引用”，显示图的来源类型和当前范围。
- 工具栏可定位人物、筛选分组/组织/孤立节点、选中心、比较人物、查询共同联系人、寻找路径、缩放和回到范围。
- 显示当前节点/边数量、过滤条件和绘图上限；截断必须说明裁掉的范围与如何收窄，不能静默漏人。
- 人物关联、组织成员、文档引用各有线型/形状/文字来源等非颜色标识；选中状态和错误状态也不能只改色。
- 点边可看关系来源、时间及其可访问状态；点节点可进入对应人物或组织详情。
- 路径和共同联系人结果明确是当前筛选范围内的查询，不推导信任、亲密度或引荐意愿。
- 提供和画布同源的文本列表视图，至少列出范围、节点和边、来源、路径链、无路径原因及截断状态。两种呈现共享查询结果和导出内容。
- 原生图的真实宿主面板与引用链接需单独按进度验收。

### 4.5 组织：当前归属、历史与共同背景

- 组织列表展示类型、当前成员和历史成员数量，支持搜索和类型筛选。
- 组织详情展示说明、当前成员、历史成员、时间区间及反向人物入口；不可达人物或文档不得静默消失。
- 人物与组织两侧展示同一成员事实。添加、结束成员关系或更换组织时，说明会影响的两侧资料、关系图和来源块。
- 归档不是删除历史。归档或解绑前显示成员和链接影响；动作后按对象列出成功、跳过、失败，并提供安全恢复入口。
- 当前与历史成员由文字状态和日期表达，不能仅由颜色区分。

### 4.6 设置与数据安全：六个目的明确的分区

1. **通用**：默认页面、卡片/表格偏好、列、排序、启动行为；当前未保存内容有明确状态。
2. **数据与字段**：存储边界说明、锚点、字段检查/补建、只读健康检查、导入导出、迁移与恢复。修复和恢复前展示目标对象与影响。
3. **提醒**：生日和联系节奏偏好、暂缓与恢复；解释提醒规则，允许关闭或调整。
4. **AI 与隐私**：总开关、配置端点、调用前预检、发送范围和日志边界。关闭 AI 后不阻断主流程。
5. **服务桥**：版本、协议、能力、可达状态和权限范围；读取失败与“当前没有能力”分开。
6. **关于**：产品数据原则、兼容说明、帮助和脱敏反馈入口。

高风险操作不得藏在宽泛的“高级”按钮里。备份恢复需要预览包含内容、覆盖边界、冲突、删除墓碑和逐项结果；锚点重绑需要唯一证据，候选歧义时停止写入。

### 4.7 初始化与首次成功

- 预检在任何写入前说明笔记本、宿主文档、AV 和插件自管数据将如何处理。
- 精确显示复用对象与新建对象。多个同名库或 AV 时由用户根据字段和来源选择，不自动取首个候选。
- 未知读取、权限失败、候选歧义都阻断写入并保留现场。
- 初始化按可续做步骤展示结果和失败位置；重试不重复创建。完成页确认创建了什么，提供“添加一位联系人”和“稍后导入”两条入口。
- 本人档案是否可跳过应依照当前产品决定和数据契约表达，不能强迫用户输入私人信息。

### 4.8 笔记捕获与 AI 候选

三步为“识别 → 确认写入 → 结果与来源”：

- 识别区分笔记双链匹配、已有联系人、AI 提名和待消歧人物。AI 提名显示证据片段和所在位置，默认未选中。
- AI 外发预检展示用途、选中的文档和正文范围、发送字段、端点、估计规模、排除字段、缩小范围和取消按钮。端点信息来源真实可查。
- 确认写入前逐人物列明互动、资料、跟进、关系和原笔记区块各将新增、更新、跳过或保持不变的内容。
- 用户可逐项确认、拒绝、跳过不确定候选；取消或超时不得回填 AI 输出或产生部分写入。
- 完成后逐项显示成功、重复跳过、失败、来源不可达和未知；安全重试只处理可重试项。
- 错误路径保持原笔记内容和人物草稿，提供回到编辑候选与查看来源的出口。

### 4.9 收编、vCard、粘贴与逐项补录

- 来源步骤让用户选择思源文档、vCard 或粘贴内容，并说明读取范围和本地解析方式。
- 解析之后先展示字段映射、候选总数、新增/疑似重复/冲突/无效项；尚未确认前不写入。
- 姓名相同只是重复候选之一，必须给出可供人工比较的资料来源或其他字段。
- 冲突处理策略明确作用对象：逐项确认、跳过冲突或保留原值；避免模糊“自动合并”。
- 结果页持久显示成功、跳过、待确认、失败和未知。支持筛选、查看对象、修正映射和安全重试，不重复处理成功项。
- 补录允许逐个完成或稍后处理；缺少可选资料不阻塞联系人使用。

### 4.10 文档档案条

- 展示姓名、分组、生日/最近互动/待跟进的有限徽标、少量可公开联系字段和折叠简报。
- 所有字段沿用已确认来源，不在文档条自动生成推断内容。
- 联系方式可复制或按既有产品决定打开；失败、空值和过期值有明确反馈。
- “打开人脉”携带当前人物稳定身份；“编辑资料”“记录互动”“添加跟进”视实现情况作为次级快捷操作。
- 移动宽度折叠次级字段，不能遮挡正文或滚动操作。

### 4.11 共用对话框与辅助流程

共用入口包含：新建/编辑人物、互动、跟进、关系、筛选、批量预览、重复核对、补录、组织新增/编辑/归档影响预览、捕获确认、导入映射、健康检查、锚点重绑、备份与恢复、AI 外发预检、脱敏诊断。

表单按任务分组，说明必填项与可选项。低风险快速表单用标准宽度；数据映射或结果对比用宽版；移动端转换为全屏流程。弹窗有明确标题、说明、主次操作和关闭方式；保存中防重复，Esc、遮罩点击和关闭按钮遵循同一草稿守卫。

## 5. 全局交互原则

- **上下文先于捷径**：任何跨页入口携带稳定人物/组织 ID 和必要筛选；返回恢复原工作状态。
- **选中与打开分离**：复选框、主详情入口和文档入口有不同 hit target 与辅助标签。
- **具体范围先于确认**：批量、导入、组织成员、迁移恢复和 AI 外发均显示对象数、字段、数据来源和后果。
- **结果可留存**：长任务和部分成功在页面内保留结果；Toast 只做附加确认，不能是唯一回执。
- **失败可识别**：零结果、读取失败、权限不足、部分成功、超时和结果未知使用不同状态与恢复方法。
- **输入可恢复**：加载或写入失败保留安全草稿；不可安全重试时先要求核对，避免重复写入。
- **无静默改变**：切换筛选、图模式或页面时保留或明确清除条件；跨窗口刷新不静默覆盖草稿。
- **不制造关系评价**：统计描述记录覆盖与日期，不构造“关系质量”“价值”或未证实的趋势评分。

## 6. 视觉语言和令牌

### 6.1 颜色和主题

正式实现遵守 [src/style/_tokens.scss](../src/style/_tokens.scss)：B3 主题变量 → 语义令牌 → 插件组件。只有令牌文件桥接思源变量；新增组件消费 lvct 令牌，禁止在组件 SCSS 写颜色字面值或直接引用 B3 变量。原型在插件根下直接使用带 fallback 的 B3 映射，服务于浏览器演示，不作为新增组件写法范例。

| 语义 | 规范 |
|---|---|
| 表面 | app 外壳、内容、卡片、浮层形成清楚层级；边框和背景共同分层，避免每一区域都套卡片 |
| 正文 | 正文、次级说明、非关键辅助使用清楚的三级层次；任何必需信息不能只使用低对比的辅助色 |
| 主色 | 一个页面仅突出一个最主要提交动作；焦点环与选中态复用主色 |
| 成功/警告/错误 | 使用语义 token，同时配图标、文本和明确动作；禁止只靠色相表达状态 |
| 分组 | 颜色仅帮助快速定位，分组名必须同时可读；图谱使用形状、线型和来源标签补充 |
| 主题 | 跟随思源主题；暗色避免纯黑大块和刺眼高亮；阴影随主题变化，关闭强制全局颜色 |

明暗切换不应造成文字、边界、聚焦环、图谱线和不可用态消失。颜色对比需满足 WCAG 2.2 AA 文本对比要求；非文本控件边界和焦点状态保持可辨认。

### 6.2 字体、层级和排版

- 字族继承思源及操作系统字体；姓名和页面标题优先清晰，避免过多粗体。
- 参考现有 token 梯度：展示 20px、页面标题 16px、区块标题约 14px、正文 13px、说明 12px、微标签 11px。移动端正文不因空间压缩低于舒适阅读尺寸。
- 正文行高约 1.55–1.65；数字和日期使用一致格式；长姓名与长组织名可换行或省略且提供完整可访问名称。
- 页面标题回答“当前在哪里/处理什么”；副标题补充范围或关键规则，不复述菜单名。
- 页头、区块、行项目的对齐线保持稳定；时间、状态、来源和动作遵循一致顺序。

### 6.3 间距、表面、圆角和动效

- 4px 基础网格：4/8/12/16/24/32 或沿用 token 中登记尺寸。
- 主要点击项桌面至少 32px，移动至少 40px；常用表单控制高度约 38–44px。
- 按钮、输入框、列表项、卡片、对话框圆角层级建议 7/10/14/18px，与正式令牌保持同步。
- 使用轻分隔、留白和文字层级构建页面，不为每张信息加重阴影；浮层阴影只说明空间层级。
- 动效用于确认操作和页面切换，常规过渡 120–200ms，上限 250ms；遵守 prefers-reduced-motion。
- 层级为内容 < Peek < 模态 < 菜单/Toast。浮层不可超出可视区，不遮挡提交反馈；移动弹层适配安全区和软键盘。

### 6.4 图标、头像和图表

- 图标优先使用仓库已采用的语义图标体系；同一操作全站固定图形和可见文字。
- 图标按钮必须有 aria-label 和足够点击区域。危险操作不依赖红色图标表达。
- 头像以姓名首字或已确认图像呈现，分组颜色只是辅助；头像加载失败有稳定首字回退。
- 图表和图谱附标题、范围、筛选、数据量、文字替代和来源；悬停不能是唯一读取方式。

## 7. 响应式、键盘和无障碍

### 桌面

工作台采用左侧导航、内容区和按需打开的详情 Peek。内容宽度优先可读，不让表格和文档无限铺满。普通 Peek 不抢占整个页面；模态需要焦点管理。

### 移动

移动断点优先由真实容器宽度验证，而不把浏览器 UA 当能力判断。实现仍须遵守仓库约定，由 getFrontend() 判定思源移动前端。底部导航固定五个主入口；详情为移动全屏对话框；卡片单列；统计 2×2；筛选与批量收进可取消、可应用、可重置的次级面板。

390px 需要逐页检查长中文姓名、多个标签、软键盘、系统返回、安全区、底部按钮、图谱工具栏、表格滚动和错误反馈。滑动不能成为唯一入口；桌面 hover 功能需在触屏上有点击替代。真实设备验证单独记录，不能用 viewport 截图代替。

### 键盘和辅助技术

- 所有操作可通过键盘完成；Tab 顺序与视觉顺序一致，焦点清晰可见。
- 对话框打开后将焦点移入；关闭后回到原触发控件；Tab 不逃出模态。关闭按钮使用可访问名称。
- Tab 页签支持当前选择和可读名称；列表、表格、开关、复选框和图谱替代视图使用正确语义。
- 异步加载、筛选计数、写入进度、部分成功和错误通过 role=status / aria-live 播报。避免每个渲染变化重复播报。
- 错误关联到具体字段，并把焦点送至摘要或第一个可恢复动作；图谱提供文本等价视图。
- 颜色之外使用图标、线型、形状、文字标签和位置；验证缩放、键盘焦点和色觉差异。

## 8. 内容语气、隐私和 AI 呈现

语气亲和、克制、事实导向。用“距上次互动 52 天”代替“你很久没联系”；用“提醒依据：你设定每 30 天查看一次”代替“关系正在降温”。说明动作结果，例如“推迟 7 天，不会删除互动记录”。错误直接说明哪些结果未知以及下一步，不责怪用户。

AI 内容要有明确标识和来源证据。显示“AI 提名 / 待确认”，不得把候选作为已确认人物或事实。外发前显示实际范围、字段和端点；用户可缩小范围或取消。操作日志、诊断和错误报告不得带出姓名、联系方式、笔记正文、密钥或访问令牌。模型生成内容仅作为草稿；需要写入时由用户逐项确认。

后续若评估 Agent 或写权限，必须先设计只读/写入权限拆分、用户授权、影响预览、撤销和审计；不得因为设计原型里有一个按钮就暗示 Agent 已可用。

## 9. 状态矩阵和页面验收

所有页面及高风险弹窗至少考虑以下状态；并非每页都需要将每种状态画成独立全屏，但触发、文案、数据保持和恢复行为必须明确。

| 状态 | 用户要知道什么 | 页面要求 |
|---|---|---|
| 首次进入 / 加载 | 正在读取哪部分，是否可操作 | 使用骨架；不显示空数据作为完成状态 |
| 正常数据 | 当前范围和数据来源 | 显示范围、关键事实与主操作 |
| 真正为空 | 空的是全库、筛选结果还是某个模块 | 简洁说明原因和一到两个具体入口 |
| 部分失败 | 哪些模块可用、哪些未知 | 保留已成功数据，模块级重试 |
| 处理中 | 对象、进度、是否可取消 | 锁定重复提交，支持合理取消或说明不可取消 |
| 完成 / 部分成功 | 成功、跳过、失败、未知分别多少 | 页面内保留结果和后续动作 |
| 完全失败 | 数据是否改变、输入是否保留 | 区分零写入与结果未知；提供安全恢复 |
| 能力不可用 | 缺什么能力、是否有替代方式 | 不误导为“无数据”，保证核心手动路径 |
| 未保存草稿 | 将丢失什么 | 继续编辑、保存离开、放弃三个可理解选择 |
| 跨窗口变化 | 哪个对象更新、草稿是否冲突 | 先比较，避免静默覆盖 |
| 移动 / 明暗 | 操作和信息是否仍可达 | 触控、键盘、软键盘、对比和安全区检查 |

原型浏览器顶部的状态预览选择器可快速切换通用状态说明；它不代表所有页面已拥有对应状态画面。UX-03.27 要为首页、联系人、人物详情、组织、图谱、捕获、导入、设置和档案条登记页面级状态证据与适用性，再按 PAGE-STATUS 逐页验证，不能以通用状态提示或截图代替行为测试。

## 10. 原型使用与设计交接

打开 docs/ui-prototype.html 后，可通过左侧导航切换 10 个产品视图与 UI 规范页；顶部可切换状态、桌面/390px 和明暗预览。联系人页支持卡片/表格切换，人物详情支持 Tab 与返回上下文，图谱切换不同的关系数据、图例和文本结果，导入支持来源/核对/逐项结果演示，设置支持六分区切换。主要交互预览覆盖建档、互动、跟进、组织影响、导入、备份恢复、AI 预检、健康检查、锚点和初始化。

原型中所有“确认”均为演示，不连接思源、不进行持久化、不代表当前功能已实现。投产实现需遵循组件分层、B3 令牌、数据契约与架构测试。页面实际能力、状态、宿主依赖和代码证据以 FEEDBACK-BACKLOG、PAGE-STATUS、源文件与最新 PROGRESS 为准。

设计对齐评审记录三类结果：**符合原型**、**有意差异及理由**、**待修正**。差异影响数据安全、上下文、状态或移动交互时应先更新规范、原型和待办，再实现。不要只比较截图颜色；需要逐页核对内容、层级、状态、交互结果、键盘、移动和明暗主题。

## 11. 候选扩展区

这些方向仍然需要独立评估，不出现在当前导航，也不计为当前能力：自定义重要纪念日、礼物与人情往来、周回顾文档、档案谈资与“下次可问”、日历同步、地图、OCR/二维码名片、组织嵌套、完整类型化关系库、AI 主动建议或 Agent 写入。

候选进入开发前评估用户价值、维护与宿主依赖、隐私/外发、数据契约、导入导出、移动交互、可解释性和失败恢复。研究结束可选择纳入、继续候选或明确不做。
