> **下一轮视觉基准（2026-10-12）：** 用户指定本机小驴闪卡 R54 为期望效果，并要求综合参考小驴拾遗、管家和常用的最新原型。闪卡的视觉迁移记录见 [R54 视觉参考](UI-REFERENCE-R54-2026-10-11.md)，跨插件模式和本轮落点见 [跨插件参考记录](UI-REFERENCE-CROSS-PLUGIN-2026-10-12.md)。重点是清楚主次、白色轻描边卡片、连续留白、页面级状态和可恢复搜索流程，人物详情继续采用正常居中窗口。

## 1. 产品定位与体验承诺

### 工作台品牌头像边界

左上角头像是工作台的显示偏好，默认使用简洁“驴”字，可由用户改为少量文字或本地位图。它只保存在 `view-preferences.json`，不进入联系人事实、组织 Logo、vCard 或 CardDAV 数据；图片固定裁切到品牌标记尺寸，失败或非法输入回退到原头像。联系人头像和组织标识仍按各自业务来源显示。

小驴人脉帮助用户在自己的思源知识库中，持续记住一个人、理解交往背景，并从记录自然走向下一次联系。联系人档案以普通思源文档和 AV 绑定行作为可见事实来源；互动、跟进和偏好遵循仓库既有的数据边界。

它是一款个人知识工作流中的人脉记忆工具。它帮助用户找回“这个人是谁、我们最近聊过什么、哪些共同背景有记录、下一步由我决定做什么”。它不做销售漏斗、社交评分、自动营销、外部社交资料抓取，也不把 AI 推测伪装成事实。

体验承诺：

1. **本地可控**：清楚说明联系人资料、互动和插件数据分别存在哪里；高风险写入可预览，取消后不写入。
2. **事实有来源**：区分用户录入、思源双链、组织成员和 AI 提名；能回到来源时提供入口，来源失效时明确说明。
3. **提醒不评判**：每条建议说明触发原因和日期；跳过或暂缓不改变关系事实，不用“亏欠”“落后”等施压文案。
4. **由浅入深**：列表先解决找人；人物详情窗口给出下一步；完整文档保留资料和知识；高级筛选、来源和诊断按需展开。
5. **失败能恢复**：明确已完成、未完成、未知和可重试对象；保留安全草稿，不将读取失败显示为零条数据。
6. **核心不依赖 AI**：关闭 AI 后仍能建档、搜索、互动记录、跟进、组织管理、回顾和导出。

## 2. 设计状态与事实边界

原型、代码和用户可用状态分开记录。页面上若出现未来方向，必须附带以下其中一个状态：

| 标签 | 含义 | 允许的表达 |
|---|---|---|
| 当前已有 | 当前开发分支代码中存在；仍以进度记录区分隔离测试和宿主验证 | “已在当前分支实现”；不能推导为真实宿主验收通过 |
| 宿主待验 | 代码路径已存在，但思源接口、原生面板、真机或多窗口行为还未得到对应证据 | 显示具体待验边界和可用回退方式 |
| 设计目标 | 本文和原型明确用户体验，功能实现、数据契约或测试还未完成 | 作为待办，不写成现有能力 |
| 候选评估 | 方向尚未决定是否进入产品；须先有研究、隐私、维护成本和数据契约评估 | 仅放在候选区，不放进当前用户导航 |

本原型使用虚构样例。功能状态看源码与 PROGRESS；设计覆盖看本文与原型；真实宿主、真机和多窗口验证单独记账。历史 UI-01～UI-12 只作为过往任务记录，不能覆盖新的页面和状态基准。

## 3. 用户、主要任务与信息架构

### 3.1 主要用户任务

- 初次使用：确认数据将保存在哪里，安全初始化，只建一位联系人并完成第一次记录。
- 日常回忆：从首页知道哪些事情值得处理、为什么出现，然后决定联系、推迟或忽略。
- 查找与维护：通过姓名、联系方式、标签、分组、组织和互动时间定位人物；批量操作前理解范围。
- 理解一个人：看资料、互动时间线、跟进计划、共同背景和来源，再选择下一步。
- 记录现场：从笔记捕获已确认的人和事件，检查 AI 候选与将发生的写入。
- 管理群体：查看组织当前或历史成员，从组织与人物两侧维护一致的归属事实。
- 保障数据：运行只读体检、修复锚点、导入、导出或恢复，并看懂逐项结果。

### 3.2 工作台导航

桌面工作台主导航为：首页、联系人、关系图谱、组织、设置。人物详情不占主导航入口，所有业务入口复用同一正常居中模态窗口，桌面沿用共用宽版对话框的 720px 宽度；视口宽度 ≤640px 时使用完整屏幕窗口。组织业务详情与管理也使用共用窗口，不采用右侧抽屉。笔记捕获、收编与文档档案条从上下文入口打开。初始化只在需要建立工作区时出现。移动端底部导航保留首页、联系人、图谱、组织、设置；次级工作流沿用全屏页面或对话框。

不在主导航放置 Agent、日历、收藏、温度评分、外部社交同步等候选能力。组织是当前产品页面，不得标为“二期占位”。关系图谱的人物关系与思源文档引用投影是两个明确数据模式；引用数据在本插件绘制，不等于嵌入或打开思源原生面板，不得把宿主待验写成已完成验证。

### 3.3 主要对象之间的路径

首页提醒 → 人物详情窗口 → 记录互动 / 处理跟进 / 打开文档
联系人列表 → 搜索筛选 → 卡片、姓名或表格 → 人物详情窗口 → 完整人物文档
组织 → 成员与历史归属 → 人物详情窗口 → 组织背景
图谱 → 文本或画布结果 → 人物 / 组织 → 来源
思源笔记 → 捕获预检 → 候选确认 → 写入预览 → 逐项结果
联系人页 → 收编 / vCard / 粘贴 → 字段映射 → 冲突核对 → 逐项结果
设置 → 诊断 / 锚点 / 备份恢复 → 影响预览 → 明确确认 → 可核对结果

每个路径都保存来源上下文。返回时尽量恢复入口页、筛选、当前页、滚动位置、图谱范围和键盘焦点；无可恢复来源时，给出清晰的联系人页或首页出口。

## 4. 页面与功能规范

### 4.1 首页：今日工作台

**目的**：回答“今天有哪些人或记录值得我看一眼”，而非展示无法采取行动的数字墙。

- 页头以简短欢迎、日期和一条主要操作为主；主要操作优先“添加联系人”，次要操作为“记录互动”。
- 统计卡展示名册、待办、本月互动、资料整理等可下钻数据，并注明统计口径；卡片需可键盘访问。
- 今日行动按跟进到期、生日、用户设置的联系节奏排序；每一项显示来源、触发原因、相关日期和上次互动日期。
- 处理动作分清记录已发生互动、完成跟进、推迟、跳过和暂缓。完成计划不自动制造互动事实。
- 后续提醒和交往回顾位于次级区域；空间或桥连接状态不能喧宾夺主。
- 首次使用给“添加一位联系人 / 导入旧资料”的两个可理解入口。空列表不能展示统计为零后就结束。
- 模块读取部分失败时分块保留成功内容，并将故障模块标记为未知或失败；不显示成空列表。

### 4.2 联系人：查找、分组和整理

- 工具栏核心顺序：搜索、筛选、排序、视图方式、创建。低频的列设置、导出、重复检查和批量整理放在次级菜单。
- 搜索覆盖姓名、电话、微信、邮箱、组织和标签；原型搜索仅过滤演示名册，并以稳定人物 ID 同步卡片与表格，避免同名联系人串项。输入框使用显式标签并关联结果区与辅助说明；桌面 `/` 快捷键只在联系人页、弹窗外且非表单/输入法组合时生效，清除按钮清空并把焦点还给输入框。每次过滤显示当前命中数。
- 保存视图应可看见名称、当前条件和结果数；修改/删除只影响视图，不影响联系人记录。
- 卡片承担快速识别：头部只放头像、姓名和简短的生日等识别信息；家庭、工作单位、学校、与我的关系放在头部下方的独立资料区，避免把姓名挤成狭窄文本列。已知为空的可选关系字段不反复显示“未填写”；历史组织条数、待核对归属和读取未知提示必须保留，不把毕业或离职经历误当成空资料。
- 已填写的联系方式按固定图标列与可换行内容列排列，长邮箱、微信和姓名完整可读，不用省略号掩盖识别信息。卡片网格按内容高度向上对齐，最小高度只保持基本节奏，不用固定高度、强制等高或裁切换取对齐；标签与主要动作使用稳定的间距和分隔。
- 表格承担密集比较：姓名、分组、组织、最近互动、跟进等用户可选列。小屏下允许横向滚动并固定关键识别列或提供卡片回退。
- 卡片、姓名、表格与首页提醒的主要点击行为一致，进入同一人物详情窗口；复选框只负责选择，不负责打开详情；电话、邮件和文档入口保留各自的明确动作。
- 已载入名册状态、当前选择范围和选中人数合并为精简提示区；显示多少条就使用对应数量，部分载入或读取失败不得冒充全名册已完成。
- 批量操作先显示当前页范围和全部筛选范围，执行前复核选中数、目标对象、动作和可逆性；部分成功保留失败对象选择。
- 疑似重复只给出候选和区分证据；同名不能自动合并。联系人新建允许渐进补录，不用完整度造成压力。
- 空名册与搜索无命中是两种状态：空名册给新建和导入；搜索无命中显示当前词并可清除或新建。加载、读取失败优先于筛选状态且不得被搜索重置；异常与权限问题不得显示为“0 人”。真实窄屏与 390px 原型预览需保持搜索框和清除按钮至少 44px 触控尺寸。

### 4.3 人物详情：正常窗口、时间线与计划

人物详情统一复用共用宽版模态窗口：桌面最大宽度 720px，空间不足时收缩到可视区域；视口宽度 ≤640px 时覆盖完整可用屏幕。首页、联系人卡片、姓名、表格、组织成员和图谱等入口沿用同一组件与稳定人物 ID，不再使用右侧抽屉。内容在窗口内部滚动，背景工作台保持原搜索、筛选、列表位置和图谱范围。

详情头部显示姓名、分组/身份、最近互动和重要来源。长姓名与身份说明完整换行；三项主要操作保持等宽，在详情内容容器宽度不足 520px 时移至独立下一行。关系资料使用最小约 150px 的自适应列，长字段继续换行。编辑、打开文档、关闭/返回入口易发现；删除或解绑作为带影响说明的低频危险操作。上一位/下一位按当前名册范围移动，不悄悄改变筛选。

打开窗口后焦点移入并锁定在当前模态，背景不可操作；关闭后恢复原入口焦点和上下文。详情内的编辑人物、新建组织或其他子窗口必须显示在详情上层，只有最上层窗口接收 Tab、Esc 和遮罩操作。子窗口关闭后回到详情内的原触发控件，完成保存后按既有流程刷新相关资料，不关闭或遮盖父窗口。

三项主 Tab：

- **概览**：人物事实、联系渠道、最近互动、未完成跟进、节奏设置、共同背景和事实型会前简报。每组信息标注来源或更新时间；无来源不可用时明示。
- **互动**：按时间倒序，支持加载更多、搜索、日期和来源筛选、历史上的今天及模板。互动是已发生的联系；创建、编辑或删除语义遵循现有数据契约。记录失败保留草稿。
- **相关人**：显示有记录的人物关联、组织成员、共同背景和来源状态。组织事实与人物关系在文案和图例中区分；不能将“未记录”表达成“没有关系”。

记录互动表单优先保持轻量：人物、可选模板和备注。当前手动记录接口按当前时间生成事件；互动类型和可编辑历史日期不在该表单的现行数据契约中。若要增加这些字段，先评估事件 schema、幂等键、时间线/联系节奏口径、导入导出、备份恢复和旧数据迁移，再更新 DATA-CONTRACT。捕获或导入中的历史日期只按其各自已定义流程处理，不由手动表单暗示支持。跟进表单明确计划日期、事项和提醒状态。完成、推迟、跳过、取消和重新打开使用不同动作和结果描述。

### 4.4 关系图谱：双模式与等价信息

- 模式明确标为“关系图”和“文档引用”，分别展示用户维护的人物/组织事实与思源双链索引；显示当前登记范围与来源类型，引用、成员归属不能自动推断为人物关联。
- 全端默认 `canvas`，保留显式“画布 / 文本”切换与文本节点定位入口。桌面默认画布 `clamp(520px, 68dvh, 880px)`，移动默认 `clamp(400px, 58dvh, 640px)`；“展开大图”增大阅读区域，分别为 `clamp(640px, 82dvh, 1040px)` 与 `clamp(480px, 76dvh, 800px)`，不是调用宿主全屏或原生图面板。
- 首要工具只保留数据模式、节点搜索、阅读方式和导出；范围、组织收窄、分组、无关系人物、显示组织与图例默认折叠。画布内提供适配、放大、缩小、重新布局、展开/收起大图、刷新六项可达操作；未准备好的画布动作禁用并解释原因。
- 首屏计数与范围采用紧凑摘要，加载、部分失败、未知来源和裁剪仍明确可读。关系探索（直接/二度、共同联系人、最短路径）与来源/排除/诊断详情位于图后，按需展开；截断说明绘图上限、裁掉范围和可恢复的收窄办法。
- 人物关联用实线、组织成员用虚线、文档引用用点线，结合来源文字而非仅靠颜色。当前 `ref` 绘图按无向文档对去重：不会绘制方向箭头，也不将任意节点排序解读为原始引用方向；有向源数据与画布投影口径必须区分。
- 节点信息卡与文本节点均有“打开来源文档”，经 `facade.openDoc` 打开当前节点文档。组织卡“打开组织视图”传递选中的 `orgDocId`，直接打开对应组织管理弹窗；人物节点沿用详情窗口，返回不丢失图范围。
- 路径、直接/二度与共同联系人仅使用当前展示图的显式 `related` 人物边，组织成员或文档引用边不参与；无路径/零结果明确限定当前范围，不推导现实信任、亲密度或引荐意愿。
- 画布、文本、搜索、范围和导出共用同一快照。文本列出范围、节点、边及来源、路径、无路径原因和截断状态；文本替换画布而非追加在图下，切换保留条件。空结果、单节点无引用、未核实来源与读取失败分别提供建档、清除条件、块引用说明或重试入口。
- 思源双链接入使用已验证 SQL 只读 `refs` / `blocks`，登记本人、联系人与活跃组织文档；查询在分页前限制登记两端、验证复合游标、预算、中心可达性与权限。不得调用会保存传入 `conf` 的 `getGraph` / `getLocalGraph`，也不暂存/恢复宿主配置；具体边界见 [图谱接入研究](GRAPH-RESEARCH-2026-10-12.md)。
- “打开来源文档”后的说明引导用户从思源文档菜单进入原生图或反向链接。目前不提供声称通过稳定公共 API 直接打开原生图的按钮，原生宿主面板和真机仍单独验收。原型对应入口只展示清晰的文档/组织操作说明，不尝试打开虚构宿主文档。
- **历史关系待办**：当前图谱成员投影仍仅纳入 `active` 记录，`former` 离职/毕业历史记录的连线保留尚未落实；须同步关系契约、筛选、查询、来源标签与导出，不能因原型展示历史状态就宣称生产已完成。远期跨简历弱联系另按待办优先级研究。

### 4.5 组织：当前归属、历史与共同背景

- 组织列表展示名称、简称、介绍及当前/历史成员概况，支持名称搜索和活跃/已归档状态筛选。组织类型与成员状态筛选仍须按设计状态记录，不作为当前已有能力陈述。
- 组织卡片的 Logo 与无图回退统一为 40px，不随图片原始尺寸扩大；名称使用可完整换行的独立内容列，简称与介绍按层级排布。活跃/归档徽标占独立网格位置，不覆盖或挤压名称；卡片按内容高度向上对齐，成员概况与操作区使用一致分隔和间距。
- 组织详情展示说明、当前成员、历史成员、时间区间及反向人物入口；不可达人物或文档不得静默消失。
- 组织业务详情与管理沿用正常模态窗口；由人物详情进入新建组织时，组织窗口位于人物窗口上层，保存或取消后恢复组织选择上下文。
- 人物与组织两侧展示同一成员事实。添加、结束成员关系或更换组织时，说明会影响的两侧资料、关系图和来源块。
- 归档不是删除历史。归档或解绑前显示成员和链接影响；动作后按对象列出成功、跳过、失败，并提供安全恢复入口。
- 当前与历史成员由文字状态和日期表达，不能仅由颜色区分。

### 4.6 设置与数据安全：六个目的明确的分区

1. **通用**：默认页面、卡片/表格偏好、列、排序、启动行为；当前未保存内容有明确状态。
2. **数据与字段**：存储边界说明、锚点、字段检查/补建、只读健康检查、导入导出、迁移与恢复。修复和恢复前展示目标对象与影响。
3. **提醒**：生日和联系节奏偏好、暂缓与恢复；解释提醒规则，允许关闭或调整。
4. **AI 与隐私**：总开关、配置端点、调用前预检、发送范围和日志边界。关闭 AI 后不阻断主流程。
5. **服务桥**：版本、协议、能力、可达状态和权限范围；读取失败与“当前没有能力”分开。
6. **关于**：产品数据原则、兼容说明、帮助和脱敏反馈入口。

高风险操作不得藏在宽泛的“高级”按钮里。备份恢复需要预览包含内容、覆盖边界、冲突、删除墓碑和逐项结果；锚点重绑需要唯一证据，候选歧义时停止写入。

### 4.7 初始化与首次成功

- 预检在任何写入前说明笔记本、宿主文档、AV 和插件自管数据将如何处理。
- 精确显示复用对象与新建对象。多个同名库或 AV 时由用户根据字段和来源选择，不自动取首个候选。
- 未知读取、权限失败、候选歧义都阻断写入并保留现场。
- 初始化按可续做步骤展示结果和失败位置；重试不重复创建。完成页确认创建了什么，提供“添加一位联系人”和“稍后导入”两条入口。
- 本人档案是否可跳过应依照当前产品决定和数据契约表达，不能强迫用户输入私人信息。

### 4.8 笔记捕获与 AI 候选

三步为“识别 → 确认写入 → 结果与来源”：

- 识别区分笔记双链匹配、已有联系人、AI 提名和待消歧人物。AI 提名显示证据片段和所在位置，默认未选中。
- AI 外发预检展示用途、选中的文档和正文范围、发送字段、端点、估计规模、排除字段、缩小范围和取消按钮。端点信息来源真实可查。
- 确认写入前逐人物列明互动、资料、跟进、关系和原笔记区块各将新增、更新、跳过或保持不变的内容。
- 用户可逐项确认、拒绝、跳过不确定候选；取消或超时不得回填 AI 输出或产生部分写入。
- 完成后逐项显示成功、重复跳过、失败、来源不可达和未知；安全重试只处理可重试项。
- 错误路径保持原笔记内容和人物草稿，提供回到编辑候选与查看来源的出口。

### 4.9 收编、vCard、粘贴与逐项补录

- 来源步骤让用户选择思源文档、vCard 或粘贴内容，并说明读取范围和本地解析方式。
- 解析之后先展示字段映射、候选总数、新增/疑似重复/冲突/无效项；尚未确认前不写入。
- 姓名相同只是重复候选之一，必须给出可供人工比较的资料来源或其他字段。
- 冲突处理策略明确作用对象：逐项确认、跳过冲突或保留原值；避免模糊“自动合并”。
- 结果页持久显示成功、跳过、待确认、失败和未知。支持筛选、查看对象、修正映射和安全重试，不重复处理成功项。
- 补录允许逐个完成或稍后处理；缺少可选资料不阻塞联系人使用。

### 4.10 文档档案条

- 展示姓名、分组、生日/最近互动/待跟进的有限徽标、少量可公开联系字段和折叠简报。
- 所有字段沿用已确认来源，不在文档条自动生成推断内容。
- 联系方式可复制或按既有产品决定打开；失败、空值和过期值有明确反馈。
- “打开人脉”携带当前人物稳定身份；“编辑资料”“记录互动”“添加跟进”视实现情况作为次级快捷操作。
- 移动宽度折叠次级字段，不能遮挡正文或滚动操作。

### 4.11 共用对话框与辅助流程

共用入口包含：人物详情、新建/编辑人物、互动、跟进、关系、筛选、批量预览、重复核对、补录、组织详情/新增/编辑/归档影响预览、捕获确认、导入映射、健康检查、锚点重绑、备份与恢复、AI 外发预检、脱敏诊断。

表单按任务分组，说明必填项与可选项。低风险快速表单用标准宽度；人物详情、数据映射或结果对比沿用 720px 宽版；≤640px 时转换为完整屏幕窗口。弹窗有明确标题、说明、主次操作和关闭方式；长内容内部滚动，适配安全区和软键盘。保存中防重复，Esc、遮罩点击和关闭按钮遵循同一草稿守卫；嵌套窗口按打开顺序提升层级与管理焦点，不让新建组织或编辑窗口落到详情后面。

## 5. 全局交互原则

- **上下文先于捷径**：任何跨页入口携带稳定人物/组织 ID 和必要筛选；返回恢复原工作状态。
- **选中与打开分离**：复选框、主详情入口和文档入口有不同 hit target 与辅助标签。
- **具体范围先于确认**：批量、导入、组织成员、迁移恢复和 AI 外发均显示对象数、字段、数据来源和后果。
- **结果可留存**：长任务和部分成功在页面内保留结果；Toast 只做附加确认，不能是唯一回执。
- **失败可识别**：零结果、读取失败、权限不足、部分成功、超时和结果未知使用不同状态与恢复方法。
- **输入可恢复**：加载或写入失败保留安全草稿；不可安全重试时先要求核对，避免重复写入。
- **无静默改变**：切换筛选、图模式或页面时保留或明确清除条件；跨窗口刷新不静默覆盖草稿。
- **不制造关系评价**：统计描述记录覆盖与日期，不构造“关系质量”“价值”或未证实的趋势评分。

## 6. 视觉语言和令牌

### 6.1 颜色和主题

正式实现遵守 [src/style/_tokens.scss](../src/style/_tokens.scss)：B3 主题变量 → 语义令牌 → 插件组件。只有令牌文件桥接思源变量；新增组件消费 lvct 令牌，禁止在组件 SCSS 写颜色字面值或直接引用 B3 变量。原型在插件根下直接使用带 fallback 的 B3 映射，服务于浏览器演示，不作为新增组件写法范例。

| 语义 | 规范 |
|---|---|
| 表面 | app 外壳、内容、卡片、浮层形成清楚层级；浅色卡片与普通面板保持白色，由轻背景、留白、边框和轻阴影区分，避免每一区域都套卡片 |
| 正文 | 正文、次级说明、非关键辅助使用清楚的三级层次；任何必需信息不能只使用低对比的辅助色 |
| 主色 | 一个页面仅突出一个最主要提交动作；焦点环与选中态复用主色 |
| 成功/警告/错误 | 使用语义 token，同时配图标、文本和明确动作；禁止只靠色相表达状态 |
| 分组 | 颜色仅帮助快速定位，分组名必须同时可读；图谱使用形状、线型和来源标签补充 |
| 主题 | 跟随思源主题；暗色避免纯黑大块和刺眼高亮；阴影随主题变化，关闭强制全局颜色 |

明暗切换不应造成文字、边界、聚焦环、图谱线和不可用态消失。颜色对比需满足 WCAG 2.2 AA 文本对比要求；非文本控件边界和焦点状态保持可辨认。

### 6.2 字体、层级和排版

- 字族继承思源及操作系统字体；姓名和页面标题优先清晰，避免过多粗体。
- 参考现有 token 梯度：展示 20px、页面标题 16px、区块标题约 14px、正文 13px、说明 12px、微标签 11px。移动端正文不因空间压缩低于舒适阅读尺寸。
- 正文行高约 1.55–1.65；数字和日期使用一致格式；人物与组织卡片、详情头部的长姓名和长组织名完整换行，联系方式使用固定图标列和可换行内容列。密集表格等确需省略的位置保留完整可访问名称。
- 页面标题回答“当前在哪里/处理什么”；副标题补充范围或关键规则，不复述菜单名。
- 页头、区块、行项目的对齐线保持稳定；时间、状态、来源和动作遵循一致顺序。

### 6.3 间距、表面、圆角和动效

- 4px 基础网格：4/8/12/16/24/32 或沿用 token 中登记尺寸。
- 主要点击项桌面至少 32px，移动至少 40px；常用表单控制高度约 38–44px。
- 按钮、输入框、列表项、卡片、对话框圆角层级建议 7/10/14/18px，与正式令牌保持同步。
- 使用轻分隔、留白和文字层级构建页面，不为每张信息加重阴影；浮层阴影只说明空间层级。
- 每个视口保留一个“视觉焦点”：通常是当前任务标题或主操作。指标、状态和快捷入口围绕焦点排列，不把所有模块做成同等重量的卡片。
- 同一视图最多使用两级提升阴影（内容面/浮层）；普通面板优先使用背景差异和 1px 描边。连续堆叠的卡片必须合并为一个面板或改成无框列表。
- 信息密度分为“扫描”和“专注”两档：列表/表格用于快速比较，人物/组织详情用于逐组阅读；切换密度只改变间距和可见字段，不改变事实或筛选范围。
- 动效用于确认操作和页面切换，常规过渡 120–200ms，上限 250ms；遵守 prefers-reduced-motion。
- 层级为工作台内容 < 正常详情/管理模态 < 后打开的编辑/新建子模态 < 当前窗口的菜单与反馈。只有最上层模态可交互和接收焦点；子窗口不可被父窗口遮盖。浮层不可超出可视区，不遮挡提交反馈；移动窗口适配安全区和软键盘。

### 6.4 图标、头像和图表

- 图标优先使用仓库已采用的语义图标体系；同一操作全站固定图形和可见文字。
- 图标按钮必须有 aria-label 和足够点击区域。危险操作不依赖红色图标表达。
- 头像以姓名首字或已确认图像呈现，分组颜色只是辅助；头像加载失败有稳定首字回退。
- 组织卡片 Logo 与回退标识固定为 40px；图片保持比例并限制尺寸，组织名称和归档徽标使用各自网格位置。
- 图表和图谱附标题、范围、筛选、数据量、文字替代和来源；悬停不能是唯一读取方式。

### 6.5 参考图提炼后的现代化视觉原则

本节吸收用户提供的仪表盘、客服工作台和项目管理界面中的通用优点，保持小驴人脉的本地、事实和低压力定位。参考图只作为视觉研究，不引入其业务对象或插画素材。

**安静画布，明确焦点。** 工作台使用中性画布承载内容，品牌色只用于当前导航、主要提交、焦点环和需要快速定位的状态。页头、指标和内容区保持同一条对齐线；大面积渐变、装饰性插画和无来源的“智能评分”不进入正式页面。

**指标是入口，不是装饰。** 首页指标带最多展示四项，每项必须有统计口径、时间范围和可下钻动作；没有可采取动作的数据不单独占用指标位。数字、变化和说明按“值 → 含义 → 入口”排列，移动端按 2×2 或纵向列表折叠。

**焦点区 + 上下文区。** 参考软件中“主内容 + 来源或下一步区域”的结构作为通用研究保留；小驴人脉当前人物、组织业务详情使用正常模态窗口，相关事实和操作在窗口内分组呈现。来源面板等辅助上下文布局仍是可评估的创意，不标为已实现的详情侧栏。若后续采用辅助区域，不复制主内容，也不能承载唯一操作；移动端顺序阅读时提供同等入口。

**用进度表达事实覆盖。** 资料完整度、导入进度和长任务使用进度条或逐项结果，旁边同时显示已完成/待处理数量和下一步。进度不等于关系质量，不使用红黄绿评分催促用户。

**色彩是角色系统。** 同一页面只突出一个主色；成功、待确认、失败和信息状态各自使用语义令牌并配文本或图标。分组色只帮助定位，姓名、组织和来源始终以文字呈现。暗色主题降低表面层差异，避免纯黑背景和高饱和霓虹色。

**丰富来自反馈，而非堆叠。** 悬停、按下、选中、加载、保存、部分失败和草稿状态均提供轻量反馈；按钮、标签、菜单和面板沿用同一圆角、间距和焦点环。渐进披露优先于一次展示所有字段，低频工具收进上下文菜单或折叠区。

### 6.6 精细化视觉验收（2026-10-11）

本轮原型细化将“高级感”落在可复用的界面行为上，而不是增加装饰元素：

- **层级**：顶部工具栏在滚动时保持轻微半透明和模糊，工作区侧栏与内容面之间保留一条低强度分界；内容面板使用极轻的双层阴影，浮层继续使用更高一级阴影。
- **焦点**：页面标题、区块标题、主要按钮和当前导航各只有一个明确强调点。区块标题使用短强调线，当前导航与设置分区用位置线和底色同时表达，不依赖颜色单独识别。
- **反馈**：按钮提供悬停、按下、禁用和主操作的不同反馈；指标卡悬停时出现短进度线；列表行、输入框和分段控件在可操作状态下有边界变化。所有反馈都不改变布局尺寸。
- **密度**：桌面内容区保持 32px 顶部留白和 24px 页头间距；面板头部与正文采用不同内边距；移动端保留 2×2 指标和单列内容，操作按钮仍满足触控目标，不用缩小文字换取密度。
- **克制**：装饰性渐变只用于聚焦区的低对比背景，颜色、阴影和圆角不得同时达到高强度。无数据、失败和不可用状态沿用文字说明与恢复动作。

原型中的这些规则用于评审实现的一致性；正式组件仍须消费 `src/style/_tokens.scss` 的语义令牌，并在暗色主题、键盘焦点、减少动效和 390px 视口下分别验收。

**实现映射与验收：**

| 视觉模式 | 原型/实现映射 | 验收条件 |
|---|---|---|
| 聚焦页头 | `.lvct-page-head`、`.lvct-page-actions` | 标题、范围、主操作一眼可见；主按钮每页最多一个 |
| 指标带 | `.lvct-grid--stats`、可下钻 `.lvct-stat--action` | 显示口径与范围；点击进入对应列表或报表 |
| 业务详情窗口 | 人物详情、组织详情/管理、共用宽版对话框 | 桌面居中 720px，≤640px 全屏；内部滚动，关闭恢复上下文，子窗口位于上层 |
| 辅助上下文研究 | 来源面板、下一步区域的布局创意；并非已实现详情侧栏 | 不复制事实，不承载唯一操作；明确设计状态，移动顺序可读 |
| 轻量状态 | `.lvct-chip`、`.lvct-callout`、`role=status` | 颜色之外有文字/图标；失败、未知和空态不混淆 |
| 进度与结果 | `.lvct-progress`、逐项结果行 | 数量、取消边界和重试对象清楚；不会只用 Toast 回执 |
| 密度切换 | 联系人卡片/表格、设置分区 | 只改变呈现密度，不改变筛选、排序和数据事实 |

参考图中的插画、营销横幅、外部头像和“AI 评分”不作为小驴人脉默认组件；只有当素材本身是用户已确认的组织 Logo、人物头像或来源文档预览时才可进入事实区域。

### 6.7 页面质感配方（2026-10-11）

本轮针对“整体页面不够有质感”的评审，将质感拆成可验收的表面配方，适用于原型和正式组件：

- **安静画布**：工作区采用中性底色叠加极低对比的径向光晕和颗粒纹理，只在页面上方或内容起始处出现，透明度足够低，不影响文字对比，也不把背景变成装饰图。
- **三段表面**：外壳、内容面、浮层分别承担背景、承载和空间提升。普通面板使用 1px 描边、顶部微光和双层低强度阴影；连续信息优先合并为一个面板或无框列表。
- **光线方向一致**：顶部工具栏与侧栏的高光从上方/内侧进入，卡片顶部保留一条细微亮边；阴影向内容外侧扩散，避免同一页面出现相互矛盾的投影方向。
- **排版呼吸**：页面标题与首个内容模块之间保留一段完整留白；面板头部比正文多一层纵向间距，数字使用等宽数字特性，长说明控制行宽并保持 1.6 左右行高。
- **材质克制**：渐变只用于聚焦页头、上下文区或品牌标记，使用同一主色的低对比混合；不同时叠加高饱和渐变、重阴影和大圆角。暗色主题降低纹理和高光强度，保留表面差异。
- **控件触感**：输入框和按钮具有内侧高光与轻微底部阴影，悬停只提升描边或表面，按下通过 1px 位移反馈；所有变化不改变布局尺寸，焦点环仍清楚可见。

**质感验收**：桌面和 390px 移动视口各抽查首页、联系人、组织、设置和弹窗；明暗主题下确认内容层级、边界、文字对比、滚动顶部工具栏和底部导航仍清晰。若纹理、阴影或渐变抢过标题、主操作或错误信息，应降低表面效果而不是继续增加装饰。

## 7. 响应式、键盘和无障碍

### 桌面

工作台采用左侧导航和内容区；人物详情、组织详情与管理按需打开正常居中模态窗口，不以右侧抽屉挤占列表。人物详情复用 720px 共用宽版，随可视宽度收缩；内容内部滚动、背景保持上下文。所有入口统一焦点锁定与关闭返回，编辑人物、新建组织等子窗口在上层显示并独立处理草稿守卫。

### 移动

移动断点优先由真实容器宽度验证，而不把浏览器 UA 当能力判断。实现仍须遵守仓库约定，由 getFrontend() 判定思源移动前端。底部导航固定五个主入口；视口宽度 ≤640px 时详情与共用对话框使用完整可用屏幕，内容内部滚动并适配安全区、软键盘和系统返回；卡片单列；统计 2×2；筛选与批量收进可取消、可应用、可重置的次级窗口。

390px 需要逐页检查长中文姓名、多个标签、软键盘、系统返回、安全区、底部按钮、图谱工具栏、表格滚动和错误反馈。滑动不能成为唯一入口；桌面 hover 功能需在触屏上有点击替代。真实设备验证单独记录，不能用 viewport 截图代替。

### 键盘和辅助技术

- 所有操作可通过键盘完成；Tab 顺序与视觉顺序一致，焦点清晰可见。
- 对话框打开后将焦点移入；关闭后回到原触发控件；Tab 不逃出模态。关闭按钮使用可访问名称。
- 嵌套对话框只让最上层窗口接收键盘与焦点；关闭子窗口回到父窗口中的入口，关闭详情回到列表或首页中的入口。隐藏页签和背景页面不进入焦点顺序。
- Tab 页签支持当前选择和可读名称；列表、表格、开关、复选框和图谱替代视图使用正确语义。
- 异步加载、筛选计数、写入进度、部分成功和错误通过 role=status / aria-live 播报。避免每个渲染变化重复播报。
- 错误关联到具体字段，并把焦点送至摘要或第一个可恢复动作；图谱提供文本等价视图。
- 颜色之外使用图标、线型、形状、文字标签和位置；验证缩放、键盘焦点和色觉差异。

## 8. 内容语气、隐私和 AI 呈现

语气亲和、克制、事实导向。用“距上次互动 52 天”代替“你很久没联系”；用“提醒依据：你设定每 30 天查看一次”代替“关系正在降温”。说明动作结果，例如“推迟 7 天，不会删除互动记录”。错误直接说明哪些结果未知以及下一步，不责怪用户。

AI 内容要有明确标识和来源证据。显示“AI 提名 / 待确认”，不得把候选作为已确认人物或事实。外发前显示实际范围、字段和端点；用户可缩小范围或取消。操作日志、诊断和错误报告不得带出姓名、联系方式、笔记正文、密钥或访问令牌。模型生成内容仅作为草稿；需要写入时由用户逐项确认。

后续若评估 Agent 或写权限，必须先设计只读/写入权限拆分、用户授权、影响预览、撤销和审计；不得因为设计原型里有一个按钮就暗示 Agent 已可用。

## 9. 状态矩阵和页面验收

所有页面及高风险弹窗至少考虑以下状态；并非每页都需要将每种状态画成独立全屏，但触发、文案、数据保持和恢复行为必须明确。

| 状态 | 用户要知道什么 | 页面要求 |
|---|---|---|
| 首次进入 / 加载 | 正在读取哪部分，是否可操作 | 使用骨架；不显示空数据作为完成状态 |
| 正常数据 | 当前范围和数据来源 | 显示范围、关键事实与主操作 |
| 真正为空 | 空的是全库、筛选结果还是某个模块 | 简洁说明原因和一到两个具体入口 |
| 部分失败 | 哪些模块可用、哪些未知 | 保留已成功数据，模块级重试 |
| 处理中 | 对象、进度、是否可取消 | 锁定重复提交，支持合理取消或说明不可取消 |
| 完成 / 部分成功 | 成功、跳过、失败、未知分别多少 | 页面内保留结果和后续动作 |
| 完全失败 | 数据是否改变、输入是否保留 | 区分零写入与结果未知；提供安全恢复 |
| 能力不可用 | 缺什么能力、是否有替代方式 | 不误导为“无数据”，保证核心手动路径 |
| 未保存草稿 | 将丢失什么 | 继续编辑、保存离开、放弃三个可理解选择 |
| 跨窗口变化 | 哪个对象更新、草稿是否冲突 | 先比较，避免静默覆盖 |
| 移动 / 明暗 | 操作和信息是否仍可达 | 触控、键盘、软键盘、对比和安全区检查 |

原型浏览器顶部的状态预览选择器可快速切换通用状态说明；它不代表所有页面已拥有对应状态画面。UX-03.27 要为首页、联系人、人物详情、组织、图谱、捕获、导入、设置和档案条登记页面级状态证据与适用性，再按 PAGE-STATUS 逐页验证，不能以通用状态提示或截图代替行为测试。

## 10. 原型使用与设计交接

打开 docs/ui-prototype.html 后，可通过左侧导航切换 10 个产品视图与 UI 规范页；顶部可切换状态、桌面/390px 和明暗预览。联系人页支持卡片/表格切换和准确的载入、选择数量；人物详情以桌面 720px 居中窗口、移动完整屏幕窗口演示 Tab、关闭与上下文恢复；图谱切换不同的关系数据、图例和文本结果；导入支持来源/核对/逐项结果演示；设置支持六分区切换。UI 规范页的“视觉配方”预览展示聚焦页头、可下钻指标带、事项列表和资料覆盖进度，辅助上下文区域仅为研究创意，不代表业务详情采用侧栏。主要交互预览覆盖建档、互动、跟进、组织影响、导入、备份恢复、AI 预检、健康检查、锚点和初始化。

原型中所有“确认”均为演示，不连接思源、不进行持久化、不代表当前功能已实现。投产实现需遵循组件分层、B3 令牌、数据契约与架构测试。页面实际能力、状态、宿主依赖和代码证据以 FEEDBACK-BACKLOG、PAGE-STATUS、源文件与最新 PROGRESS 为准。

设计对齐评审记录三类结果：**符合原型**、**有意差异及理由**、**待修正**。差异影响数据安全、上下文、状态或移动交互时应先更新规范、原型和待办，再实现。不要只比较截图颜色；需要逐页核对内容、层级、状态、交互结果、键盘、移动和明暗主题。

## 11. 令牌维护与复用

正式样式按 primitive → semantic → component 三层令牌组织在 `src/style/_tokens.scss`；按钮、输入框、复选框和加载态由 `_controls.scss` 统一消费。颜色、间距、字号、行高、圆角、阴影、层级和动效不得在新组件中重新定义同义字面值。新增变体需说明用途并登记组件令牌。

可复现审计：`pnpm audit:tokens`（脚本 `scripts/audit-design-tokens.mjs`），基线和收敛报告见 `docs/TOKEN-CONSOLIDATION-2026-10-14.md`。审计扫描正式 SCSS 与原型 HTML；原型中的演示内联样式可保留，但投产样式必须优先引用 `--lvct-*`。图谱画布、响应式 `clamp()` 和头像/图标几何尺寸是登记过的布局例外。

## 12. 候选扩展区

这些方向仍然需要独立评估，不出现在当前导航，也不计为当前能力：自定义重要纪念日、礼物与人情往来、周回顾文档、档案谈资与“下次可问”、日历同步、地图、OCR/二维码名片、组织嵌套、完整类型化关系库、AI 主动建议或 Agent 写入。

候选进入开发前评估用户价值、维护与宿主依赖、隐私/外发、数据契约、导入导出、移动交互、可解释性和失败恢复。研究结束可选择纳入、继续候选或明确不做。
