## 外部调研候选池（2026-09-28）

按产品口径扩大调研（个人 CRM / 笔记生态 / 通讯录导入 / 思源集市与图谱 / 回顾提醒五路，详见 D-0018）后沉淀的候选方向。**以下全部未排期、未承诺**：进入任何批次前须先补契约与原型状态，不自动绑定版本号。

**功能候选（价值排序）**

1. 礼物/人情双向往来记录（WOLB「我送 Ta / Ta 送我」、Monica gifts/debts/promises）：新 JSON 契约，可进时间线、简报与报表——中文人情场景差异化最优先候选。
2. 星标收藏＋常用联系人置顶条（Google Starred / Cardhop widgets）：需给数据库新增星标字段（经字段健康检查机制增量补建）。
3. 档案条「谈资区」：显式记录「怎么认识的 / TA 告诉过我的事 / 下次可以问的」（Obsidian 用户工作流验证），文档模板级改动。
4. 潜在关系推荐表（Obsidian Graph Analysis 共现/共同邻居）：「常被同笔记提及但尚无关系边」提示，与无关系筛选互补；已连接行淡出。
5. 周回顾文档生成（Bases CRM 周检视仪式）：一键生成超期未联系/本周生日/待办嵌入的回顾文档。
6. 「与我的关系」称谓（Gramps Relationship to home person）与 FamilySearch 链式路径卡的逐边类型标签——依赖二期关系类型库建模。
7. 图谱时间轴回放（Gephi Timeline 范围滑杆 / Kumu 点击年份）：依赖新增「认识时间」字段契约。
8. 嵌套群组（WOLB）：现分组为扁平 select，与二期关系库/组织库一并评估。
9. Cardhop 式快速输入栏（「张三 138…」建档、「张三 电话」复制）：解析器成本中高，中远期。
10. 键盘度数聚焦（Kumu：±逐度/数字键跳度）、图例即过滤器（点图例项显隐分组）：图谱小增强，纯前端。
11. LvContacts v2 契约化：对齐打卡 API v5 的能力协商/防御性副本/契约自测包；消费打卡 getCalendarProjection 把生日投影进打卡日历。
12. 生日→系统日历出口（思源 CalDAV 同步插件已证明 AV→日历通道可行，远期外发通道）。

**展示与交互小项**：温度环（按个人节奏换算的可解释温度，挂 F06）；卡片大字显示号码（分享场景）；日历格密度圆点；空态「三件套」已入质量线（PRODUCT-PLAN §4）。

**生态与战略印证**：思源集市 528 个插件中无人脉/CRM 直接竞品（蓝海）；思源不允许插件注册新的数据库视图类型——独立工作台面板拉 AV 数据是唯一正解；云端个人 CRM 赛道收缩（Clay→me.sh、Cloze 转型、Covve 转名片扫描），本地优先路线本身是差异化论点。明确不吸收项见 D-0018。

## 性能与大规模（2026-09-27 落地 + 演进预案）

已落地（DATA-CONTRACT §4 性能预算）：
- 名册缓存（30s TTL + 写失效）：生日/久未联系/图谱/关系候选共享一次全量渲染
- 列表搜索/筛选改客户端（万级内 <1ms）+ 200/页客户端分页
- 收编批量合并（500 篇 = 1 次映射 + 3 次绑定）；图谱 800 节点上限（capGraph，按度数保留）
- SQL 安全面收敛：`/api/query/sql` 无绑定占位符（API 限制），语句组装仅在 api 层，
  进入语句的只有经 `^\d{14}-[0-9a-z]{7}$` 校验的 ID，自由文本客户端过滤

演进预案（触发条件见 DATA-CONTRACT §5）：名册持久化缓存（启动秒开）、互动事件分段、
内核侧分页列表、生日倒排索引。

## 从笔记捕获人脉（2026-09-27 落地 v0.2a + 演进设计）

**场景**：一篇会议/聚会笔记里提到多人——已入库的记"共同交集"，未入库的引导收编。

**v0.2a 已实现（确定性，零 AI 依赖）**
- 识别：笔记内的块引/双链（`((文档ID "名字"))` / siyuan://blocks 链接）经 refs 索引 100% 确定
  → 与名册交集 = 已入库参与者（E2E 实证 refs 索引覆盖 kramdown 块引）
- 确认 UI：「从笔记捕获」弹窗（命令面板"captureFromNote"或编辑器右键"人脉：捕获本文人员"）：
  勾选参与者 + 新人名单（按名收编）+ 日期/地点/备注
- 记录：每人一条互动事件（source=diary，**externalRef=笔记 ID 即"同场身份"**，幂等防重复捕获）；
  日期/地点/备注随事件保存
- 体现：①人物文档档案条与"久未联系"自动更新 ②笔记末尾写入「参与人员」双链区块
  （原生反链可见，会议文档 ↔ 人物文档互相指回）③同场人员共享 externalRef →
  后续可做"共同出席 N 次"统计与图谱"同场"虚线边
- 设计决策：共同出席**不自动建** related 关系边（同场 ≠ 有关系），只记同场事实（D-0011）

**v0.2b AI 抽取已实现（可选增强，需思源内置 AI 配置）**
- 在确认 UI 增加"AI 分析本页"：抽取出**未链接的纯文本人名**、时间、地点、新人员建议
- 人名候选与名册做精确匹配预填；一切结果进确认 UI，用户勾选才落库——AI 只做提名不做决定
- 隐私边界：笔记内容仅在用户点击分析时发送到用户自己配置的思源 AI 端点；插件不持有密钥、无后台扫描

**v0.2c 跨插件协作已实现：人脉插件作为"人员服务"提供方（D-0012）**
- 协议：`window.LvContacts = { protocol: 1, capabilities: [...], searchPeople(keyword),
  ensurePerson(name) → docId, recordInteraction(docIds, {ref, date, place, note}) }`
  ——与打卡的 window.siyuanCheckin 协议 v5 同款形态，带版本协商与能力声明
- 用法：任务管理类插件在任务表单加"参与人员"选择器（调 searchPeople 搜索 / ensurePerson 新建），
  任务完成/到期时调 recordInteraction 记录共同交集——一场会议待办、一次家庭聚会即一次同场事件
- 推进路径：①本插件协议与文档已完成 ②外部插件接入需另行协调
  ③同时经 `addAgentCapability` 注册 Agent 能力（"查人/建人/记交集"），任何支持思源 Agent 的
  插件与流程都能间接调用——官方通道一次接入处处可用
- 原则：不逆向、不监听其他插件的私有存储（D-255 纪律）；集成只走公开桥或官方 Agent 通道

## 需求③ 关系的显示与延伸（深化设计）

现状：related relation 字段（双向，内核自动回链）+ cytoscape 图谱（分组着色、度数定大小）+ 详情弹窗增删。

**显示层演进**
1. 人物文档"相关人物"双链区块已实现，原生反链可见；关系类型标注尚未实现，依赖二期建模。
2. 图谱交互：边按关系类型过滤；点击节点高亮一度邻接、二度展开（"朋友的朋友"）；
   两点最短路径（"A 怎么认识 B"，引荐链查询）；按认识时间的时间轴回放。
   已落地：选取关系中心高亮直接或严格二度邻接，选择对比人物查看共同联系人或最短连接路径；查询限于当前展示图，点击节点仍打开详情。关系类型过滤仍未实现。
   最短路径复用 Cytoscape 无权无向 Dijkstra，等长链路只展示一条，不表示引荐意愿或关系强弱；筛选/裁剪可能移除中间人物，无路径仅指当前图内无连接。
3. 结构洞察：共同联系人高亮；"桥梁节点"识别（连接两个社群的人，弱关系价值，Granovetter）；
   孤立节点提醒（0 关系的人，引导补全）。
   已落地：无关系人物筛选，按完整名册的有效显式关系判断，自环与悬空关系不计；不是根据搜索后的图判断，也不是自动提醒。

**建模层演进（二期，见 D-0005）**
- 独立"关系库"：一行 = 一条关系（甲 / 乙 / 类型 / 强度 / 开始时间 / 备注）。
  类型自定义（家人/同事/上下级/引荐人/师生…），支持非对称（父母→子女）；
  图谱边从关系库读取后可着色/过滤；从现有 related 字段一键升级（同边迁移，类型留空待补）。
- 组织维度：公司/学校库（第二数据库），人物挂组织；图谱支持"按组织聚合"视图——
  对应 Notion Contacts↔Companies 与 WOLB 群组图谱的成熟模式。

## 需求④ AI 的运用（设计）

原则：本地统计不出工作区；生成式 AI 仅显式调用时发送到用户配置端点。官方通道注册（`addAgentCapability` / kernel plugin）尚未交付，需先验证公开接口。

**远期候选：思源官方 Agent 能力（公开接口待验证，不在当前隔离开发批次）**
- 注册只读能力 `query-contacts`：自然语言查人（"张三的电话""下个月谁过生日""谁认识李四"）。
  实现 = renderAttributeView 全量 + 域层投影，无需外部服务。
- 注册写能力 `record-interaction`（带确认）："今天和张三吃了饭" → 互动事件落库。

**近期方向：插件内行动建议（纯本地计算，见 PRODUCT-PLAN B 批）**
- "本周该联系谁"：生日、个人联系节奏和明确跟进日期合并，显示事实依据；当前未建模重要度/关系强度，不先引入不可解释加权评分。
- [x] 会前/会面简报：打开人物文档时在档案条聚合最近互动、显式关系与共同出席；生日倒计时沿用档案徽标。

**后续候选：生成式辅助（用户主动触发，不阻塞核心流程）**
- 问候语起草：生日/久未联系场景，按关系亲疏生成 2-3 版（调思源内置 AI 配置，插件不持有密钥）。
- 交往摘要：把某人的互动事件流压缩成一段"最近交往回顾"。

**远期：kernel.js 常驻服务**
- 外部捕获与常驻服务另行评估公开接口和隐私边界；「今天值得关注的人」计划在工作台内投影展示（F08，待开发），不依赖 kernel.js 或原生通知。
