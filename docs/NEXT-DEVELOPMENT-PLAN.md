更新：2026-09-29。状态：**规划中，未进入实现**。本文件是下一阶段的现状盘点、执行顺序与验收索引；需求原文、历史反馈和产品决定分别见 [FEEDBACK-BACKLOG](FEEDBACK-BACKLOG.md) B11–B14/AUDIT-01/CODE-AUDIT-02/UI-AUDIT-02、[DECISIONS](DECISIONS.md) D-0021/D-0022，实际存储事实以 [DATA-CONTRACT](DATA-CONTRACT.md) 为准。F01–F16 和 v0.3.0 已交付能力不重复开发。下述「已实现」指源码与既有隔离验证，真实宿主/真机状态另记。

## 目标、优先级与边界

主路径是「建立本人档案 → 为本人和联系人登记公司/学校归属 → 发现有依据的共同背景 → 在两种图谱中查看」。组织 B13 从远期候选提高为**下一阶段优先业务增量**；B11 本人身份和 B12 基础资料是前置。B14 原生图能力验证与数据建模并行，实际切换在文档集合和引用口径稳定后交付。

现有功能逻辑是：人物文档与思源数据库承载名册和 `related` 关系，插件 JSON 承载互动、跟进索引、节奏、提醒与偏好；服务层把它们汇总到首页、人物详情、档案条和自研图。新增本人身份与组织成员记录后，先确保名册和组织视图读取同一归属事实，再生成受控文档链接；原生图是否能按该文档集合呈现，取决于 B14 的宿主实证。这条读写链也是迁移、刷新和体检必须覆盖的范围。

本轮 UI/流程复审补出一条与业务建模并行的质量主线：所有异步写入、批量操作、图谱查询和 AI 调用都要让用户在动作前知道范围、执行中知道进度、执行后知道结果和失败项；画布、颜色和短暂 Toast 不能成为唯一信息载体。`UI-AUDIT-02` 的可访问替代视图、批量选择语义、隐私预检、焦点播报和规模反馈会在对应页面开发时一并验收。源码深审发现的关闭守卫、迁移、关系并发、设置映射和 API 超时等风险见 `CODE-AUDIT-02`，列为 B11–B14 实现前或同批必须通过的质量门槛。
