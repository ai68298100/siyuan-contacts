## B01 首页「今日行动」过长（中）

- **现象**：40 条「从未互动」铺满首屏，每行一个「去看看」，找不到真正该先联系的人。
- **现状（代码事实）**：`domain/action-list.ts` 把生日、联系节奏、跟进三源按人聚合；`DashboardView`
  全量渲染，无上限、无折叠、无分组；「从未互动」的人默认全部入列（久未联系阈值只管有互动者）。
- **目标（口径已定）**：**按原因分组折叠**（逾期 / 今天 / 本周）＋ **「从未互动」单独归组**。
  分组头显示条数并可整体折叠；「从未互动」单独成组、与"有互动但久未联系"分开呈现。
- **验收要点**：首屏不超过 1–2 屏；任何被隐藏的内容都有可见入口（分组头计数 + 展开）；
  折叠状态在会话内保持、可选持久化；不改变三源口径与统计。
- **补充要求（梳理时发现）**：①「从未互动」组的排序不能按姓名——建议按"最近收编/最近编辑"或
  按分组聚类，否则 40 人永远同一顺序、看不出该先联系谁；② 与 B-C02（收编宽限期）配套，
  否则导入当天仍会被 40 条淹没；③ 首页「近期生日」「久未联系」已用 `slice(0, 8)` 截断，
  今日行动要对齐同一套"计数 + 展开"语言。
- **关联**：与 B08 同处一块界面，建议一起设计。

## B03 选人器缺搜索与筛选（高）

## B04 联系人文档档案条：UI 与显示内容优化（中）— **已定：不管顶部导航，只做档案条**

- **现象（截图，未附文字）**：文档正文前有「上一篇 / 下一篇」导航胶囊 + 人脉档案条两条，
  占位偏多、层次上分不清归属。
- **关键事实**：**「上一篇 / 下一篇」不是本插件渲染的**（全仓检索无该文案与实现），
  归属宿主或另一插件。**已定：这部分不管**（不是我们的界面，也不做联动）。
- **改造范围：只优化人脉档案条自身的 UI 与显示内容。**
- **现状（代码事实，`src/panels/person-panel.ts`）**：身份区 = 姓名 + 徽标（生日剩 N 天 /
  最近互动 N 天前 / 尚未互动）+ 右侧按钮（编辑资料 / 打开人脉）；chips 行 = 📞 电话、💬 微信、
  ✉️ 邮箱、🎂 生日（含农历后缀）、`#标签`；未填资料时整行替换为「未填写联系资料，可点右侧编辑」；
  下方一个「会前简报」折叠区。
- **可优化的点（现状缺什么 / 乱在哪）**：
  1. **缺关键信息**：分组、未完成跟进数、关系数、最近一次互动的内容摘要都没显示；
     生日只按徽标呈现，"还有几天"与"具体日期"分散在两处。
  2. **chips 无上限**：标签多或电话长会把一行撑满/溢出，需要 `最多 N 枚 + "+M"` 与省略号处理。
  3. **层次**：徽标行 + chips 行 + 按钮行三层堆叠，视觉重量接近标题；建议压成一到两行、
     次要信息降级（hover/点击展开）。
  4. **空态**：「未填写联系资料」占一整行，可并入身份区一行灰字。
  5. **移动端**：现有样式未针对窄宽度重排（截图为桌面）。
- **验收要点**：桌面 / 移动 × 明暗四景截图留证；长电话 / 长标签 / 无标签 / 全空四种数据形态
  都不溢出；信息层级一眼可分（姓名 > 关键提醒 > 联系方式 > 次要）。
- **待定问题**：无（已定范围，可在排期时直接开工）。

## B05 关系需带方向与身份称谓（高，工作量最大）

- **原话**：一个人有多个身份（某人同时是甲的晚辈、乙的配偶、丙的平辈），要能表明不同的关系联结。
- **现状（代码事实）**：单一**无向** relation 列「相关人」+ 内核自动维护的回链列「被相关人」；
  只知道"有关系"，不知道**是什么关系、朝哪个方向**。
- **目标**：可标类型的关系建模——关系类型词表（亲属 / 婚姻 / 同事 / 朋友…）、方向与互逆称谓
  （女儿 ↔ 父亲、妻子 ↔ 丈夫、姐姐 ↔ 弟弟）、同一对关系可并存多种身份、一人多边；
  详情、图谱、简报、报表的表述随之升级。
- **契约影响**：新增关系存储（对齐 `ROADMAP.md` 二期「独立关系库：行 = 关系：甲 / 乙 / 类型」），
  **必须先补 `DATA-CONTRACT.md` 再实现**，并给出从现状（无向边，可能为空）到新模型的迁移路径。
- **验收要点**：一人多身份可录入可回读；互逆称谓自动一致；图谱边可按类型区分；
  导出（vCard / 简报 / 报表）不丢方向语义；不产生"删一边留一边"的悬空关系。
- **风险**：与既有「关系变更同步写入人物文档相关人物区块」的写入路径强耦合，需一并改造。

## B06 离开时未保存弹窗：告改动明细 + 保存出口（高）

- **原话**：「应该提示都修改了什么，是否直接保存，不然都找不到哪里进行保存」。
- **现状（代码事实）**：统一草稿守卫 `src/components/close-guard.ts` 已覆盖多处入口
  （详情必填、互动备注、跟进事项、批量编辑、vCard / 导入、设置偏好），但弹窗是宿主原生
  `confirm`，只有「取消 / 确定」，既无改动明细，也没有保存动作（保存入口在各自表单里，
  离开时看不到）。
- **目标**：自定义三选一弹窗——「保存并离开 / 放弃并离开 / 取消」，并列出改动明细
  （哪个区块、哪个字段、从 → 到，或"将丢失 N 条输入"）。
- **验收要点**：所有守卫入口一致；键盘可达；明细与实际改动一致（未变化不得虚报）；
  不引入新的存储写入。
- **依赖**：需要各草稿提供"改动摘要"（纯函数即可）；建议先做 2–3 个高频入口（详情资料、
  互动备注、跟进）再铺开。

## B07 跟进事项 → 思源原生待办（高）— **已定：落对应文档 + 双向同步**

- **原话**：「添加的任务，要成为【待办事项】，列入对应的文档中。这样这个事情也能被其他的
  任务管理器插件获取到。」已定：写入对应（人物）文档；要求双向同步；其余按下述推荐。
- **现状（代码事实）**：跟进只写插件自管 `follow-ups.json`，宿主搜索、原生待办聚合与其他
  任务管理插件都读不到。
- **推荐方案（可行性已在隔离内核 v3.8.5 实证 12/12）**：
  - **文档任务块为事实源**，`follow-ups.json` 退为索引 / 快照（首页清单、导出、不可达兜底）；
  - **关联键**：任务块上的 `custom-lvct-followup="<id>"`（`/api/attr/setBlockAttrs` 写入，
    实测勾选后仍存活，可按 `ial LIKE` 反查）；
  - **识别口径**：`type='i' AND subtype='t'`——`subtype='t'` 会同时命中列表容器（`type='l'`），
    必须再按 `type='i'` 过滤；官方勾选端点 `updateTaskListItemMarker {id, marker}` 只接受
    列表项 ID（传容器报 `block is not a list item`），批量用 `batchUpdateTaskListItemMarker`；
    勾选态存在 `blocks.markdown`（`- [X]` 大写）；
  - **写入纪律**：在人物文档维护一个带标记的「跟进事项」区块，只增改自己的任务项，
    **从不删除用户手工添加的任务**；改期只改文本里的 `📅YYYY-MM-DD`，不新建任务；
    取消计划 → 移除任务块（插件侧保留记录）；
  - **同步方向**：文档勾选 → 插件置 done；取消勾选 → 恢复 open；标题 / 日期以文档为准；
    任务块被删 → 标记「不可达」而不静默复活；两端冲突以文档为准，不做自动互相覆盖；
  - **保持不变**：完成跟进不自动写互动（既有纪律）；
  - **可选开关**：设置里「集中写入指定文档」（默认关，默认落各自人物文档）。
- **契约影响**：需在 `DATA-CONTRACT.md` 补"文档内任务块"写入约定与 `custom-lvct-followup`
  属性命名，再实现。
- **实证**：`pnpm spike:task` → `scripts/spike/task-item-spike.mjs`（12/12，
  `scripts/spike/task-item-results.json`，提交 `12f547b`）。
- **验收要点**：新建 / 改期 / 完成 / 取消四种操作在文档与插件两侧都一致；反复操作不产生
  重复任务；用户在思源里勾选后首页与详情同步反映；任务块被删后插件给出可解释状态；
  作者自己的任务管理器插件能读到这些待办（需真机确认，作者执行）。

## B08 今日行动行内快捷处置（高）

- **原话**：「这里要放更多的快速处理方案，比如跳过，多少天后提醒，不再提醒，更多」。
- **现状（代码事实）**：每行仅一个「去看看 / 处理」按钮（进详情）；推迟 / 取消等能力只存在于
  详情的「跟进计划」与首页「待办跟进」区块，不能就地把事情安顿掉。
- **推荐方案（按来源给动作）**：
  - 生日：处理（进详情）· **跳过本年** · 更多；
  - 久未联系：处理 · **顺延**（3 天 / 1 周 / 1 个月 / 指定日期）· **不再提醒** · 更多；
  - 跟进事项：处理（完成）· **推迟**（沿用既有语义 snooze：明天 / 三天后 / 下周一 /
    一个月后 / 按日期）· **取消计划** · 更多；
  - **更多**菜单：打开详情 / 记录互动 / 编辑资料 / 打开文档（零新存储）。
- **存储映射（优先复用，避免双事实源）**：
  - 顺延（久未联系）→ `person-cadences.json` 的 `days`（设为"距上次互动天数 + N"即精确表达
    "N 天后提醒"）；不再提醒 → 同一文件的 `paused`（设置页已可恢复）；
  - 跟进三动作 → 既有 `follow-ups.json` 语义（推迟 / 完成 / 取消）；
  - **唯一新增**：最小契约 `reminder-dismissals.json`（`{personDocId, kind, until}`，
    `kind ∈ birthday|stale|followup`，`until` 为空串表示长期），承担"生日跳过 / 今天先跳过"；
    **只影响提醒的呈现，不改变统计与久未联系名单**；设置页提供"已暂缓的提醒"列表可一键恢复，
    避免"点过一次就永远找不回"的幽灵状态。落地前先补 `DATA-CONTRACT.md`。
- **交互细节**：行内最多「主按钮 + 一个次按钮 + ⋯更多」（顺带缓解 B01 的密度问题）；
  顺延用语义选项、不做裸日期；操作后该行就地消失并给「已顺延到 X 月 X 日 · 撤销」；
  顶栏保留既有"把 N 条逾期跟进顺延到今天"，可加"今天全部跳过"（仅今天，不写语义）。
- **验收要点**：误点可撤销；刷新 / 重启后暂缓仍生效且状态可解释；不产生重复提醒；
  统计口径与久未联系名单保持不变。
- **待定问题（已定）**：生日「跳过」默认**管本年**；「不再提醒」**不减**首页"久未联系"统计
  （统计保持真实，只在提醒呈现上生效，设置页可恢复）。

### C01 宿主样式下的浮层基线（由 B02 派生）— 建议采纳

- 问题不只是"视图"菜单：同一区域还有 **列设置**、**更多筛选** 两个自绘浮层
  （`.lvct-people__colmenu` / `__moremenu` / `__viewsmenu`），共用同一套背景 / 阴影 / z-index 规则，
  B02 的显示异常很可能同时影响三者。
- 现有隔离回归与截图用的是手写近似宿主样式，**无法覆盖宿主真实 CSS**——这是本次缺陷能溜到
  真实使用中的根本原因。
- 建议：① 把宿主 `base.css`（本地安装目录可读）引入截图/回归 harness，作为"宿主样式基线"开关；
  ② 为所有自绘浮层统一定义基线（不透明底色 + 显式边框/阴影 + 明确层级 + 最大高度与滚动 +
  移动端全宽），不再依赖单一 `surface-lighter` 令牌推导。
- 验收：宿主基线开启时，三个浮层 × 明暗 × 桌面/移动 六景全部可读、不遮挡、不溢出。

### C02 收编宽限期与"批量安顿"（由 B01 派生）— 建议采纳（最小版本）

- 现象：作者一次性收编了 40 位存量联系人，当天首页立刻出现 40 条「从未互动」——
  提醒系统被导入动作本身撑爆。
- 建议最小版本：收编（导入已有文档）写入的 `createdAt` 作为"宽限期"起点，**收编后 N 天
  （默认 14，可在设置调整）内不计入"从未互动"提醒**，只在联系人列表里可见；
  同时提供一次性"批量安顿"动作：把当前「从未互动」组整体顺延 N 天 / 设为暂停提醒
  （复用 B08 的映射，不新增存储）。
- 验收：刚导入 40 人时首页不再被淹没；宽限期到期后按正常规则出现；批量动作可撤销。

### C03 资料完整度视图与"补资料"引导（由截图观察）— 建议采纳

- 现象：40 人几乎全是"生日未填写 / 未填写联系资料"——生日提醒、联系节奏这些功能的**前置数据
  大面积缺失**，提醒质量的天花板就在这里。
- 建议：联系人页增加"资料完整度"筛选/视图（缺电话 / 缺生日 / 缺分组 / 资料全空），
  并提供串行补录流程（一人一屏，键盘 Tab 连填、保存即进下一位）。
- 验收：能从 40 人里筛出"缺生日"的 38 人并连续补录；补录后首页提醒立即反映；不写冗余存储。

### C04 资料体检（一键巡检）（由 B05 / 既有健康检查派生）— 建议合并进设置页

- 已有基础：设置页字段健康检查 + 疑似重复检查（F13）。
- 建议扩展为一次"资料体检"：缺关键字段、疑似重复、悬空关系（指向已解绑人物）、
  可疑生日（年份异常 / 未来日期）、无分组无标签、长期无互动——一处列出、逐项可跳转处理。
- 验收：只读巡检零写入；每项给出可解释理由与跳转入口；不出现"自动修复"。

### C05 关系模型的连带改造清单（由 B05 派生）— 必须与 B05 同批

- **互逆称谓需要性别/称谓数据**：现在字段契约里**没有性别或称谓偏好字段**，只有"相关人"。
  两种设计：(a) 新增可选字段 `gender`（或"称谓偏好"）以自动推出女儿/儿子、父亲/母亲；
  (b) 每条关系同时存两侧称谓（笨但永不推断错）。**建议 (a) + 通用词表兜底**：
  无性别时用中性逆称谓（子女 / 父母 / 配偶 / 兄弟姐妹），有性别时细化；字段按既有
  "字段健康检查增量补建"机制加入（与 ROADMAP 候选池里"星标联系人"同一路径）。
- 连带面：详情关系列表（增删改 + 方向展示）、图谱（边标签 / 类型图例 / 过滤）、
  会面简报（"相关人物"要带称谓）、报表（关系类型分布）、导出（vCard `RELATED` 属性映射、
  Markdown 说明）、关系候选推荐（ROADMAP 候选 4）。
- 验收补充：无性别人物不得出现"女儿"这类错误推断；升级前后既有无向边不丢失；
  删除一侧时另一侧同步收敛（不留悬空）。

### C06 会话内撤销能力（由 B08 的"可撤销"派生）— 建议采纳（最小版本）

- 现状：全仓**没有任何撤销能力**（检索无实现），而 B08 要求"操作后可撤销"，
  其它破坏性操作（删除互动、移除关系、取消跟进）同样受益。
- 建议最小版本：会话内操作栈（保存"反向操作"闭包 + 展示"已撤销/已恢复"），
  只覆盖最近一次同类操作，不做历史面板；跨重启不保留，不写存储。
- 验收：顺延 / 跳过 / 不再提醒 / 完成 / 取消 / 删除互动 六类操作都可一键撤销；
  撤销后界面与存储一致；多窗口下不谎报成功。

### C07 从提醒一键建档：行动 → 跟进事项（由 B07 + B08 派生）— 建议采纳

- 逻辑闭环：B07 让"跟进"变成原生待办，B08 让行动清单可就地处置——那么最自然的一步是
  **在今日行动/档案条上直接"为这个人建一条跟进"**（默认标题如"联系一下"、默认日期=今天+7），
  它立刻变成文档里的原生待办，并进入首页行动清单。
- 边界：**不自动**为生日 / 久未联系生成任务（会瞬间产生 40 条任务，违背降噪目标）；
  只有用户显式点击才建。
- 验收：从首页/档案条两步内建成任务；文档里出现带日期的原生待办；插件与文档状态一致。

### C08 备份与数据带走的完整性缺口（由 B07 派生）— 建议排入 B07 同批

- 现状：导出中心已覆盖全量名册 vCard 与互动事件 JSON；**跟进事项、联系节奏、提醒暂缓
  （B08 新增）不在任何备份里**，而它们恰恰是"计划类"数据。
- 建议：① 设置页增加"合并导出"（资料指引 + 互动 + 跟进 + 节奏 + 暂缓）与对应恢复路径；
  ② B07 落地后，恢复时需定义与文档任务块的冲突策略（文档为准 / 只补缺失）。
- 验收：导出文件可被本插件完整恢复（预览差异 → 确认合并，既有纪律）；不产生重复任务与
  重复跟进；明示"这不是思源原生数据的字节级备份"。

## B09 手机端显示与布局（高）— 首批真机截图证据（2026-09-28，390px 宽 Android）

> 证据：作者提供的 4 张真机截图（首页 / 联系人 / 关系图谱 / 设置）。截图中的「GKD」浮标是
> 思源宿主彩蛋，非本插件问题。本条各子项在开发时**并入对应页面的批次**执行，验收统一用
> 390×844 视口截图留证（结合 C01 的宿主样式基线）。

1. **联系人页工具栏灾难性换行**：10 个控件（视图 / 搜索 / 全部分组 / 排序 / 更多筛选 / 表格 /
   整理 / 导入已有文档 / vCard / 新建联系人）在窄屏换成约 6 行，首屏全是按钮、卡片被推到一屏外。
   移动端需要"工具栏收纳"设计：常驻（搜索、新建、视图切换），其余收进「筛选」「⋯」抽屉或底部
   弹层；原型目前也缺这块设计（见 B10-B）。
2. **人物卡片大量留白**：直接原因是 `.lvct-person-card { min-height: 172px }`（为桌面网格对齐而设）
   在移动单列下不收缩——空数据卡只有两行灰字也占 170px+。移动端应内容自适应（目标 ≤ ~120px）、
   压缩 padding；chips（电话/微信/邮箱/分组/标签，实现里已有、数据驱动）为空时整体收起。
3. **全局头部不分页**：「搜索联系人 + 新建联系人」出现在**所有**视图，包括设置页与图谱页
   （原型按屏设计头部）；设置页同时存在「返回工作台」按钮与底部 Tab，三者冗余。
   移动端应按视图显隐头部内容：设置/图谱不显示搜索与新建。
4. **图谱页工具栏吃掉近半屏**（搜索节点 / 分组 / 仅无关系 / 适应 / 放大 / 缩小 / 重新布局 /
   刷新 + 图例 + 关系中心 / 对比人物）：移动端应折叠为可收纳的工具组（缩放交给双指手势，
   cytoscape 原生支持），画布高度优先；当前尺寸下节点标签不可读，需要按缩放级别显隐标签的策略。
5. **触控目标未达规范**：令牌已有两级（`--lvct-touch-min: 32px` / `--lvct-touch-min-mobile: 40px`），
   但移动端媒体查询里只有 `.lvct-dash__row-main` 一处用了 40px，其余按钮仍是 32px——
   低于原型「移动端 ≥ 40px」的可访问性底线。需要一次令牌应用审计（哪些组件绕过令牌硬编码尺寸）。
6. **首页「待办跟进」区块挤压**：推迟 / 完成 / 取消按钮与日期输入同行换行错位。
7. **首页尾部低频区块**（工作空间 / 服务桥 / 打卡联动）占长滚动尾部，移动端应默认折叠或并入设置。
8. **同类动作不一致**：久未联系行有「去看看 + 记一笔（内嵌备注表单）」，今日行动行只有
   「去看看 / 处理」——统一方案在 B08。
9. **文案与磁贴**：底部 Tab「关系图」与桌面「关系图谱」不一致（宽度挤压所致）；设置页 6 个
   分区磁贴过大占近半屏，可改紧凑列表。

## B10 原型对齐审计：缺失项 / 设计差异 / 显示差异（中）

> 方法：以 `docs/ui-prototype.html` 为基线逐屏对照桌面实现与真机截图。结论分三类。

**A. 原型有、实现缺或有差异**
1. 统计卡次级信息：原型有「本月 +12」「人均 1.8 条」「含农历 2 位」等副文案，实现只有数字 + 标签。
2. 统计卡点击直达筛选：原型明确"可点击直达筛选结果"；实现已支持（如从未互动），但四张卡的
   口径与"已筛选"反馈不一致，需补齐。
3. 生日分桶着色（今天 / 7 天内 / 30 天内）：近期生日列表有 bucket 样式，统计卡与其它位置未统一。
4. 人物卡"最近互动 + 来源"：原型卡片显示互动摘要带来源（"3 天前 · 课程评审会"），实现只有
   相对天数、无来源。
5. 组件规范项：Toast 右上堆叠 ≤ 3（实现用宿主 `showMessage`，位置与堆叠不受控）、
   悬停卡 300ms 延迟等——差异记录，是否补齐随批次决定。

**B. 实现有、原型缺（原型滞后，需回补）**
1. 今日行动区（F07）整体——原型首页根本没有这块，B01 分组折叠与 B08 行内快捷处置更无从对照；
   移动端形态也缺。
2. 首页「待办跟进」区（F05）的移动端形态。
3. 移动端工具栏收纳设计（B09-1）——原型的"移动端适配要点"只有一句话，没有逐页设计。
4. 设置页移动端导航形态（磁贴 vs 紧凑列表）与「返回工作台」的存在性。
5. 久未联系行的「记一笔」实现已超出原型（内嵌备注表单），原型应回补为双按钮形态。

**C. 显示差异（真机 vs 隔离回归的盲区）**
1. 隔离截图用手写近似宿主样式 + 固定视口，"能过"但真机仍暴露 9 类问题（B09）——
   与 C01 合并治理：宿主 base.css 基线 + 真机视口截图纳入证据链（本批截图即首批真机证据）。
2. 令牌"有值未用"：40px 触控令牌等规范存在但未全量应用（见 B09-5），需要一次
   "绕过令牌的硬编码尺寸/颜色"审计并清零。
