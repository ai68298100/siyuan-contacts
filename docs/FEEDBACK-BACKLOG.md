### BASE-01.2 数据和产品边界

- 当前字段契约只有 `birthday`、`lunarBirthday`、`phone`、`email`、`wechat`、`website`、`group`、`tags`、`related` 九类字段；没有公司、职位、地址、头像、任意纪念日、星标或关系类型/方向。FAST-01 识别到未有契约的字段只能进入待确认建议/原文草稿，不能静默丢弃或直接写库。
- 当前关系是 `related` 双向无向边；B05/C05 的类型化关系、组织库、时间轴和迁移必须先修改 `DATA-CONTRACT.md`，再设计迁移、健康检查、详情、图谱、简报、导出和回滚，不能只在 UI 里增加一个“关系类型”下拉。
- 当前跟进是插件自管 JSON；B07 要求写入人物文档原生待办并双向同步，`custom-lvct-followup` 任务块属性、冲突口径和任务管理器协作必须先入数据契约并做真实思源人工验证。
- 当前首页生日/久未联系/行动的“暂缓、跳过、恢复”没有完整的 `reminder-dismissals` 契约；C08 完整迁移包还需覆盖人物指引、互动、跟进、联系节奏、提醒状态和模板/视图偏好，并明示原生文档/数据库不属于插件字节备份。
- 原型详情页画出的互动日期/地点输入不属于当前互动事件字段和 `recordInteraction(personDocId, note)` 合约；在决定扩展事件模型前，应把它记录为“原型超出当前范围”的有意差异，不能仅按 UI 缺失开工。若要支持日期/地点，先补事件契约、导入导出、幂等和回顾口径。
- C02 的收编宽限期不能直接假设存在 `createdAt`：当前字段契约没有该字段，开工前必须决定将收编时间存在哪里（插件索引、文档属性或其他现有来源），并为旧联系人定义缺省行为；C03 的资料完整度也只能按当前九个字段判定，不能把公司/职位/地址等候选字段混入“缺失字段”统计。
- FAST-01.9 提到的 `sourceText/sourceKind/confidence/normalization` 在当前没有持久化契约；默认只在本次预览内存中使用，若要跨会话审计必须另立版本化识别结果存储、脱敏和清理规则，不能在实现时偷偷新增 JSON 键。
- 当前 AI 只在用户主动点击时调用配置端点；关闭 AI 后核心查人、记录、回顾、跟进和导出必须继续可用。OCR、二维码、官方 Agent、日历、组织、人物合并、问候起草均是候选或远期，不进入本轮已实现清单。
- 互动数据当前遵循“只追加事件 + 墓碑删除 + 幂等 externalRef”纪律；没有编辑、批量修正或跨重启撤销。FUNC-01.10 在决策前只能做复制/重新记录引导和说明，不能在页面层覆盖原事件。
- 外部桥 protocol 1 当前只有查人、按名解析/建人、记录互动四类能力；字段补丁、建议、跟进和批量逐项结果必须先升协议、补兼容/能力降级和隐私校验，不能把 FAST-01 的候选接口直接当成现有能力。

## FAST-01 快速填充与信息识别（高，减少手工录入的大项）

> 状态：**新增待办，未开始**。当前联系人新增/编辑主要依赖逐字段手填；已有 vCard 导入、笔记双链捕获和 AI 人名/日期/地点抽取，但还没有一套统一的“输入内容 → 识别字段/事项 → 预览确认 → 写入/回退”流程。本大项优先解决手机号、微信号、邮箱、生日等高频字段的快速填充，再扩展到互动、跟进和关系候选识别。

### 设计原则与边界

- **本地确定性识别优先**：手机号、邮箱、网址、日期、显式“微信/电话/生日”等键值先由本地规则识别，不把普通联系人资料发送给 AI。
- **所有识别都先预览确认**：识别结果逐字段显示来源文本、目标字段、置信度、冲突值和将执行的动作；用户可逐项接受、修改、忽略，不能静默覆盖已有资料。
- **事实和建议分开**：电话/微信/生日属于人物资料；日期/地点/备注属于互动事实；“下周联系”“提醒我”属于跟进计划；“这是同事”属于关系候选。不同类型进入不同存储和确认步骤。
- **保留来源与可回溯性**：记录来源文档、块或粘贴批次、识别时间和用户确认结果；未被当前字段契约支持的内容不能无提示丢弃。
- **隐私默认收敛**：剪贴板、文件、图片和选中文本只有用户主动触发才读取；AI 只调用用户已配置的思源端点，不新增网络服务、不做后台扫描。

### PAGE-01.0 页面契约、状态矩阵与原型口径（P0）

- 为工作台外壳、首页、联系人、详情 Peek、关系图谱、设置、初始化、捕获、导入、人物文档档案条分别建立“入口 → 主任务 → 数据范围 → 主操作 → 成功出口”的页面卡片；每张卡片明确可跳转目标、返回规则、深链接参数和当前联系人/筛选/选中状态是否保留。
- 每个页面至少列出：首次加载、骨架加载、正常有数据、空名册/空结果、部分数据、提交中、成功、失败可重试、权限/能力不可用、草稿未保存、跨窗口数据变更、移动端和暗色主题等状态。页面没有该状态时要写“无需此状态”的理由，不能默默省略。
- 在版本化原型 `docs/ui-prototype.html` 中增加 `已实现 / 已实现但待优化 / 计划 / 暂不支持` 标识。当前原型中的 F02–F08、F14 等已实现能力不能继续标成“计划”；类型化关系、组织、建议等未完成能力必须显示为目标或禁用态，避免原型与 `PRODUCT-PLAN.md`、`PROGRESS.md` 互相矛盾。
- 页面每个时刻只保留一个最主要动作；次要动作收进上下文菜单或二级面板。主动作需说明是否可重复、是否幂等、是否需要确认、失败后是否可继续；所有异步动作均要有 busy 防重复和失败后的重试/查看详情入口。
- 验收：形成一张可勾选的页面状态矩阵；每个矩阵项都能关联一张截图、一个可复现夹具状态和一个实现任务编号，不能只以“页面能打开”作为通过条件。

### PAGE-01.1 工作台外壳、导航与全局动作

- **当前问题**：`Workbench.svelte` 的导航文字与图标共用 `span` 样式，窄宽度下会逐字竖排；首页才显示全局搜索/新建，联系人、图谱、设置的页头动作和返回规则不一致。移动端虽然有底部导航，但原型没有真实 390px 的选中、返回和安全区画面。

- **实现安排**：修正导航选择器和文字容器；抽出统一页头（标题、副标题、返回、搜索、更多、主操作）；统一工作台滚动容器、页头吸顶和底部安全区；定义全局搜索词在首页→联系人→离开→返回链路中的保留、清除、回填和显式清除规则，避免旧搜索条件静默过滤；补全键盘快捷键、当前导航 aria、焦点归还和移动端全屏 Dialog 规则。
- **验收**：1280/640/390px 下导航不竖排、不出现双滚动；每个页面能从侧栏和深链接进入并回到原上下文；全局搜索上下文可解释、可清除，返回联系人时不会无提示恢复过期条件；移动端点击底栏不丢弃正在编辑的草稿。

### PAGE-01.7 初始化、收编、捕获与导入流程

- **当前问题**：`InitWizard.svelte` 主要展示 logo、说明、日志和单一进度；同名/改名/移动候选只能隐式取首个。`CaptureDialog.svelte` 虽有三步框架但主要画识别/确认，AI 只返回人名/日期/地点；捕获、收编和 vCard 导入发生中途失败时，用户只有总错误，无法继续未完成项。导入还缺字段诊断、未知列和孤儿文档处理。
- **原型调整**：所有长流程统一为“来源与范围 → 识别/映射 → 预览确认 → 执行进度 → 逐项结果 → 下一步”。初始化先列候选工作空间/文档/数据库和将创建的资源；捕获区分双链确定、规则识别、AI 提名，显示原文片段和动作清单；收编/vCard/CSV 显示字段映射、同名冲突、未知字段、已创建资源和可继续任务。结果页明确成功/跳过/失败/待重试，并提供打开联系人、打开原文、导出报告。
- **实现安排**：为初始化、捕获、收编、导入保存阶段 checkpoint、幂等键和已写资源；支持取消、超时、继续未完成、回滚选择和孤儿清理；捕获重复时让用户选择查看已有捕获、更新元数据或追加新场合；FAST-01 的手机号/微信/邮箱/生日/事项识别全部先预览确认，暂不支持的公司/职位/地址/关系只能保存为建议或原文。
- **子流程矩阵**：初始化、收编、vCard、捕获、CSV/TSV（规划）分别画出来源选择、预览、确认、执行、逐项报告和完成出口；不能用捕获三步画面代表导入/vCard/初始化。每个流程都登记“已创建文档但后续绑定失败”“结果未知”“可继续/可清理”的分支。
- **验收**：窄窗口和 390px 下步骤条、进度条、长路径、长错误和底部动作不溢出；每一步失败都能定位到对象和下一步；重复提交不重复建人/记互动；部分成功后刷新页面仍能继续；成功页提供新建联系人、导入下一批、打开总表/原文等入口。

### PAGE-01.8 人物文档档案条、编辑器入口与外部桥

- **当前问题**：`src/panels/person-panel.ts` 已注入头像、字段、chips、简报和编辑/打开按钮，但联系方式还是文本 chips，不能复制/拨号/发邮件；“打开人脉”不一定定位当前联系人；外部编辑或互动后档案条不会主动刷新，读取失败时可能直接消失。`external-bridge.ts` 的批量互动中途失败也无法返回逐项结果。
- **原型调整**：档案条分为身份、关键字段、最近互动/待跟进/相关人摘要和动作四层；电话、微信、邮箱提供复制和外部打开的明确反馈；动作包括定位 Peek、记录互动、添加跟进、打开文档和更多。增加非人物文档、字段缺失、无互动、生日未知、锚点移动、刷新失败和重绑提示的异常画面；桥状态显示已启用/已关闭、能力版本和最近调用结果。
- **实现安排**：监听数据变化并在读取失败时保留旧内容加重试；定位工作台时携带当前人物 ID；注入和参与人员区块写入前展示冲突差异，不覆盖用户手改；桥批量返回 `succeeded/skipped/failed`、幂等键和可安全重试的错误分类，补 ID/日期/长度校验和能力协商。
- **验收**：从文档、工作台、桥三处进入同一人物时上下文一致；复制/打开/记录/跟进成功或失败有结果；人物文档移动、标题改写、数据变更、权限失败和桥部分成功不会让档案条静默消失或显示过期数据。

### PAGE-01.9 移动端、键盘和可访问性逐页收口

- 以 390px、640px、1280px 三档分别维护首页、联系人、详情、图谱、设置、向导/导入的画面，不只测试工作台外壳；每页检查安全区、键盘弹出、旋转、横向溢出、滚动容器和固定底栏。
- 移动端联系人筛选改为抽屉/底部面板，表格改为必要字段卡片或可横向查看的明确区域；详情 Peek 改全屏并提供显式关闭和未保存确认；图谱工具栏折叠且支持触摸缩放；设置分区改列表；长流程底部动作固定但不被键盘遮挡。
- 所有 icon-only 操作提供 aria-label、可见 focus 和 tooltip/辅助文案；键盘顺序覆盖搜索、筛选、切人、Tab、确认、取消和恢复；颜色不是唯一状态信息，正文对比度达到 4.5:1，触控目标至少 40px；遵守 `prefers-reduced-motion`。
- 验收：键盘-only 可完成每页主流程；屏幕阅读器能读出标题、当前页、结果数量和错误；明暗主题、无障碍焦点和 reduced-motion 截图无明显跳动。
