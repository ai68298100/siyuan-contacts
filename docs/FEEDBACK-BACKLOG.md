### BASE-01.2 数据和产品边界

- 当前字段契约只有 `birthday`、`lunarBirthday`、`phone`、`email`、`wechat`、`website`、`group`、`tags`、`related` 九类字段；没有公司、职位、地址、头像、任意纪念日、星标或关系类型/方向。FAST-01 识别到未有契约的字段只能进入待确认建议/原文草稿，不能静默丢弃或直接写库。
- 当前关系是 `related` 双向无向边；B13 组织/成员契约优先设计，B05/C05 的完整类型化人物关系和时间轴继续延期。新增存储先修改 `DATA-CONTRACT.md`，再设计迁移、健康检查、详情、图谱、简报、导出和回滚。
- 跟进已在人物文档写原生任务块并维护插件索引；B07 读侧仍需同步标题/日期、处理块删除/移动并做真实思源任务管理器互读验证，见下一阶段计划 P0。

- **安排**：在导入预览中逐字段显示“已映射/被忽略/无法映射”，允许用户将可识别字段映射到现有字段或保留原始备注；明确同名跳过、覆盖、创建副本三种策略，默认仍保持安全跳过。
- **验收**：用户能知道每个输入字段的去向；导入后可回读核对；未知字段不会静默丢失；未确认的同名不会改写现有人物；导出再导入的可支持字段保持稳定。
- **关联**：F14、C03、`DATA-CONTRACT.md §7`；头像、组织和地址字段若要真正落库需另立字段契约。

#### FUNC-01.10 互动修正、批量操作与审计边界 — **路线已定（D-0020）：维持只追加**

- **代码事实**：互动采用只追加事件 + 墓碑删除，目前支持单条删除，不支持修正日期/备注、批量删除或撤销；这是当前数据纪律下的有意限制，但用户无法在界面上看到“为什么不能编辑”。
- **已定路线**：继续只追加。增加“复制为新记录/删除并重新记录”的引导和审计说明；不做事件修订链，不在页面层覆盖原事件。
- **验收**：无论选哪条路线，详情、备份、导出和帮助文案一致；批量删除必须逐项确认、按人物校验并保留墓碑；失败不报告为成功。
- **关联**：互动存储契约、C06；列为决策项，未确认前不直接扩展写入语义。

#### FUNC-01.11 对外服务桥的批量结果与契约自测

- **代码事实**：`window.LvContacts` v1 已支持搜索、查人、按名创建和批量记录互动，但批量记录按人物串行写入，遇到中途失败只会抛异常，调用方无法知道哪些人已成功；协议也没有分页、能力自测和错误码约定。
- **安排**：补充批量结果 `{succeeded, skipped, failed}`、幂等键回显和可安全重试的错误分类；增加协议版本/能力自测页面或脚本，明确未初始化、人物不存在、日期非法和部分写入的处理。
- **验收**：一批多人中途失败时不丢失成功结果，也不要求盲目整批重放；外部插件能根据 capabilities 选择能力；协议文档、类型定义和隔离测试一致。
- **关联**：`docs/BRIDGE.md`、`bridge/external-bridge.ts`、C08；不监听其他插件私有存储。

#### FUNC-01.12 常规读取失败不能伪装成空数据（P0，2026-09-29 审计新增）

- **代码事实**：`data/storage.ts#loadJson` 将读取异常与键不存在都返回 `null`；互动、跟进等展示读取再归一为空，首页可能把存储故障显示成「无人互动/无待办」。
- **待办/验收**：区分首次无数据、损坏和读取失败；受影响的首页、人物时间线、跟进和体检显示模块错误、保留旧值并可重试。故障期间零写入，不让空态或统计掩盖原数据。

#### FUNC-01.13 存储锁超时接管安全性（P0，2026-09-29 审计新增）

- **代码事实**：`data/storage.ts#withStoreLock` 等锁 5 秒后用 `steal` 接管；若原持有者只是慢写，原异步回调未必停止，两个读改写过程可能重叠。
- **待办/验收**：实证宿主与 Web Locks 行为，改为可证明排他的等待/恢复机制；双上下文注入超过 5 秒的正常写、挂起回读和失败，互动、跟进、模板、索引均无丢写或错误成功。

#### FUNC-01.14 AI 资料候选禁止旧快照全字段覆盖（P0，2026-09-29 审计新增）

- **代码事实**：`CaptureDialog.svelte#applyAiExtras` 按每条候选从 `preview.linked` 旧快照构造完整草稿，再调用会清空空字段的 `updatePersonFields`。未双链但被 AI 匹配的既有人可能丢失原资料；同人多条候选后写的会覆盖先写的。
- **待办/验收**：按人物合并勾选补丁，回读最新资料，逐字段显示新增/冲突并只写用户确认字段。未双链既有人、同人电话+邮箱、保存前并发改资料三个用例中，未勾选/已有字段保持原值。

#### FUNC-01.15 手动建档与多步写入的断点恢复（P0，2026-09-29 审计新增）

- **代码事实**：`services/contacts.ts#createContact` 顺序建文档、绑数据库行、并行写字段；中途失败会留下半成品，同名重试又可能被查重挡住。批量字段与双向关系写入同样缺逐步结果。
- **待办/验收**：返回已完成步骤、失败步骤与结果未知项；重试前按文档 ID/行 ID 回读，仅补缺失写入。注入每一步失败，不重复建档、不清空已写字段、不把部分成功报为全部成功；与 FUNC-01.5 的收编/捕获报告共用结果口径。

## FAST-01 快速填充与信息识别（高，减少手工录入的大项）

> 状态：**快速填充和结构化候选已有实现，导入映射与高阶识别仍待办**。本大项最初以「输入内容 → 识别字段/事项 → 预览确认 → 写入」为目标拆分；FAST-01.1～01.4 已有落地记录，后续余项与 B12/B13 新字段映射见 [下一阶段开发计划](NEXT-DEVELOPMENT-PLAN.md)。

### 设计原则与边界

- **本地确定性识别优先**：手机号、邮箱、网址、日期、显式“微信/电话/生日”等键值先由本地规则识别，不把普通联系人资料发送给 AI。
- **所有识别都先预览确认**：识别结果逐字段显示来源文本、目标字段、置信度、冲突值和将执行的动作；用户可逐项接受、修改、忽略，不能静默覆盖已有资料。
- **事实和建议分开**：电话/微信/生日属于人物资料；日期/地点/备注属于互动事实；“下周联系”“提醒我”属于跟进计划；“这是同事”属于关系候选。不同类型进入不同存储和确认步骤。
- **保留来源与可回溯性**：记录来源文档、块或粘贴批次、识别时间和用户确认结果；未被当前字段契约支持的内容不能无提示丢弃。
- **隐私默认收敛**：剪贴板、文件、图片和选中文本只有用户主动触发才读取；AI 只调用用户已配置的思源端点，不新增网络服务、不做后台扫描。

  - **关系/组织候选**：同事、同学、家人、客户、公司、学校、团队；
  - **来源链接**：当前笔记、块、外部 URL、名片或 vCard 来源。
- 识别后先生成“动作清单”，让用户选择“补资料 / 记录互动 / 建跟进 / 建议关系 / 仅保存原文”，不根据一句模糊话自动创建多个事实。
- 同一段文字同时包含日期和动作时，明确日期是事件发生日还是跟进到期日；缺少上下文时要求用户选择或保留为草稿。
- 验收：所有动作均能回到现有服务和存储契约；暂不支持的动作有明确原因，不生成半成品数据。

### FAST-01.6 vCard、CSV/TSV 与粘贴表格导入

- 在现有 vCard 文件导入之外，增加“粘贴 vCard 文本”和拖放文件入口，移动端优先支持系统分享的 `.vcf` 文件。
- 评估 CSV/TSV/Markdown 表格导入：首行字段映射、预览前 20 行、字段类型校验、同名冲突策略、空值是否清空、分批导入和失败重试；映射结果保存为本次导入计划，不默认写入长期偏好。
- 导入预览中明确多值电话、多个邮箱、微信号、生日无年份、农历标记、未知列和图片字段的处理；与 `FUNC-01.9` 的字段保真任务共用结果模型。
- 验收：文件、文本和表格导入共享“解析 → 预览 → 确认 → 逐项报告 → 核对重试”流程；不因文件过大阻塞页面；旧 vCard 导入行为兼容。

### FAST-01.7 图片名片、二维码与 OCR（P2，能力探测后实施）

- 支持用户主动选择名片照片、截图或二维码图片，识别常见 vCard/MECARD/联系方式二维码；识别结果必须先进入预览，不直接建人。
- 优先复用宿主可用的本地 OCR 或用户配置的 AI 能力；启动时探测能力，不假设浏览器一定有摄像头、二维码解码器或图像 AI API。
- 图片识别失败时保留原图文件名和手工录入入口；不把图片上传到插件维护的服务，不在后台扫描相册。
- 验收：普通图片、模糊图片、多个二维码、无法识别和权限拒绝均有明确状态；识别出的电话/微信/邮箱可逐项修改；未确认不写入。

### FAST-01.8 外部插件和系统输入的快速填充

- 评估扩展 `window.LvContacts`：增加带用户确认边界的资料补丁/建议接口，而不是允许外部插件静默覆盖电话、微信和生日；建议接口返回字段级 diff 和 `source`。
- 为任务、打卡、捕获等公开桥场景增加可选的 `suggestPersonFields`、`recordInteraction` 批量结果和能力协商；不读取其他插件私有存储。
- 系统联系人导入继续以 vCard/CSV 为主，不依赖浏览器 Contact Picker 等宿主不稳定能力；如增加原生能力，必须有文件导入回退。
- 验收：外部调用方能知道插件版本、支持的字段和需要用户确认的动作；部分失败返回逐项结果；资料更新仍经过格式校验、查重和写后回读。

### FAST-01.9 识别质量、冲突与安全规则

- 为每个识别值保留 `sourceText`、`sourceKind`、`confidence` 和 `normalization` 信息，UI 显示“来自哪一段文字、为什么识别为该字段”。
- 建立本地规则测试集：大陆/国际手机号、座机、分机、微信号边界、邮箱大小写、URL、中文日期、农历日期、身份证号误识别、金额和订单号误识别。
- 识别到多个联系人候选时按姓名、已有电话/微信/邮箱、当前文档上下文排序；不能只按第一个匹配项写入。
- 已有值冲突时提供“保留旧值 / 使用新值 / 两者并存到备注 / 忽略”选项；涉及批量更新时先显示影响人数和字段列表。
- 验收：误识别可追溯、可取消、可重试；日志不记录完整手机号、微信号或笔记正文；AI/图片外发范围在确认前明示。

### FAST-01.10 快速填充的交付顺序

1. **P0**：FAST-01.1～1.3，先落地本地粘贴识别、结构化模板、选中文本/当前文档识别；不新增字段，复用现有联系人写入和草稿守卫。

## AUDIT-01 2026-09-29 全量功能、UI、交互与数据审计新增项

本节记录本轮对源码、页面矩阵和数据契约逐条核对后新增的待办；它们不重复 F01–F16 的已交付功能，优先修复会造成数据误导或数据丢失的路径。

### P0 数据安全与正确性

- **FUNC-01.12 读取故障显式化**：`loadJson` 目前把键不存在和读取失败都归一为 `null`，互动、跟进和首页可能把故障显示成空数据。区分首次空库、损坏和读取失败，保留旧值并提供重试，故障期间零写入。
- **FUNC-01.13 存储锁接管审计**：存储锁等待超时后使用 `steal` 可能与仍在执行的慢写重叠。验证双窗口慢写、挂起回读和失败路径，确保所有 JSON 读改写仍排他且无错误成功。
- **FUNC-01.14 AI 资料候选安全写**：捕获 AI 候选按旧快照逐条全字段写入，可能清空未双链人物资料或让同人多条候选互相覆盖。按人物合并补丁，回读最新资料，逐字段确认冲突。
- **FUNC-01.15 手动建档断点恢复**：创建文档、绑定行和写字段中途失败时，返回已完成步骤并按稳定 ID 续做，不重复建文档、不把部分成功报为成功。
- **FUNC-01.8a 初始化锚点误选（P0）**：`inspectWorkspace` 当前遇到同名总表直接取 `avBlocks[0]`，而 `readColumnsOrEmpty` 把列读取失败也当作零字段；若首个 AV 是用户的无关库，续建会给它补联系人列并保存错误锚点。预检应枚举所有同名笔记本、总表和库，以字段匹配及已有设置/持久标记为证据；候选零匹配、读取未知或多项同等匹配时暂停写入并让用户明确选择。选择后写前复核 `notebookId/hostDocId/dbBlockId/avId` 的归属和列证据；只有确认无旧候选且扫描完整时才允许新建。验收：同一总表首个 AV 为无关库、后一个为联系人库，及首个 AV 为零字段/读取失败的场景，均不向无关库补列、不保存错锚点；旧半成品可经明确确认续建。

- **RF-09 档案谈资与下次可问**：调研中的“怎么认识的 / 对方分享过的事 / 下次可以问”可直接改善会前简报，但当前人物资料与 `briefing` 没有显式字段。先决定插件自管字段还是人物文档标记块，定义来源、可见范围、模板和导出脱敏；不得让 AI 自动写入。验收：人物详情可编辑、简报可选展示、移动端可用；删除/改名不影响正文；迁移和导出明确包含/不包含。

### P3：先做能力验证或候选评估

- **RF-05 生日/重要日期日历出口**：先核对思源日历/CalDAV 或公开桥的能力、权限和冲突语义，再决定是否提供只读投影；不在未验证前承诺系统通知或双向同步。验收：用户明确选择日期范围和字段，导出失败不影响本地提醒；重复同步幂等，撤销出口不删除原始生日事实。

- **RF-06 官方 Agent 查询/确认式写入**：自然语言查人、查生日、查共同联系人和“记录一次互动”仍是远期候选。先做公开 API/能力注册 spike 与权限/确认设计，复用现有 `window.LvContacts` 能力，不让 Agent 绕过人物确认、AI 隐私预检或只追加互动纪律。验收：能力不可用时保留普通 UI；查询只读；写操作显示对象、日期、备注和幂等键并要求确认。

- **RF-07 图谱高级分析与快速输入**：按度数聚焦、图例即过滤、时间轴回放、潜在关系建议、Cardhop 式输入、OCR/二维码继续归入 `RESEARCH-UI-01`/既有 FAST 候选；进入实现前先补数据契约、移动端成本、可解释性和失败回退，不与 B14 原生图范围承诺混写。

- **RF-10 共同出席证据视图**：当前共同出席只在详情统计，不进入关系图。可评估默认关闭的同场事实列表/虚线边/场合节点，边显示来源和次数，且不计入 related 度数、最短路径或关系强度；依赖 B14 范围、来源追溯和非颜色图例，先做原型与证据可解释性评估。

**功能复核结论**：当前主线已经覆盖“建档—查人—记录—提醒—跟进—导出—关系探索”的核心闭环；下一阶段应先完成 `CODE-AUDIT-02` 的数据和关闭安全，再做 B11–B14。`RF-01` 是现有互动价值的直接补强，`RF-02/03/08/09` 是可复用现有数据或低耦合的中期增量，`RF-04/05/06/07/10` 先过契约、宿主、隐私和可解释性门槛。上述项目不改变 B05/C05 类型化关系延期决定。

## UI-AUDIT-02 设计、流程与交互补充审查（2026-09-29）

> 本节来自对 `UI-HANDOFF.md`、`UI-REFACTOR-PLAN.md`、`UI-REGRESSION.md`、`ui-prototype.html`、`PAGE-STATUS.md` 和当前组件实现的再次对照，调研取舍见 D-0022。已有 `UX-01`/`PAGE-01` 的通用要求保留；下列任务把之前只写成原则、但还没有具体状态契约或可验收出口的部分拆开。它们是待办，不代表源码已实现。原型交互和设计资料的校准归既有 `PAGE-01.10`，本节细化其验收；待补回归用例见 `UI-REGRESSION.md` 49–56。

### P1：先保证可访问、可确认、可恢复

- **PAGE-01.13 图谱可访问替代视图**：Cytoscape 画布即使能获得键盘焦点，屏幕阅读器仍无法读取节点、边、路径和截断范围。为关系图增加可切换的文本/列表结果视图，至少列出当前范围、节点/边数量、节点名称、关系来源、路径链和无路径原因；从列表可用键盘打开人物 Peek，导出内容与两种视图共用同一查询结果。验收：不使用画布也能完成查节点、查路径、读懂范围和打开人物；组织成员边、显式 `related` 边和原生引用边有文字来源标识。
- **UX-01.14 异步状态播报与焦点策略**：统一筛选刷新、分页、批量写入、组织成员变更、迁移恢复和跨窗口刷新等动作的 `role="status"`/`aria-live` 文案、结果计数、部分成功和失败重试出口。成功不能只靠短暂 Toast 或颜色；失败后焦点应回到错误摘要或首个可操作的重试/查看详情控件。验收：键盘和屏幕阅读器能知道“正在处理、已完成多少、失败多少、下一步是什么”，重复提交不产生重复播报。
- **PAGE-01.14 批量选择范围语义**：借鉴 Gmail/Linear 的“当前页全选 → 可扩展为全部筛选结果”模式，明确跨页保留、筛选变化、取消选择、批量影响预览和部分失败后的剩余选择。验收覆盖 0/1/200 人、分页、当前页/全部结果、筛选条件变化和部分失败；界面显示实际选中范围与写入人数，不能把未加载或已被筛掉的行静默纳入操作。
- **FAST-01.11 AI 调用前隐私预检与来源回显**：`CaptureDialog` 当前点击“AI 分析本页”即调用配置端点，设置页说明不足以替代本次调用提示。调用前显示文档范围、拟发送的文本类别/可能包含联系方式、端点来源和关闭/取消出口；确认后才调用，完成后回显候选来自哪段原文。验收：AI 关闭、取消、重试和权限失败均零意外调用；预检不写库，候选仍须用户确认后落库，隐私说明不泄露完整手机号或正文。

### P2：收口查找、组织操作和规模反馈

- **PAGE-01.10 设计资料与交互原型口径校准（细化既有项）**：仓库外原始 design 原型写“移动 Peek 底部抽屉/下滑关闭”，仓库内原型与当前实现已采用移动全屏详情；`UI-HANDOFF.md` 的 v0.2.1 事实和原型中“F02/F03/F04 仍是计划”的文字也已落后。以仓库内原型为验收基准，逐帧把历史设计决策、已实现能力、有意差异、B11–B14 和本轮交互质量线标清；更新 UI-HANDOFF/UI-REFACTOR 的历史/当前状态，不让旧截图或旧文案指导新页面开发。验收：首次使用、联系人/组织互跳、双图、AI 预检、批量范围和各失败态在原型中有可点击或可切换的最小演示；每处与源码有意差异写明原因与状态。
- **UX-01.15 搜索/筛选交互收口**：统一首页下钻、联系人列表、选人器、图谱和组织列表的搜索/筛选行为：显示匹配数量和命中高亮，键盘上下/回车选择，`Esc` 清除或关闭，移动端抽屉提供“应用/取消/重置”，切页和深链接明确携带或清除条件。验收：旧条件不会静默过滤新入口；空结果给出可执行的清除/放宽建议；列表、选人器和图谱不各自发明不同的清除语义。
- **PAGE-01.15 组织归档与批量变更影响预览**：组织归档、恢复、解绑成员和批量换组织前，先以零写入预览列出当前成员、历史归属、人物/组织标记区块、图谱呈现和不可达副作用；执行后按对象返回成功/跳过/失败，提供可撤销或安全恢复出口。验收：人物历史不丢、双向页面读回一致；失败可按未确认步骤重试，不重复新增成员或链接。
- **PAGE-01.16 视图密度与大数据量反馈**：在现有 40/200 人名册和 800 节点图谱夹具之外，设计 1k/10k 名册的渐进渲染或虚拟化、搜索防抖、结果裁剪、加载耗时提示和滚动/焦点锚点保留。验收：大名册滚动、键盘移动、筛选和返回 Peek 不跳位；明确显示“已显示 N / 总 N”、正在裁剪或需要进一步筛选，不能用空白或无尽 spinner 掩盖规模限制。
- **UX-01.16 图谱非颜色编码与色盲可读性**：分组、组织成员、显式关系和原生引用不能只靠颜色区分；增加文字图例、形状/线型/标签或模式标识，并检查灰度和常见色觉差异。`src/domain/graph.ts#GROUP_COLORS` 仍写死十六进制色值，随令牌审计把图谱分组色改为可随思源明暗主题适配的 `--lvct-*`/`--b3-*` 映射，避免域层持有展示色值。验收：去色或低对比模拟下仍能区分边来源、节点类别、选中态和截断态；明暗主题切换后颜色映射正确，颜色仍只是增强信息。

## UX-03 全产品原型重构与 UI 系统落地（高，2026-10-03 新增）

**目标**：以当前产品定位和源码事实为准，完成覆盖全页面、主要功能、真实用户旅程和关键状态的可交互原型；用一份规范统一视觉、交互、文案、响应式、无障碍、隐私与未来扩展边界。原型是设计依据，不是功能完成或宿主验证证明。

**设计基准**：[全产品 UI 系统规范](UI-SYSTEM-SPEC.md) + [可交互原型](ui-prototype.html)。任务按设计基线、页面、流程、状态与质量验收拆分；状态为待做。原型中的演示确认不连接思源、不产生写入。

### P0：事实基线、信任与高风险流程

- **UX-03.1 当前功能事实与设计状态映射**：逐页对照源码、PAGE-STATUS 与最新进度，将能力标为当前已有、宿主待验、设计目标或候选评估。验收：组织不再显示为未来占位；关系图与原生引用图分别呈现；已实现与未验边界有证据链接；旧快照保留日期，不被当作当前状态。
- **UX-03.2 导航和跨页上下文规范**：统一工作台五个主入口、次级流程、共享人物 Peek、移动导航和返回规则。验收：所有首页/列表/组织/图谱/档案条的人物入口携带稳定对象；关闭或返回恢复筛选、滚动、图谱范围和焦点；无来源时有确定出口。
- **UX-03.3 设计令牌与 B3 主题桥接核对**：将原型语义映射到现有 _tokens.scss 和 B3 变量，核对明暗、焦点、语义状态与分组色。验收：新增产品组件只消费 --lvct-*；只有令牌层直接桥接 B3；b3 引用含 fallback；颜色不作为唯一信息；原型与生产 token 的差异有说明。
- **UX-03.4 写入前影响预览统一**：对联系人批量操作、捕获、导入、组织成员调整、锚点修复、迁移恢复和 AI 外发给出统一预览结构。验收：确认前看见对象/字段/范围/新增更新跳过/可逆性；取消为零写入；无法确认结果时先核对，不盲目重试。
- **UX-03.5 AI 外发与候选确认流程**：明确模型用途、真实端点、发送范围、字段、规模、排除内容、取消和逐项证据；AI 输出保持未确认候选。验收：关闭 AI 后主流程仍可用；取消/超时不写入、不回填；无证据候选不默认接受；脱敏诊断不包含笔记正文、联系方式或密钥。
- **UX-03.6 失败、部分成功和未知结果文案**：统一读取失败、超时、权限、取消、部分写入和结果未知的表述及可执行恢复。验收：用户能区分已完成、未完成、未知；读取失败不伪装为空；重试只针对安全对象；表单草稿保留。

### P1：页面与功能的视觉、交互和信息层级

- **UX-03.7 工作台外壳和导航**：校准桌面侧栏、页头、内容宽度、Peek 层级及移动底部导航。验收：首页、联系人、图谱、组织、设置五个入口稳定；桌面不浪费窄屏空间；移动无横向溢出。
- **UX-03.8 首页与行动清单**：梳理统计下钻、生日、久未联系、待办、联系节奏、交往回顾和工作区状态。验收：每条行动显示原因、日期、上次互动与处理影响；不评判用户；统计口径可读；有数据、空、部分失败和重试都有清晰画面。
- **UX-03.9 联系人列表卡片和表格**：统一搜索、筛选、排序、保存视图、列设置、分页和卡片/表格主点击。验收：命中数量和条件可见；卡片密度舒适；表格窄屏可操作；复选框不打开详情；清空条件可预期。
- **UX-03.10 建档、编辑、重复核对与批量操作**：设计渐进补全、同名消歧、字段冲突、选择范围、批量影响预览和逐项结果。验收：只填最少必要资料可先保存；同名不自动合并；全部筛选与当前页范围可区分；部分失败时仍能定位未完成对象。
- **UX-03.11 人物详情概览与关系上下文**：逐项设计头像/身份、字段来源、组织归属、共同背景、最近互动、跟进、节奏、事实型简报和文档入口。验收：核心下一步可发现；事实与计划分开；来源状态可读；“无记录”不会暗示“没有关系”。
- **UX-03.12 互动时间线、模板与联系节奏**：把记录互动、搜索、来源/日期筛选、历史回顾、模板套用、加载更多和来源不可达纳入同一套层级。验收：互动只表示已发生事实；创建计划不改变最近联系；失败保留输入；来源打开失败说明原因。
- **UX-03.13 跟进的完成、推迟、跳过和取消**：调整人物详情与首页中计划动作的词义、确认和撤销路径。验收：每种动作解释会改变什么；完成不自动创建互动；推迟保持待办；批量操作逐项反馈。
- **UX-03.14 组织列表、详情和成员生命周期**：覆盖组织搜索、类型、当前/历史成员、双向人物入口、新建/编辑、结束成员和归档影响。验收：时间状态可读；两侧事实一致；预览保留历史和引用影响；归档、不可达和部分失败有恢复办法。
- **UX-03.15 关系图谱双模式和文本替代**：覆盖自研关系图、思源原生引用、本人/人物/全局范围、组织过滤、路径、共同联系人、图例和导出。验收：模式、数据范围、节点/边数量与截断可见；线型/标签辅助区分来源；文本列表与画布共享结果；原生宿主状态单独标记。
- **UX-03.16 设置六分区与数据维护流程**：逐页设计通用、数据与字段、提醒、AI 与隐私、服务桥、关于；校准体检、锚点、迁移、导出、恢复与诊断入口。验收：一眼能理解每区用途；危险操作不藏；预览、忙碌、成功、部分失败和重试一致。
- **UX-03.17 初始化预检、续建与首次成功**：整理多候选停止、对象复核、进度、失败续做、本人档案与可跳过导入。验收：明确会创建/复用什么与存储位置；歧义/未知阻断写入；中断后安全续做；新手可不配置 AI 完成第一位联系人和首条互动。
- **UX-03.18 笔记捕获完整旅程**：涵盖双链、AI 提名、来源证据、参与者勾选、隐私预检、写入变更预览、幂等和完成结果。验收：候选逐项可选/取消；AI 与确定链接视觉区分；原文追加范围可见；取消无写入；成功、跳过、失败和未知逐项展示。
- **UX-03.19 收编、vCard 和逐项补录**：覆盖来源选择、解析、字段映射、同名冲突、逐项确认、部分成功报告和核对后重试。验收：解析前后数据边界清楚；映射冲突可以理解；同名不自动合并；已成功项不会因重试重复写入；空/损坏文件有具体修复动作。
- **UX-03.20 文档档案条与双向导航**：梳理头像/徽标/字段 chips/简报折叠、复制联系方式、编辑、互动和返回工作台。验收：有限宽度不盖住文档；字段来源明确；来源不可达时有提示；打开人脉准确定位当前人物。
- **UX-03.21 共用组件和内容密度**：统一按钮主次、图标、表单、标签、提示、对话框、结果表、空态、骨架、Toast 与页面内反馈。验收：每个页面每个关键流程最多一个视觉主操作；低频内容渐进披露；关键回执不只靠自动消失的 Toast。

### P2：多设备、可访问性与交付闭环

- **UX-03.22 桌面/移动逐页适配**：对所有页面和对话框补真实 390px 视口布局，并覆盖软键盘、安全区、系统返回、表格、图谱、底部导航和全屏详情。验收：操作可达、无横向溢出、主按钮不被键盘遮挡；getFrontend() 仍是实现侧移动判断依据；隔离视口与真机结果分开记录。
- **UX-03.23 键盘、读屏和焦点路径**：为导航、列表、筛选、对话框、批量选择、图谱文本结果和异步状态建立逐流程键盘/读屏规范。验收：焦点可见且关闭后恢复；动态结果不过度播报；对比度满足 WCAG 2.2 AA；不存在只靠颜色或悬停才能获得的信息。
- **UX-03.24 明暗主题和长内容压力审查**：检查亮暗主题、长姓名/标签/组织名、多语言文本、缩放与低对比。验收：界面不丢主次、状态、边界和焦点；省略文本可被完整读取；内容放大后可滚动操作。
- **UX-03.25 用户旅程舒适度走查**：至少走新手首次成功、日常处理提醒、列表找到人后记录互动、笔记捕获复核、移动端导入失败恢复、组织成员调整、图谱查证据、备份恢复八条旅程。验收：每条记录步骤数、意外中断、返回是否保留上下文、失败后是否知道下一步；发现问题进入页面任务。
- **UX-03.26 原型可交互性与稳定检查**：为导航、主题/设备/状态、人物 Tab、卡片/表格、图谱模式/文本视图、设置分区和高风险预览建立自动冒烟。验收：无控制台错误；控件能抵达正确视图；移动端无关键覆盖；原型只改变演示状态，不触发真实写入。
- **UX-03.27 页面状态矩阵和原型/代码差异台账**：逐页登记首次加载、正常、空、部分失败、忙碌、成功、失败重试、不可用、草稿、跨窗口、移动和暗色。验收：每项标注当前已有、宿主待验、设计目标或候选；每个有意差异记录理由与证据；不能用历史截图替代当前状态。
- **UX-03.28 设计评审与实现验收模板**：建立按页检查信息顺序、状态、点击结果、移动/明暗、键盘、隐私和来源的模板。验收：实现逐页记录“符合原型 / 有意差异及理由 / 待修正”；功能测试通过不自动代表视觉通过，截图成功也不自动代表宿主验收通过。
- **UX-03.29 候选能力的设计停放区**：在产品规划中隔离纪念日、礼物往来、周回顾、档案谈资、地图、日历、OCR/二维码、嵌套组织、类型化关系和 Agent。验收：只登记用户问题、数据契约、隐私/外发、宿主依赖、移动成本与解释方式；研究未完成前不进入主导航或已承诺功能表。

### UX-03 交互证据与细节补全

- **UX-03.30 可操作控件清单**：逐个盘点原型和生产页面中的按钮、链接、下拉、开关、卡片、标签、分页和图谱节点。验收：每个看起来可操作的控件都有预期结果、键盘名称、失败反馈和代码归属；演示占位明确标注“设计目标/静态示例/宿主待验”，不留下无声无效点击。
- **UX-03.31 联系人字段边界与样例数据审计**：区分联系人 AV 预设字段、标签、人物文档内容和组织成员的部门/职位/任职日期；清理把城市、职业或组织属性误画成联系人字段的样例。验收：卡片、详情、导入映射、重复核对和文档档案条中的每个值都有来源类型；不支持的字段不能以已支持控件出现。
- **UX-03.32 来源徽标与事实新鲜度**：为用户录入、人物文档、互动、组织成员、思源引用和 AI 候选设计统一来源徽标、更新时间、不可达和过期表达。验收：来源可追到文档/记录或说明不可达；“无记录”“读取失败”“未核实”有不同文案和操作。
- **UX-03.33 桌面 Peek 与移动全屏详情**：统一列表、首页、图谱、组织、档案条进入人物详情的行为。验收：桌面保留下层工作区，移动成为真正对话层；关闭/系统返回恢复筛选、滚动、图谱范围和触发焦点；背景不可交互，导航的 aria-current 不漂移。
- **UX-03.34 页面路由和返回语义**：为主导航、次级流程、人物/组织互跳、弹窗和文档回跳定义来源上下文对象。验收：深链、刷新、无来源关闭和跨窗口更新都有确定出口；返回不会把用户带到过时筛选或错误人物。
- **UX-03.35 关系图双模式等价性**：分别核对自研关系图与思源原生引用图的范围、中心、过滤、节点/边计数、图例和宿主待验边界。验收：模式切换不丢筛选；画布、文本结果和导出共享同一查询快照；边的来源、方向、组织成员语义可读。
- **UX-03.36 图谱可读性压力测试**：覆盖节点密度、截断上限、长姓名/组织名、孤立节点、无路径、路径过长、缩放、键盘和文本等价视图。验收：截断原因和收窄方式可见；不依赖悬停；移动端能先看文本结果再定位画布节点。
- **UX-03.37 导入步进与结果幂等**：验证来源选择、字段映射/冲突核对、逐项结果三步之间的状态、返回和刷新。验收：重复进入不会追加重复结果；成功项、待核对、失败、未知分开；安全重试只处理可重试项，取消不写入。
- **UX-03.38 导入来源与字段映射解释**：为思源文档、vCard、粘贴文本分别说明读取范围、解析方式、忽略字段、重复判断和冲突策略。验收：用户确认前看见实际映射；不支持的 ORG、ADR、PHOTO 等属性不会静默伪装为联系人字段。
- **UX-03.39 手动互动表单契约门禁**：原型只展示当前接口支持的人物、可选模板和备注，并明示时间由当前流程生成；互动类型和历史日期需先完成 schema、导入导出、迁移和联系节奏评估。验收：契约决策前页面不出现伪造的类型/日期控件；决策后同步更新 DATA-CONTRACT、域层、表单和测试。
- **UX-03.40 互动与跟进的语义分离**：对记录互动、创建跟进、完成、推迟、跳过、取消、重新打开建立文案和结果矩阵。验收：计划动作不产生已发生互动；互动失败保留草稿；首页和人物时间线不把计划误算为联系事实。
- **UX-03.41 AI 候选证据等级**：设计双链命中、已有联系人、AI 提名、待消歧和无证据五类候选的不同层级。验收：AI 候选包含证据片段、位置、置信度/不确定性和人工确认动作；低证据不默认选中；模型拒答、超时和空结果都有本地回退。
- **UX-03.42 AI 外发同意与撤回**：把用途、端点、字段、文档范围、预计规模、排除内容、脱敏、日志保留、取消和调用中止做成一次可核对的预检。验收：关闭 AI 不阻断手动流程；取消/超时不回填或写入；用户可收窄范围并看到最终实际发送摘要。
- **UX-03.43 AI 生成内容的草稿边界**：为简报、谈资、关系总结、候选标签和下一步建议统一显示“AI 草稿/待确认”。验收：事实引用与推测分开；逐项接受/拒绝/编辑；没有来源的生成内容不能进入联系人事实、提醒或关系图。
- **UX-03.44 隐私诊断最小化**：设计脱敏诊断预览、字段白名单、请求编号和复制前确认。验收：不含姓名、联系方式、笔记正文、密钥、访问令牌或完整路径；用户能在复制前逐项删减；失败日志仍能定位模块而不暴露内容。
- **UX-03.45 组织成员时间线**：统一组织列表、组织详情、人物详情和图谱中的当前/历史成员、部门、职位、加入/离开日期和归档状态。验收：多组织、多段历史和悬空成员可区分；结束成员关系保留历史；影响预览说明双方页面和图谱变化。
- **UX-03.46 批量操作安全边界**：覆盖当前页、全部筛选结果、手动选中三种范围，以及标签、分组、跟进和导出等动作。验收：确认层显示实际对象数和字段；不可逆动作需要更强确认；部分成功逐项列出；刷新或跨窗口变化不会静默覆盖选择。
- **UX-03.47 备份、恢复与迁移预览**：为导出、合并导入、恢复、删除墓碑和 schema 升级统一比较界面。验收：展示新增/更新/跳过/冲突/未知、覆盖范围和可回滚性；预览零写入；确认后锁内重读，结果与用户确认的快照一致。
- **UX-03.48 数据健康与锚点修复分层**：区分只读体检、建议修复、唯一候选重绑、歧义停止和权限失败。验收：体检结果不伪装为修复完成；每个修复列出目标文档/字段/影响；失败保留原锚点并提供安全重试。
- **UX-03.49 初始化向导续做体验**：验证预检、多候选、复用/新建、断点续做、局部失败和完成后的首个任务入口。验收：重复点击不重复创建；未知读取和歧义阻断写入；用户可跳过 AI 和本人档案，仍能完成第一位联系人与首条互动。
- **UX-03.50 页面状态证据包**：为首页、联系人、人物、组织、图谱、捕获、导入、设置、档案条及高风险弹窗各建立正常、空、加载、部分失败、处理中、成功、重试、不可用、草稿、跨窗口、移动和暗色证据。验收：每个状态标注实现/宿主待验/设计目标；截图、操作步骤和预期结果成套保存。
- **UX-03.51 视觉回归与令牌漂移**：建立桌面、390px、暗色、长内容和大字号的截图基线，检查颜色、间距、层级、焦点、边框和 B3 变量映射。验收：差异有分类和理由；原型直接色值、生产组件绕过令牌或前缀违规会被守门检查拦截。
- **UX-03.52 长内容与多语言布局**：覆盖超长姓名、标签、组织名、来源标题、错误文案、英文/混合文本、系统字体放大和窄屏键盘。验收：没有不可滚动、遮挡、横向溢出或依赖截断才能理解的关键信息；省略字段可通过可访问名称或详情查看完整值。
- **UX-03.53 读屏与键盘交互剧本**：逐流程核对导航、搜索筛选、表格选择、人物 Tab、图谱文本、导入步骤、设置分区、弹窗和异步结果。验收：焦点顺序与视觉顺序一致；动态状态只播报必要变化；弹窗焦点锁定和关闭后恢复可重复验证。
- **UX-03.54 触控与误触防护**：检查移动底部导航、卡片主入口、复选框、图谱节点、弹窗按钮、滑动区域和危险操作的点击区域及间距。验收：常用控件满足移动最小点击尺寸；选择与打开分离；危险动作不能因滑动或双击误触发。
- **UX-03.55 离线、慢速和宿主能力降级**：模拟内核读取慢、桥不可达、原生图不可用、权限不足、网络关闭和多窗口更新。验收：核心本地手动流程可继续；能力不可用与无数据区分；用户知道正在等待什么、能否取消和下一步回退。
- **UX-03.56 文案与日期本地化**：统一“距上次互动”“计划日期”“来源时间”“未知”和时区口径，覆盖相对日期、跨年、农历生日和无效日期。验收：不使用施压或关系评分；绝对日期和相对日期的含义可追溯；错误日期阻止写入并指向修复字段。
- **UX-03.57 页面级性能预算**：为首页、联系人列表、图谱、组织成员、捕获候选、导入结果和设置体检登记首屏、筛选、切换和长列表的可接受等待与渐进展示。验收：预算基于真实数据量和宿主环境；超时显示原因和重试；性能优化不得省略状态或来源。
- **UX-03.58 设计到代码映射表**：将规范中的页面、组件、令牌、状态和交互动作映射到实际源码文件、测试和宿主证据。验收：每个设计目标有实现负责人和阻塞原因；实现差异记录“符合/有意差异/待修正”；旧 UI 任务编号不覆盖新基准。
- **UX-03.59 用户研究与可量化回顾**：以不收集联系人内容为前提，设计首次成功、找人、记录互动、捕获确认、导入失败恢复、组织维护和备份恢复的观察表。验收：记录步骤、停顿、误解、回退和信心反馈；不预设未经基线验证的数值目标；研究结论能回链到页面任务。
- **UX-03.60 发布前 UI 门禁包**：整合契约核对、架构测试、原型冒烟、状态矩阵、截图、可访问性、移动/暗色和宿主待验清单。验收：`pnpm check && pnpm test`、浏览器控制台、关键旅程和保护文件审计均有记录；任何未验状态显式列出，不以“看起来完成”替代证据。

### UX-03 执行门槛与顺序

1. 先完成 UX-03.1～03.6 的事实和信任基线；涉及数据契约或宿主 API 时先遵守 DATA-CONTRACT 与隔离 spike 规则。
2. 再按用户主路径完成 UX-03.7～03.20；先看原型与状态，再实现各页，双图、组织、捕获和迁移不能省略异常分支。
3. 并行完成 UX-03.22～03.24、UX-03.30～03.36 的控件、状态、设备和图谱证据；再推进 UX-03.37～03.49 的高风险流程。
4. 用 UX-03.25～03.28、UX-03.50～03.60 做旅程、原型、可访问性、性能和实现对齐验收；每条未完成证据保留阻塞原因。
5. UX-03.29 以及规范候选区保持候选性质。进入正式产品范围需有独立决策、数据边界和验收，不按原型出现顺序自动排期。
6. 任务完工按仓库工作流跑 pnpm check 与 pnpm test；涉及源码才跑对应构建/隔离/E2E。宿主、真机和多窗口待验状态单独记录。
