# 架构决策记录（DECISIONS）

每条决策带编号、日期与动机；重大翻转需新增条目而非修改旧条目。

## D-0001（2026-09-27）数据主干选思源数据库（AV），不用插件自管 JSON

人脉数据天生是"笔记内容的一部分"：用户要求一人一文档、要双链、要卸载插件后数据仍在。
AV 官方 API 完整覆盖建库/绑行/写值/关联（M0 spike 9/9 实证），并提供原生四视图与筛选。
打卡插件的自管 JSON 路线仅适用于"本就不该长在文档里"的数据（打卡记录）；本插件自管 JSON 只存
设置/偏好/可选事件缓存。参照 [[D-0004]]。

## D-0002（2026-09-27）技术栈选官方 vite-svelte 模板（Vite 8 + Svelte 5 + pnpm），不用自家 webpack 栈

本插件是三个插件里表单/视图最重的（卡片、表格、图谱、属性面板、移动端）。
Svelte 5 响应式显著降低视图层成本；发布流水线由通用发版 skill 负责、E2E 基建是内核级与打包器无关，
"复用自家 webpack 基建"的收益弱于组件化收益。约束：**域层/数据层保持框架无关纯 TS**，
Svelte 只出现在 components/，由 `tests/architecture.test.ts` 守门。

## D-0003（2026-09-27）M1 砍掉模板的 kernel.js 双 target

内核插件（goja 运行时）为常驻后台服务而生，本插件 M1-M4 无内核侧需求；
保留会带来发布物维护成本。需要接思源 Agent 或后台提醒服务时（远期）再引入，
模板 `plugin-sample-vite-svelte` 的 kernel-capture 示例仍在官方仓库可考。

## D-0004（2026-09-27）UI 文案 M1 先中文硬编码，i18n 全面接入放 M5 发布门禁

目标用户中文优先；向导/工作台的完整双语键表在 M5 落地（`public/i18n/*.json` +
i18n parity 测试）。plugin.json 的 displayName/description 双语从第一天就绪。

## D-0005（2026-09-27）relation 自关联双向作为 MVP 关系主干；类型化关系库放二期

单一 relation 字段存边成本最低且原生可 rollup；关系类型（同事/家人/引荐人）的严谨建模需要
"行=关系"的独立库，MVP 用「分组列着色图谱 + 文档双链区块」过渡，二期一键升级，不做半吊子中间态。

## D-0007（2026-09-27）新建联系人的防重与收编语义

`createDocWithMd` 对同路径**会再建新文档**（不是幂等返回原 ID，E2E 实证）。因此：
1. 防重判据 = 按姓名查 `renderAttributeView`（query=姓名）中的精确名匹配，与文档 ID 无关；
2. 通过防重后，若目标文档已存在但未绑定行（用户手建的文档），直接收编（补绑行+写字段）；
3. 已绑定的同名联系人 → 抛错由 UI 呈现。

## D-0008（2026-09-27）渲染值的 select 选项用 content，列定义 options 用 name

写入与回读的单元格值 `mSelect[].content`；仅 `view.columns[].options[].name` 是列元数据。
api/av.ts 以两个类型显式区分（AvValueOption / AvColumnOption），防止混用。

## D-0009（2026-09-27）关系数据以 itemID 为边、文档 ID 为节点

relation 字段的 blockIDs 存的是行 itemID；卡片跳转与图谱节点用 docId。
ContactSummary 同时携带两者（itemId/docId/relatedItemIds），换算只在服务层做一次，
组件层禁止再触碰映射端点。

## D-0029（2026-10-04）关系事实与人物文档投影分离

关系字段是唯一事实源，人物文档中的“相关人物”区块只是可重建投影。关系编辑在锁内回读最新名册，写后再次回读核对目标边；事实核对未知时不自动重试。事实已确认写入而某个文档投影失败时保留事实，逐文档报告失败和重试键，重试按当前事实幂等重建，不回滚关系。

## D-0010（2026-09-27）语言策略修订：zh-CN 为主语言，en 保持键级一致

M5 发布门禁从"完整双语"修订为"zh-CN 全量 + en 键级一致（parity 测试守门）"：
目标用户中文优先，en 首版只覆盖插件级文案；完整英文翻译放 v0.2。
parity 测试（tests/i18n.test.ts）保证以后补翻译时不会漏键。

## D-0011（2026-09-27）"共同交集"的记录方式与关系边界

从笔记捕获时，每位参与者记录一条互动事件（source=diary），事件共享 **externalRef=笔记 ID**
作为"同一场合"身份；时间取笔记确认的场合日期，地点/备注进事件 note。
共同出席**不自动建** related 关系边——同场 ≠ 有关系；"共同出席统计/同场边"作为二期图谱
叠加层（虚线），由事实数据随时可算，不抢先写入关系字段污染用户数据。

## D-0012（2026-09-27）跨插件集成：做"人员服务"提供方，不做私有格式消费者

任务管理插件想在待办里加参与人员，正确姿势是人脉插件对外提供公开桥
（window.LvContacts 协议 + capabilities 协商，形态对齐打卡 v5）与思源官方 Agent 能力；
不读取、不监听其他插件私有存储格式（D-255 纪律）。外部插件调用 ensurePerson/recordInteraction
即可完成"任务带人 → 人脉自动增长"。

## D-0006（2026-09-27）锚点 ID 信任链：设置固化，绝不反查

notebookId/hostDocId/dbBlockId/avId/fieldMap 全部在初始化时固化为插件设置；
运行时不按名称/路径反查（用户改名是常态）。锚点失效（文档被删等）在设置页给出重建入口，不做静默自愈。

## D-0013（2026-09-27）vCard 导入导出：数据保真优先，语义靠自定义属性与查重回填补齐

vCard 是冷启动与数据可迁移的关键通道（ROADMAP 需求②延伸）。映射取舍：
1. **多 TEL 用 `" / "` 连接写入单值电话字段**——丢号码比字段难看代价大；EMAIL 只取首个
   （插件邮箱字段有格式校验，拼接值会卡死后续编辑）。
2. **BDAY 只接受完整年月日**；无年份（vCard 4.0 `--0520`）与文本形式丢弃——生日字段契约是完整日期，
   塞占位年份会污染提醒投影。农历生日导出写 `X-LVCT-BDAY-LUNAR` 而非 BDAY（BDAY 语义是公历），
   回导可无损恢复农历勾选；外部文件的农历无法识别，不做猜测。
3. **导出不折行**（RFC 75 字节是 SHOULD）——主流解析器都容忍长行，折行按字节算需要按 UTF-8
   重新分块，收益为零；读取侧则必须完整支持展开（含 QP 软换行的无空格续行变体，大量国产导出器如此）。
4. **导入对同名默认跳过而非合并**——与 D-0007 防重同源；合并（更新已有联系人字段）是编辑语义，
   不在导入通道里悄悄发生，UI 预览标注"已存在"由用户决定。
5. **微信号不导出**——vCard 无标准属性，X- 扩展在其他应用里是死数据。
6. 批量导入复用收编的写放大控制（绑行 200/批），查重对名册快照一次完成，不逐人重查。

## D-0014（2026-09-27）UI 设计体系：令牌三层架构 + 左侧栏导航 + Peek 详情

UI 重设计方案定稿（移交文档 docs/UI-HANDOFF.md，原型 docs/ui-prototype.html，排期 docs/UI-REFACTOR-PLAN.md）。核心取舍：
1. **令牌三层架构**：b3 变量 → `--lvct-*` 语义令牌（src/style/_tokens.scss，唯一桥接点）→ 组件类。
   组件禁直引 b3 与色值字面值——比"组件散引 b3"多一层间接，换来 b3 变量版本漂移时的单点修复能力
   （§6 已有多起 b3 行为与文档不符的先例）。分组色为插件自有令牌、明暗双套（color-mix 派生），
   替代现状硬编码 hex。
2. **左侧栏导航取代顶部三 Tab**：为二期「组织/建议」留扩展位，对齐主流笔记软件范式；

   Peek 在列表/图谱/仪表盘三视图内均可达，dock 只在编辑器场景可达；且防误丢「记一笔」输入。

## D-0015（2026-09-27）最短连接路径沿用显式无向关系与现有算法

- 复用 Cytoscape 的无权无向 Dijkstra，不手写路径引擎、不新增依赖或关系存储。
- 域函数使用临时 headless 图计算并立即销毁，无 DOM、内核或存储 IO；界面只更新现有画布样式，不因查询重新布局。
- 范围为当前筛选和裁剪后的展示图，悬空边与自环不参与；无路径仅表示当前图内无连接，不推断完整名册或现实社交关系。
- 等长路径只返回一条，不承诺某位中间人物优先；边权均为 1，不表示关系强弱、方向或引荐意愿。共同联系人模式与路径模式分开，避免混合统计。

## D-0016（2026-09-27）二度关系与无关系筛选的范围

- 二度结果为当前图内距离恰好两段的联系人，复用 Cytoscape 邻接算法，排除中心和已有直接关系；高亮同时保留直接联系人作为中间连接，不自动建立新关系。
- 无关系筛选使用完整名册投影的有效关系度数，包含入边；悬空关系与自环不计。先判断孤立再应用搜索/分组和规模裁剪，避免隐藏关系对端造成假孤立。
- 无关系筛选只改变展示，不提供删除/自动补关系；设置仅驻留当前组件，不增加存储契约。清除筛选同时重置该开关。

## D-0019（2026-09-28）初始化必须幂等可续建；写入端点形状以真内核实证为准

首次引导实故（v0.2.0 首发，用户首启）：第一次初始化在中途失败、第二次点击直接报
"已存在同名笔记本「人脉」"，向导无路可走。隔离内核（v3.8.5）复现并定位到两个独立缺陷：

- **端点形状未按实证消费**：`insertBlock` 的 `data` 是**事务结果数组** `[{doOperations:[…]}]`，
  而 api 层按对象读 `data.doOperations`，于是建库第一步就抛"未返回新块 ID"（真内核实证：
  scripts/spike/init-resume-spike.mjs 通道10）。M0 spike 与 M2 E2E 都把形状写对在脚本里，
  却没有守门 api 层的消费端——"脚本里对了"不等于"产品代码对了"。
- **物化参数错**：`createDatabaseInDoc` 调 `renderAttributeView` 时传 `createIfNotExist:false`，
  全新数据库块上内核返回 `code=-1 attribute view not found`（通道9a）；正确值 `true`
  且物化后调用幂等（通道7/9b/9c）。

**决策**：初始化链整体按"幂等可续建"实现——复用同名笔记本（内核允许重名，实测第二次
`createNotebook` 返回 code=0 并静默建出第二个同名笔记本——必须客户端预检）、笔记本内按标题
找回「联系人总表」、文档内按 `type='av'` 找回数据库块并从 `blocks.markdown` 还原 avID
（块 IAL 里没有 avID）、按列名+类型对账只补缺失列（重复 keyName 不报错但会叠出同名列，
实测通道6）、回链列已在则跳过双向配置；不删除任何已有内容。现场识别只认「联系人总表」
文档内的数据库块，避免把同名笔记本里用户的无关数据库当成自己的。向导失败后按钮转为
「继续初始化」，并在运行前预检提示"将复用哪些已有内容"。

**纪律补强**：任何内核端点的消费形状（返回体结构，不只是端点存在性）必须在真内核 spike
里断言，并由隔离回归守住产品代码的读取路径；只在独立脚本里复刻序列不算验证。

## D-0024（2026-10-03）内核请求先区分等待失败、协议失败与合法空结果

`fetchPost` 没有可传入的取消信号，插件不能把超时或取消描述成“内核写入已撤销”。因此统一在
`kernelPost` 外层设置 deadline：`AsyncTimeoutError` 和 `AsyncAbortError` 只表示调用方停止等待，
不触发自动重试；写操作是否重发由用户显式决定。响应信封、端点数据容器和权限失败分别用
`KernelProtocolError`、端点解码器、`KernelPermissionError`/`KernelResponseError` 表示，避免把
坏响应降级成空列表或空映射。

写入端点的成功 `data` 不作为回读事实源：允许契约明确的空 `data`，例如属性写入成功后由服务层
按既有流程重新渲染确认；只有已经实证的返回形状才做对象解码。这样既不把合法的 void 写入误报为
协议失败，也不把未知对象当成成功。

## D-0026（2026-10-03）等待超时保留存储锁，不接管仍可能恢复的写者

AG-P0-019 的实际浏览器双上下文复现：旧写者已读出互动快照，保存暂停超过全部取锁等待；原实现以 steal 接管后第二上下文保存新记录，旧保存恢复又覆盖该记录。因此等待时长不能作为持有方已停止的证据，取消等待也不能撤销已发给宿主的保存。

取锁保留有限宽限重排队，次数耗尽后返回可识别的占用超时错误，并保证该调用的业务回调尚未执行；不再接管。锁获准后清除取锁定时器，原临界区一直持锁至完成或失败。回调自身的取消/失败不能被取锁重试机制重新执行。真正挂起时牺牲该键的暂时可写性，等待原操作结束并核实结果；不以自动重发、增加等待时长或强制释放锁恢复可用性。无 Web Locks 时仍只保证同一上下文排队，真实宿主多窗口待验。
