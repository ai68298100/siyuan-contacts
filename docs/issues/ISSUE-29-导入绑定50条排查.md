# Issue #29：导入 400 多个联系人只绑定 50 个

## Issue 现状

- Issue：[\#29](https://github.com/ai68298100/siyuan-contacts/issues/29)
- 报告版本：v0.5.6；思源 3.8.6；桌面端
- 原始描述：`我导入400多个联系人，只绑定了50个`
- 没有提供导入类型、是否全选、导入报告、日志或截图，因此无法仅凭 Issue 还原唯一场景。

## 代码排查结论

插件有两条“导入”路径：

1. **已有文档收编**：扫描按 500 篇分页，单次扫描预算默认 1000 篇；选中项进入固定队列，逐项核实文档、绑定行和字段。没有 50 条截断，但扫描继续后新增候选不会自动勾选，界面会显示已扫描和已选择数量。
2. **vCard 导入**：先逐卡建文档，再批量绑定数据库行，最后通过“绑定文档 ID → 行 ID”映射写入字段。v0.5.6 的业务层使用 200 条绑定批次，并对大批文档 ID 使用单次映射请求。

Issue 中的“恰好 50 条”实际对应属性视图读取链路：插件旧实现向 `/api/av/renderAttributeView` 传 `pageSize: -1`，思源 3.8.6 内核会把小于 1 的页大小回退为属性视图默认值 50。名册读取因此只拿到前 50 行；导入过程逐项回读名册核实时，第 51 项以后会被误判为没有唯一绑定，最终表现为“只绑定 50 个”。这不是绑定端点本身的 50 条上限。

## 已完成修复

- 在 `src/api/av.ts` 增加统一的 `ATTRIBUTE_VIEW_BATCH_SIZE = 50`。
- `bindDocsAsRows` 对输入去重并按 50 条拆分。
- `mapBoundDocIds` 按 50 条拆分请求并合并结果，空输入不发请求。
- 存量文档收编和 vCard 导入统一使用该批次策略。
- `renderView` 改为显式分页（单页最多 500）并按 `rowCount` 汇总全部行；真实思源返回总数时，即使服务端按默认 50 行分页也会完整读取，重复页和不完整分页会明确报错，不再静默截断。
- 增加 401 行分页回归测试，模拟内核按 50 行返回，确认跨页结果保持顺序且全量可见；另覆盖缺少 `rowCount` 时按短页收口的旧响应兼容行为。
- 增加 101 条 vCard 回归测试，并模拟映射接口每次最多返回 50 条；测试确认 101 条全部绑定、全部写入，且不存在第 51 条后的漏项。
