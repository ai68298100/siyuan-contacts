## 1. 人脉主库（思源数据库）

### 1.1 布局锚点

- 笔记本：向导创建，默认名「人脉」（记录 `notebookId`）。
- 宿主文档：`人脉/联系人总表`，内嵌一个数据库块（记录 `hostDocId`、`dbBlockId`）。
- 数据库 ID（`avId`）由**插件客户端预生成**（`newNodeId()`），插 DOM 块后用 `renderAttributeView(createIfNotExist: true)` 物化（spike ①；该参数必须为 `true`，见 §6）。
- 四个锚点 ID 全部固化在插件设置里；**绝不通过列名/文档名反查锚点**。
- **初始化幂等可续建**（D-0019）：设置缺失时重跑向导不新建第二份——按名复用笔记本、按
  标题在笔记本内找回「联系人总表」、按 `type='av'` 找回数据库块并从 `blocks.markdown`
  还原 `avId`、按列名+类型对账只补缺失列、回链列已在则跳过双向配置；不删除任何已有内容。
  现场识别只认「联系人总表」文档内的数据库块（同名笔记本里用户的无关数据库不当作自己的）。

### 1.2 字段契约

主键(block)列由建库自带 = 姓名 = 文档标题。预设字段（`src/domain/fields.ts` 为唯一事实源）：

| 稳定键 | 默认列名 | 类型 | 说明 |
|---|---|---|---|
| `birthday` | 生日 | date | 公历时为完整公历日期；`lunarBirthday=true` 时年份作为出生年份、月日作为农历月日；`isNotTime: true` |
| `lunarBirthday` | 农历生日 | checkbox | true = `birthday` 的月日按农历月日解释并换算为本年度公历发生日 |
| `phone` | 电话 | phone | |
| `email` | 邮箱 | email | |
| `wechat` | 微信 | text | |
| `website` | 网站 | url | |
| `group` | 分组 | select | 内置建议选项：家人/朋友/同事/同学/其他；用户也可写入任意自定义字符串，AV select 会按思源语义自动建立对应选项；不改变字段结构 |
| `tags` | 标签 | mSelect | |
| `related` | 相关人 | relation | 指向本库；双向，回链列「被相关人」内核自动创建 |

- 插件记 `fieldMap: 稳定键 → keyID`，**用户改列名不影响插件**；用户删列则相关功能降级并在设置页提示重建（M2+）。
- `keyID` 由客户端按节点 ID 格式生成（spike ②）。

### 1.3 行（人）的语义

- 一个人 = 一篇文档（`人脉/<姓名>`）+ 主库中绑定的一行（`addAttributeViewBlocks isDetached: false`）。
- **`itemID`（行 ID）≠ 绑定文档 ID**。换算只准经：
  - `getAttributeViewItemIDsByBoundIDs`（文档 ID → itemID，spike ④）；
  - 渲染响应主键单元格：`rows[].id` = itemID，`value.block.id` = 绑定文档 ID。
- 删除联系人文档前先解绑行（`removeAttributeViewBlocks` 对绑定行只解绑不删文档，spike ⑥）。

**AG-B12-003 同名与新建续做**：姓名只用于候选提示，文档 ID 是人物身份；同名不同文档允许并存。手动新建先完整分页核实未绑定同名文档，并显示已有联系人和未绑定候选的稳定 docId/行 ID/路径等证据，由用户明确选择“独立新人物”或具体文档 ID；不能自动收编第一个或唯一同名文档。扫描失败不等于没有残留，不发送创建请求。默认 API 调用遇到候选报消歧，显式允许同名才创建独立人物。

候选排除当前联系人总表及带 custom-lvct-org 标记的组织文档；标记读取失败停止预览，不能把组织收编为人物。组织和人物同名可以建立独立文档，二者身份不合并。

新建断点持有稳定请求 ID、原锚点/姓名/路径/字段签名、创建状态与已核实 docId/itemId，以及人工选择的 existing/created 来源。创建 Markdown 同次写 `custom-lvct-contact-draft="<请求 ID>"`，v3.8.6 隔离内核已证原子创建和请求查询（text-encoding-results.json.contactRequestMarker）。响应丢失只查询原请求；未知/多标记/读取失败不重建。明确拒绝可用原请求重试；选定已有文档则按原 ID 核实所在笔记本与可达性，删除或解绑后不创建替代、不改绑到同名人。已核实后的文档改名不改变请求身份。绑定响应丢失先回读映射，行改变阻止字段补写；失败字段重试先核实再补写。相同数据库的手动新建/导入写入使用同一创建锁；调用方保留断点并原样重试。手动表单在产生断点后冻结资料，取消保留窗口，明确放弃只丢内存断点，不删除已保存文档/行；当前窗口关闭后不能宣称自动找回旧请求。

vCard 同名项默认跳过，但允许逐项人工确认“作为独立人物”后导入；不是合并。预览显示现有 docId/itemId 及同批卡片序号；重试继续原请求，不凭名称补写同名行。外部桥按名查人遇到多候选明确拒绝并返回候选稳定 ID，调用方选好后用 getPerson(docId)，不返回第一人。相关人选人器对同名候选显示稳定 docId/itemId 与联系方式；AI 无稳定目标证据的同名资料/跟进候选不自动指派第一人。

### 1.4 单元格写入

2026-10-04 实际服务隔离内核补证：`setAttributeViewBlockAttr` 成功返回 `data: {value: <AvValue>}`，不是顶层 AvValue；写后仍须独立渲染核实。全新空 `select/mSelect` 单元格保留合法 `type/keyID` 而省略 `mSelect` 属性，省略表示空选项；显式非数组、非法选项仍按未知处理。不得将合法空列误报为坏数据而阻断生日保存。

`setAttributeViewBlockAttr` 传 `itemID`（`rowID` 已进弃用通道）。值形状（全部 spike ⑤ 回读验证）：

| 类型 | value |
|---|---|
| text/phone/email/url | `{"<type>": {"content": "..."}}` |
| date | `{"date": {"content": <ms>, "isNotEmpty": true, "isNotTime": true}}` |
| select / mSelect | `{"mSelect": [{"content": "...", "color": "1"}]}`（新选项自动创建） |
| checkbox | `{"checkbox": {"checked": true}}` |
| relation | `{"relation": {"blockIDs": [<对方 itemID>]}}` |

联系人资料写入（新建、编辑、批量编辑与 vCard 导入）共用同一套写入前置检查和逐字段结果模型：在任何 `setAttributeViewBlockAttr` 之前，必须重新读取当前属性视图并严格验证 `fieldMap` 的列存在、稳定键唯一映射及列类型一致；检查失败时零字段写入，旧值不被清空，文档/行创建流程也不得在此之前启动。字段写入按字段隔离并记录 checkpoint；部分字段失败不能报告整项成功，已成功字段保留，后续重试只补失败字段。非法日期、非法邮箱和未知/缺失字段映射在写入前拒绝。

资料写入完成后须直接重新渲染属性视图，按 itemID 定位唯一行并逐字段核对，不使用名册缓存代替。
`applied` 只表示预期值已核实；请求返回成功另记 `requestStatus: accepted`，不能单独作为完成证据。
读取失败、行/列丢失、重复行/单元格或值结构未知记 `unknown`；已读到合法值但不符合预期记 `failed`。
报告分别含 accepted/applied/failed/unknown/skipped/unresolved；任一未核实字段不得标 complete。
生日以当地日期比较（不受毫秒内的时间影响），清空须验证 date.isNotEmpty=false；农历核对 checkbox，
标签按去重集合比较，分组按单选值比较，字符串按写入后的规范值比较。缺失单元格只能证明空值，
不能证明非空生日/文字/勾选已保存。重试先重新读取并核对目标字段，已符合预期的字段零重写；
未知结果不能直接重发。明确失败也不回滚其他已经核实的字段，不重复建文档或行。

### 1.4.1 设置修复的确认与断点（AG-P0-003，2026-10-04）

设置修复使用当前 `contacts-settings.json` 的严格读取，在同一工作区排他锁内重读；陈旧锚点与字段映射不得覆盖新设置。字段映射修复核对完整结果中的列唯一性，不能抢占未修改字段的列。补建先只读列出缺失字段；确认冻结原锚点、字段映射与缺失列清单，变化后重新预览。每列在内核写入前持久保存稳定 keyID，相关人同时保存稳定回链 keyID；逐步回读列存在、类型及双向关系，再逐列持久更新映射。响应未知先读取原 keyID，不换 ID 重建；明确拒绝且确认未写入时才允许显式重试。派生 `settings-repair-checkpoint.json` schema 1 只服务本工作区补建续做，不迁移；坏断点或读失败保留原文件并停止。

重绑先只读验证笔记本、宿主文档、该文档内数据库块和 AV 标识的一致性，再展示原/新锚点与字段匹配影响；确认后锁内重读设置与目标归属，预览过期零写入。跨笔记本目标必须明确提供 notebookId，不沿用原笔记本猜测。重绑仅切换配置，不移动原文档、不改本人身份或 JSON 人物归属；源资料需保留，目标不可达/多重绑定/字段不明时拒绝。页面卸载后的异步结果不得更新新页面或触发导航。

### 1.5 读取

**文档名称与 Markdown 编码（AG-P0-011，隔离内核 v3.8.6 实证）**：`createDocWithMd.path` 是以 `/` 分隔的文档层级路径，不是 URL；中文、空格、`[]()#`、百分号与反斜杠可按原文作为单段标题。百分号编码不会被解码，而会成为实际标题。`/` 会新建层级，换行会被内核移除；`renameDoc` 同样会删去 `/` 与换行，不能保证这类名称原文保真。因此新建/改名必须在任何写入前拒绝空标题、斜杠和控制字符，错误明确说明支持边界，不静默替换或编码成另一个名字。每段路径独立验证；联系人、vCard、捕获、组织、日记和地点复用该规则。标题正文、链接标签和其他 Markdown 行内文本分别转义；链接目标只接受稳定文档 ID。跟进日期只来自受控任务标记末尾的 `📅YYYY-MM-DD`，非法日期不进入写入，也不从普通文本或中间日期猜测。证据为 `scripts/spike/text-encoding-spike.mjs` 与 `text-encoding-results.json`；真实用户宿主仍待验。

`renameDoc.path` 使用目标文档的实际物理路径；嵌套文档为 `/<父文档 ID>/.../<文档 ID>.sy`。改名须先按稳定文档 ID 从 `blocks.path/box` 核实唯一目标、笔记本和路径，禁止一律拼接根目录 `/<文档 ID>.sy`。本次 spike 已验证嵌套文档的回读物理路径可用于改名；未知路径不写入。

**vCard 建档断点（AG-P0-014）**：每个勾选计划持有稳定请求 ID、目标 notebookId/avId/dbBlockId、原姓名与路径、字段写入计划、文档/行 ID 和建档状态，随逐项报告保留，不属于新的自管 JSON。建档 Markdown 标题块携带 `custom-lvct-vcard="<请求 ID>"`，标记与文档由同一次 createDocWithMd 原子创建；隔离 v3.8.6 实证见 text-encoding-results.json 的 requestMarker。创建响应丢失或返回非法结果记 unknown；按请求标记核实唯一文档并检查笔记本/姓名，未发现或读取失败时禁止再次建档。明确内核拒绝才允许同请求重试。已核实文档的绑定/字段重试复用原 docId，先核实绑定映射再补绑，不重建已存在的行；名册中的同名人物不代替请求目标。改换输入或锚点拒绝复用旧断点；同数据库的导入与重试串行，锁内重新核实。未知结果报告保留请求 ID 和文档 ID，旧 UI 关闭会失去内存断点，重开导入不得凭旧 unknown 自动恢复或宣称完成；真实重启/宿主行为留待验。

- 完整名册及需要全员扫描的功能仍走 `renderAttributeView`（`pageSize: -1`），卡片/表格热路径走已实证的 `page/pageSize` 分页，**数据库没有 SQL 表**（spike ⑧）；`/api/query/sql` 仅用于文档/块/反链查询。
- 单元格遍历：`cells[].value.keyID` 定位字段（不是 `cells[].keyID`）。

### 1.6 初始化锚点扫描

- 初始化找回候选只读查询 `blocks` 文档索引：`type='d' AND box=<严格校验的笔记本 ID>`，固定
  `ORDER BY id`，每页最多 500 行；禁止用 `LIMIT -1` 或单次全量读取。
- 续扫使用当前笔记本的最后一个文档 ID 作为 keyset 游标（`id > afterDocId`），而不是把“第几页”
  当作事实。游标还带笔记本 ID、已扫描数量和扫描快照中的笔记本 ID 列表；笔记本集合变化时必须
  重新开始扫描，避免新增/删除导致静默漏项或重复跳过。
- 扫描响应必须区分 `complete`、`truncated`、`blocked` 三态，并携带页大小、单次文档上限、已扫描
  文档数、候选数和可选总文档数。达到上限只返回可继续的游标，不得把部分结果报告为完整扫描。
- 文档上限是每次调用的新预算，不得扣除游标中的累计数量。`documentsScanned` 为累计成功扫描数，
  `documentsScannedThisCall` 为本轮数，`candidatesFound` 为本轮返回数；设置页累计候选按四锚点去重。
  笔记本按稳定 ID 顺序扫描，顺序变化不代表集合变化。总数仅用于展示；短页/空页才确认本本耗尽。
  扫描不是强一致快照，扫描期间新增或移动到已扫描范围的文档需重新开始扫描核实。
- 文档、宿主文档数据库块或属性视图列读取失败属于未知状态：扫描停在失败前的游标并允许重试；
  不得把未知列降级为零字段，也不得在初始化中据此自动创建/绑定第二套数据库。多候选字段证据并列
  同样只报告歧义，不自动采纳。

## 2. 关系建模

- MVP：`related` relation 字段存边（双向）。目标库配置唯一通道是 transactions 动作
  `updateAttrViewColRelation`（**请求体必须带 `reqId`**，spike ③）。
- 人物文档内"相关人物"双链区块由插件维护（M3），保证反链面板与思源关系图可见。
- 二期：独立"关系库"（行=关系：甲/乙/类型/开始时间），支持类型化与非对称关系，从现有数据一键升级。

### 2.1 关系写入与文档投影一致性

- 关系编辑按 `avID + related keyID` 使用排他锁；锁内必须重新渲染名册，再基于最新 `itemID` 列表做增量添加或删除，不能直接使用详情页旧快照。
- 属性写请求完成后必须重新渲染并核对目标边：添加必须观察到目标 `itemID`，删除必须确认目标已不存在。请求已接受但核对失败属于 `unknown`，不得显示为保存成功，也不得自动重放写请求。
- 关系字段是事实源，人物文档内 `custom-lvct-related` 区块是可重建投影。事实写入成功后，任一文档投影失败不回滚事实；结果必须逐文档报告 `applied/failed/unknown`，并保留文档 ID 作为显式重试键。
- 投影重试先重新读取名册和当前关系事实，再按当前事实幂等更新标记区块；不得用旧快照恢复已删除的关系。跨窗口刷新只失效名册缓存，由下一次读取取得最新事实。
- 人物关系的双向可见性按本库任一端的 `related` 出边确定；对方回链列不另造事实。重复添加已存在的反向边零属性写入；从任一端解除时核对并移除双方显式出边，若中途写入或回读未收敛，保留未知状态并先读后重试。读取缺列、坏 relation 单元格、人物已移除或行文档绑定变化时停止写入。
- 投影保存先读受控标记块，多个标记块属于未知而不自动选择；内容一致零重写。写后经已实证的 `flushTransaction` 和标记块 SQL 回读核对 Markdown，未改变或回读失败不报成功。原生文档手工修改及不遵循插件锁的其他写入不具备原子事务保证。

## 3. 插件自管 JSON

全部键带 `schemaVersion` 包装；读入必须经 normalize（不兼容返回 null 引导重建，**永不抛错阻断启动**）；写入必须写后回读验证（两次不收敛即真失败）。读-改-写走 Web Lock 临界区。

**展示读语义（FUNC-01.12，2026-09-29 细化）**：展示读分两级——**容错读**（键不存在与读取失败均归一为空）与**严格展示读**（键不存在返回空态，读取失败/损坏抛错）。首页仪表盘、人物互动时间线、跟进列表与备份预览、资料体检一律走严格展示读：读故障必须显式呈现——仪表盘聚合到 `DashboardData.readFailures`（指名受影响模块 + 重试，受影响模块以空数据参与投影并明示可能不完整），时间线/跟进列表进入错误态可重试，体检中止并指名失败模块；**不得把读取故障呈现为空数据或正常空态**。首次使用（键不存在）仍为正常空态。写入路径（锁内前置读取）一律严格读，损坏当前库拒绝覆盖。容错读仅保留给模板展示（空存储按设计回退内置默认）与尚未收口的读路径（NEXT-DEVELOPMENT-PLAN P0 余项）。

**本人旧库与迁移（AG-B11-001）**：本人身份仅有 schema 1；旧库缺键/null/空字符串为未建立，坏对象、未知版本、非法文档/行 ID、非法日历日期是读取失败，保留原文件并拒绝写入，不按未建立重建。本人按 selfDocId 识别；文档改名/移动不改身份，selfItemId 是当前数据库绑定索引。名册不能吞掉已装配身份存储的损坏错误；未装配只用于隔离/启动装配前的无身份上下文。保存先校验输入，锁内严格回读当前身份，相同身份零重写；不同 selfDocId 仅显式修复可改绑。默认建本人时同名多候选停止，不取首个；已有身份不在当前名册或绑定行失配，停止续建并给修复指引。

迁移包包含可选 `selfIdentity: {schemaVersion: 1, identity: <本人身份或 null>}`；兼容未包含此模块的旧包。空模块不清除当前本人；不同本人冲突保留当前身份并返回待核对项/重试包，不因同名覆盖。恢复必须先恢复原生文档并重绑数据库，再按稳定 selfDocId 核实名册中的唯一人物及 mapBoundDocIds；源 selfItemId 不直接用于目标库。相同文档的目标行可显式恢复为核实的新行，保留当前 createdAt；写后再次核实目标绑定，不收敛报告 unknown。本人模块读取失败时禁止导出看似完整包；JSON 包仍不含思源原生文档，跨工作区新文档 ID 映射尚需显式选择，不按姓名猜测。

**体检分模块语义（AG-P0-012）**：资料体检固定返回名册、互动、跟进、组织成员和本人身份五个模块。每个模块分别报告 `success`、`failed` 或 `unknown`，并携带 `verified`、`not_found`、`read_failed`、`timed_out`、`bad_json` 或 `unverified` 读取证据。合法空库是 `success + not_found`；权限/读取异常是 `failed + read_failed`；结构损坏是 `failed + bad_json`；超时或依赖未核实是 `unknown`，不得显示为“没有问题”。本人身份没有标记属于已核实的 `not_found`，不把本人计入普通联系人完整度和提醒体检；组织成员对孤儿人物、不可达组织文档和重复历史只读列出。重试接口只读取上次状态为 `failed` 的模块，保留 `unknown` 和已核实模块结果。每项修复先返回目标、影响和 `writes: 0` 的预览，确认入口另行执行，体检本身永远零写入。

读取与检查范围分别核实：模块内容已读取时保留 `verified`/`not_found` 证据；名册或本人身份未核实时，依赖其范围的检查仍为 `unknown`。失败重试仅重读失败模块，用本次和上次成功读取的内存快照重新计算依赖结果，不重复读取成功模块；超时模块不会自动重试，需显式重新核实。完整重新体检可携带上次报告，读取失败时保留旧问题并标为待复核；快照不落插件 JSON，不保证跨模块强一致。名册检查直接回读属性视图并核对字段来源，避免以缓存掩盖故障。原数组兼容入口在任一模块未完成时抛出附带完整报告的异常，不返回正常空数组。修复预览仅定位对象和影响；本卡不执行成员删除、人物合并、身份改绑或任何文档修复，真实宿主持久化与页面入口需另行验收。

**账本和别名的完整读取（AG-P0-015，2026-10-04）**：展示、识别及写前读取共用严格解析；缺键（null/undefined）和宿主约定的空串表示首次空库。其他值必须为版本 1 的对象及正确数组；未知版本、损坏容器、任一非法条目或重复记录 ID 整体拒绝，错误仅提供模块、原始条数、条目序号和原因，不包含金额、正文或别名文本。读取失败不覆盖原文件、不丢弃坏项后继续识别，人物面板显示错误和只读重试，不能同时出现正常空态；捕获在别名索引未知时停止新建和互动写入。合法但跨人物重复的别名文本保留并返回歧义，不能通过归一化选择第一人。泛称和超过长度限制的旧别名条目也须先修复。错误只阻断相关操作，由入口显示并提供重试，不阻断整个插件启动。

**账本创建身份（AG-P0-018，2026-10-04）**：每次新表单生成合法节点格式的 `requestId`，首次保存、失败重试及未知结果核实保持同一键；落盘的记录 `id` 即该请求键，不新增存储版本。创建调用必须携带该键，不以正文、金额或日期推断相同业务。锁内严格重读后查同 ID；已有同人物且创建内容一致的记录直接返回，零重写；同 ID 的人物或内容冲突拒绝，不能覆盖。状态被后续明确更改时保留最新状态，旧创建请求不重开账目。调用保存后的异常标为 `ExchangeWriteUnknownError`，表示可能已保存；面板保留输入和请求键，暂停修改本次输入，点击核实重试先读已存记录，只有确认该 ID 不存在才追加。只有已核实成功或用户明确放弃本次表单并开始新一笔才换键；两个不同请求键即使内容相同也保留两条真实往来。存储读取失败仍停止，不能按“不存在”重发。

不支持 Web Locks 时，按存储键使用进程内 Promise 队列串行执行，同一键按调用顺序排队，
不同键互不阻塞，失败不会阻塞后续任务。此降级仅保护同一 JS 上下文，不保证跨窗口排他；
支持 Web Locks 的环境仍使用宿主浏览器锁，不自动在锁请求失败后绕过保护写入。
取锁带中止信号，单次等待默认 5 秒；只对本次等待定时器触发、且尚未获得锁的请求重排队，
`storeLockConfig.acquireRetryCount` 默认 1（首次等待后再等一次），0 表示一次等待后报错。
等待次数耗尽返回 `StoreLockTimeoutError`（含存储键、单次等待时长和次数），说明本次回调尚未执行，
原操作结果需在其结束后核实，再由用户显式重试。等待超时不能证明持有方已停止，**禁止 steal 接管**：
真实双上下文夹具已复现旧保存暂停超过全部等待后恢复，覆盖接管者已保存的互动记录。
获得锁后立即清除取锁定时器；临界区的慢保存/慢回读继续持锁直到原回调结束，不声称已取消宿主写入。
回调自身的 AbortError、取锁被平台拒绝等异常原样传递，不重跑业务回调，不降级为无锁写入。
两次不收敛的已有写后回读策略不因此改变，不能把持锁中的未知写结果归因于未获得锁。

### 3.5 本人初始化断点（AG-B11-002，2026-10-04）

通用 `saveJsonVerified` 写后使用严格读取。回读请求失败属于未知结果，立即上抛且不自动再次保存；调用方保留稳定请求和原草稿，再次操作先读取核实。只有成功回读且值确定不匹配时，才允许原排他锁内最多一次重写；保存请求本身失败也不自动重发（AG-P0-020）。

`self-identity.json` 严格区分缺键与坏文件/未知版本；后者阻止自动建档。已有身份按原文档与唯一绑定行核实，改名/移动不改变身份，失配须显式修复。旧库无身份时，同名已绑定联系人只有一个才可复用，多候选不自动取第一人。

本人初始化与显式换绑使用同一 `self-profile-init` 排他锁，锁内重读身份和名册。新建前完整分页检查未绑定的「我自己」文档；读取失败或多个候选阻止创建。复用仅绑定原文档，不清空其已有资料。

文档→绑定行→身份分别回读；绑定响应丢失后先核实映射，已绑定不重发。身份回读失败保留断点，下次先严格读身份，已保存则仅核实。本人创建可跳过，失败不阻断工作空间初始化，向导必须显示待续做/设置入口；手动设置页的失败直接呈现原原因，不把未知结果显示为普通空态。无 Web Locks 时仅保证同一上下文串行，真实多窗口留 HOST-002。

  **重试不产生重复块**。真实任务管理器互读 Host pending。
  读侧对账（人物详情打开时）以文档为准单向收敛插件库，不回写文档。

- **AG-P0-008 全量与报告**：同步与对账读取该人物的全部历史索引（含第六条及更早的 done/cancelled），
  不使用仅展示最近五条关闭事项的列表。文档按已实证 SQL `ORDER BY id LIMIT 200`、`id > 游标`
  分页，先 `flushTransaction`；读失败、坏行、重复关联键不得当作空任务或删除。
  报告逐项带 `personDocId/followUpId/blockId/action/changes`，分别给出索引
  `verified/failed/unknown` 与文档 `verified/missing/not_created/pending/failed/unknown`。
  缺日期、非法日期、未知勾选标记保留旧索引并报告 unknown；取消记录不因文档取消勾选复活。
- **可选重试字段与兼容**：schemaVersion 仍为 1，事项新增可选 `docSyncPending: boolean`、
  `docSyncBlockId: string`。旧记录缺字段即无待写意图；新字段类型错误严格读取拒绝覆盖。
  插件显式变更在同一存储锁内保存索引及 pending；文档写前保存 pending 和目标任务项 ID，
  写后回读核实勾选、标题、日期及关联键，再清 pending 并记录 `docBlockId`。
  pending 保留到文档和索引均核实，读侧不得用旧文档覆盖失败写入的意图。
  重试可限定失败事项及 index/document 模块；index 重试不重复文档写入。
  写后读取失败为 unknown，已接受但值未生效为 failed；索引失败不能标整项一致。
- **原子关联键写入（v3.8.6 隔离实证，2026-10-04）**：`insertBlock` 返回的是列表容器 ID，
  缩进 Markdown IAL 挂在子段落；普通 Markdown `updateBlock` 会丢掉任务项关联键。
  因此插入使用 `dataType:"dom"`，一次携带有独立 ID 的 `NodeList/NodeListItem/NodeParagraph`，
  `custom-lvct-followup` 直接放在 `NodeListItem`；标题和属性值作 HTML 转义。
  改标题/日期用 `updateBlock {id:任务项ID,dataType:"dom",data:NodeListItem DOM}` 同时保留关联键；
  勾选仍用已验证官方 marker 端点。删除和改写均回读任务项，未知结果不补造第二个任务。
  证据见 `scripts/spike/task-item-results.json` ⑤～⑤c；真实任务管理器、用户工作区和宿主呈现仍由 AG-HOST-003 验收。

同一场合允许每位参与者各有一条互动事件；`source+externalRef` 表示共同场合，
只有人物 ID 也相同时才判定重复。事件 ID 在全库唯一，归一化同时按事件 ID 去重。
此修正保留 schemaVersion 1，不改变存储结构；旧版本已经跳过或丢弃的参与者事件无法自动恢复。

互动事件的展示读取可容错降级；新增与删除必须在锁内严格读取，宿主读取抛错时终止操作，
不得把读取异常当成空库保存。null/undefined 或空字符串允许首次写入：思源 v3.8.5
宿主 `Plugin.loadData` 的未创建文件默认值为 `""`（本机 stage/build/app/common 构建实证）。
非空数据必须具有兼容版本、事件数组与墓碑数组，且各项类型合法；否则新增与删除均报错，
不自动将未知版本或损坏内容归一为空库覆盖。展示读取仍可过滤损坏项，正常去重与墓碑投影不受影响。

人物详情支持分批浏览、备注/日期搜索及来源筛选；单条删除经过确认，按人物 ID 校验事件归属后在锁内写墓碑。
仅移除当前人物的该条互动，不删除人物文档、来源笔记或其他参与者事件；时间线、共同出席及首页统计重新投影。

同场统计仅使用非空 externalRef，与 source 一起表示场合身份；缺少标识不与字面值 `"undefined"` 的场合关联。
同场人数按不同人物计数，每位人物在同一来源/场合中最多贡献一次共同出席；重复事实不放大人数或次数。
时间线按场合索引计算人数，不对每条本人事件重复扫描全库；本人时间线日期排序保持不变。

设置页的「导出互动事件 JSON」生成一次性导出包：
`{schemaVersion: 1, exportedAt, storageKey, rawStore, events, tombstones}`。导出包不回写插件存储，
`events` 与 `tombstones` 保留当前归一化后的审计事实；新增 `rawStore` 保存宿主读取的原始 JSON 值，
不丢弃损坏项、重复项、墓碑或未知版本，`storageKey` 标明源文件。
这是 JSON 值快照而非源文件字节备份；数据在同一排他锁内读取，读取异常时导出失败，禁止生成空成功备份。
首次未创建文件的 null 或空字符串也原样保留在 `rawStore` 中。schemaVersion 保持 1，原有字段继续可用。

设置页支持预览并合并互动 JSON 备份，不覆盖整个库、不新建联系人文档。
接受 schemaVersion 1 的事件库、旧版导出包及带 rawStore 的新版包；新版优先严格检查 rawStore，
拒绝损坏快照或未知版本，不用已过滤的 events 偷换原数据。空快照表示空导入。
合并以当前库优先，按事件 ID 或人物+来源+场合去重；合并双方墓碑，删除标记优先，禁止复活。
合并计算复用基于 Set/Map 的批量归一化，当前事件排在备份前面，避免逐条扫描和复制整个库；
按当前及备份事件总量线性处理，存储读取、JSON 解析与保存开销另计。
预览不写入；确认后在同一存储锁内重新读取、合并、写后回读验证，返回实际新增/跳过/移除/新增墓碑数量。
当前库存储损坏或读取失败时拒绝导入；包含删除标记的备份须在确认中明确说明会移除对应互动。

### 3.4 偏好并发契约（AG-P0-009）

`view-preferences.json` 仍为 schemaVersion 1；新增单调递增的 `revision`，旧文件缺失时按 0 读取，
仅存储键不存在（null 或空字符串）才使用默认偏好。读取异常、非对象、未知 schemaVersion、
非法 revision 必须上抛，页面保留最后一次已核实值并显示读取失败，不把未知状态当成默认值。

保存携带提交快照及其编辑基线，只提交相对基线发生变化的字段；数组字段整体替换。
同实例按提交顺序排队，在 `withStoreLock` 内严格重读最新文件、合并字段差异并增加 revision，
再经 `saveJsonVerified` 写后回读。无差异不写入；不同窗口修改不同字段互不覆盖，
同一字段以锁内最后成功提交为准。重置默认也以当前编辑基线计算差异，不重置 revision。
读取失败或坏文件零写入；已提交但回读失败属于未知结果，保留草稿，先重新读取核实再显式重试。

偏好保存确认后发布含 revision 的窗口内事件；宿主 `onDataChanged` 先使在途读取失效，
防抖后严格重读并广播已核实 revision。通知只用于失效，不携带可直接覆盖界面的偏好快照。
每个插件/工作台实例使用请求代次，只允许仍存活的最新请求更新缓存和页面；旧错误也不得覆盖新结果。
设置页在刷新时合并未保存字段，保存期间新增编辑保留为草稿，不被旧提交响应清空。
卸载/销毁时取消订阅、清除刷新及启动定时器、废弃在途响应；不声称撤销已发出的宿主写入。
真实多窗口事件投递和宿主读取缓存一致性仍需真实思源验收；无 Web Locks 时仅保证同进程串行。

## 4. 性能预算（随人数增长的读取策略）

联系人列表的“最近互动”列与排序从当前 `interaction-events.json` 一次读取投影：按文档 ID 取最大 `occurredAt`，相同时按姓名稳定排序；没有事件的联系人排在末尾。该读取不修改事件库、墓碑或 schema，读取失败须显示错误，不把失败伪装成“无互动”。视图偏好 `peopleSort` 可取 `recent`，旧偏好保持兼容。

> 设计目标：百人秒开、千人流畅、万级可用。核心原则——**全量渲染只有一条路径（名册缓存），
> 列表热路径禁止 `pageSize: -1`**。

| 场景 | 策略 | 复杂度 |
|---|---|---|
| 联系人列表（卡片/表格） | `renderViewPage` 分页（200/页）+ 首屏先展示 + 后台逐页追加；完整名册核实前禁用“选择全部筛选” | 首屏 O(页)，完整读取 O(总人数/页) |
| 组织卡片列表 | 组织标记按 `root_id` keyset 分页（200/页）+ 文档 ID 批量回读；重复标记、空页矛盾或游标缺失停止续读 | 首屏 O(页)，组织文档读取 O(组织数/页) |
| 搜索/分组筛选 | 纯客户端（名册上字符串过滤，万级 <1ms） | 0 内核调用 |
| 仪表盘（生日/久未联系/统计） | 名册缓存 + 互动事件本地投影 | 0 额外内核调用 |
| 关系图谱 | 名册缓存 + `capGraph` 800 节点上限（按度数保留，UI 明示截断） | 0 额外内核调用 |
| 详情关系候选 | 名册缓存 | 0 额外内核调用 |
| 新建防重 | 名册（写后失效重建） | 与名册共享 |
| 收编候选发现 | SQL 按 `box=笔记本ID LIMIT 500`（ID 严格校验，见下）+ 批量绑定（200/批） | 常数次调用 |

- **名册缓存**（`services/roster.ts` + `domain/roster.ts`）：供图谱、仪表盘、关系候选和写入核实的完整名册进程内复用，可随时重建，不是事实源；
  所有 services 层写操作（新建/收编/关系变更）立即 `invalidateRoster()`。联系人卡片/表格首屏不等待该缓存，改走 `services/contacts.ts#listContactPage` 的已核实 AV 分页；后台追加期间显示已加载/总数，停止或失败后不得把部分名册当完整。
  完整缓存身份包含 avId、dbBlockId 与字段映射；同配置并发查询合并，TTL 从完成查询时计算。失效前或被新配置替代的在途查询只返回原调用方，不回填共享缓存；失败后允许直接重试。
  多窗口下他人对数据库的写入最多滞后一个 TTL（30s）；分页列表的当前读取仍以页请求返回的 `rowCount` 和行 ID 为核实依据。
- **写放大控制**：收编 500 篇 = 1 次批量映射 + 3 次批量绑定（200/批），而非 1500 次逐个调用。
- **SQL 安全约束**：`/api/query/sql` 只有 stmt 字符串参数、不支持绑定占位符（内核 API 层限制）。
  因此约定：业务 SQL 组装只允许出现在已审查的查询服务（当前包括 `services/contacts.ts#discoverImportCandidates`、组织分页服务与 `services/org.ts` 的组织扫描/标记统计），
  进入语句的外部值仅限"通过 `^\d{14}-[0-9a-z]{7}$` 校验的思源 ID"或本插件常量（custom-* 属性名），自由文本（关键字）不进 SQL、客户端过滤。（D-12 口径校准：组织扫描落地后本节与现状同步。）
- **互动事件存储**：单文件 JSON 到 ~2 万条事件仍可流畅；此后需做分段/压缩（ROADMAP"大规模演进"）。

## 6. 端点行为备忘（v3.8.5 实测与文档的差异）

- **请求边界纪律（CODE-02.6）**：所有内核请求经 `kernelPost` 有界等待（`kernelConfig.timeoutMs`，
  默认 15s）——宿主挂起时抛 `AsyncTimeoutError`，调用方传入已取消的 `AbortSignal` 或主动取消时抛
  `AsyncAbortError`；**不自动重试**（写入类重试会产生重复块/重复文档，重试由用户在界面显式发起）。
  思源 `fetchPost` 无中止能力，因此取消/超时只停止等待，不能撤销已经发给内核的请求。协议异常形状
  必须上抛、不得归一为空：响应信封非法抛 `KernelProtocolError`，401/403 或明确权限消息抛
  `KernelPermissionError`，其他非零 code 抛 `KernelResponseError`，回调失败或同步抛错抛
  `KernelTransportError`；`querySql` 非数组、`lsNotebooks` 缺 notebooks、
  `getAttributeViewItemIDsByBoundIDs` 非映射对象均属于协议异常（读故障显式化，防止「异常=空名册/空库」）。
  空数组、空字符串、`null`/`undefined` 只有在该端点契约允许时才是合法空结果，不得用 `?? []` 或
  `?? {}` 掩盖解码失败；属性写入端点允许成功信封携带空 `data`，但若携带对象则仍必须符合已知形状。
- `addAttributeViewKey`：`keyIcon` **必填**（文档称可选）。
- `/api/transactions`：请求体顶层必须带 `reqId`。
- `appendAttributeViewDetachedBlocksWithValues`：`blocksValues` 是**数组的数组**（每行直接是值数组），无 id 包装。
- `createNotebook` 返回值不保证是 ID：创建后重新列表获取；`refreshNotebooks` 端点在 3.8.5 **不存在**。
- **块属性存储**：自定义属性存于 `blocks.ial` 列（kramdown IAL 文本，形如 `custom-x="1"`），
  旧 `attributes` 表已弃用；按属性查块用 `ial LIKE '%<attr>="%'`。
- **IAL 语法**：markdown 中 IAL 必须**独占一行**跟在块后（`内容\n{: custom-x="1"}`）；
  写在行尾不会被解析为属性、原样留在正文（scripts/spike/ial-probe.mjs 实证）。
- 数据库**没有 SQL 表**：`av_table.go` 系渲染逻辑；数据库读取一律 `renderAttributeView`。
- **`renderAttributeView` 的 `createIfNotExist` 语义**（v0.2.0 首启实故的根因）：
  全新数据库块上传 `false` 以 `code=-1 attribute view not found` 失败，传 `true` 才物化
  （默认视图 + 主键列）；物化后两种取值都能读，且重复传 `true` 幂等。
- **`insertBlock` 的 `data` 是事务结果数组** `[{doOperations:[…]}]`（dom 与 markdown 两种
  dataType 实测一致）：新块 ID 取 `data[0].doOperations[0].id`；按对象读会取不到 ID
  （v0.2.0 首启在建库一步抛“未返回新块 ID”的原因）。
- **`createNotebook` 重名不报错**：返回 `code=0` 并静默创建第二个同名笔记本——
  重名保护必须由客户端预检完成（`listNotebooks` 比对）。
- **`addAttributeViewKey` 重名列不报错**：返回 `code=0` 并叠出同名列——续建初始化必须先按
  列名/类型对账，只补缺失列，否则会把库配出两套同名列。
- **数据库锚点还原通道**：数据库块的 `blocks.markdown` 列含 `data-av-id`（块 IAL 里没有），
  按 `parent_id = '<宿主文档ID>' AND type = 'av'` 查块即可还原 `dbBlockId` 与 `avId`；
  这是初始化续建（D-0019）与“找回半成品现场”的唯一可靠通道，实证见
  `scripts/spike/init-resume-results.json`。
## 7. vCard (.vcf) 导入导出映射（v0.2d）

vCard 处理是**瞬态转换**（不落插件存储），但属性↔字段映射是数据边界契约，事实源在
`src/domain/vcard.ts`。以 vCard 3.0 为主，兼容读取 4.0 日期形式。

| vCard 属性 | 插件字段 | 语义 |
|---|---|---|
| `FN`（回退 `N`） | 姓名（主键列 + 文档标题） | 无 FN 用 N 的"姓+名"连写；两者皆无则丢弃该卡片 |
| `TEL`（多个） | 电话 | 全部保留，`" / "` 连接写入单值文本字段（去重保序） |
| `EMAIL`（多个） | 邮箱 | 只取首个（邮箱有格式校验，不做多值拼接） |
| `URL`（多个） | 网站 | 只取首个 |
| `BDAY` | 生日（公历） | 只接受完整年月日（`19900520` / `1990-05-20` / 带 `T` 时间后缀）；无年份（`--0520`）与文本形式丢弃 |
| `X-LVCT-BDAY-LUNAR` | 生日 + 农历勾选 | 本插件导出农历生日的回写属性；导入时仅当 BDAY 缺失才读它 |
| `CATEGORIES` | 标签 | 逗号切分，空项丢弃 |
| 其余（`ORG`/`ADR`/`NOTE`/`PHOTO`/`UID`/`REV`…） | — | 忽略；`ORG` 留给二期组织维度，`PHOTO` 留待头像需求 |

- 导出为 vCard 3.0（CRLF 行尾、不做 75 字节折行——D-0013）；**微信号不导出**（无标准属性，X- 扩展互通性为零）。
- 导入查重：与名册精确同名（或同批次在前项同名）默认跳过；UI 显示稳定候选，用户逐项勾选可明确作为独立人物导入（D-0031 修订 D-0007），不按姓名合并或补写。
- 导入预览逐卡显示字段边界：FN/N、TEL、EMAIL、URL、BDAY、CATEGORIES 和本插件农历扩展进入映射；ORG/ADR/NOTE/PHOTO 等未支持属性只列为“已忽略”并零写入；可识别但日期格式不受支持的属性列为“需人工核对”，不猜测改写。
- 导入批量路径写放大与收编同款：逐篇建文档（内核单文档语义）→ 绑行 200/批 → 一次批量映射 → 逐人写单元格。
- 支持 QP（QUOTED-PRINTABLE）编码值解码（UTF-8/GBK 字符集，含无空格续行的软换行变体）。

## 8. 组织建模（B13.1 设计定稿，基于 B13.1a 隔离内核实证）

**实证结论（scripts/spike/b13-org-spike.mjs，v3.8.6 隔离内核，2026-09-30）**：

- **跨库 relation 不被支持**：人员库 relation 单元格写入组织库行 itemID，`setAttributeViewBlockAttr`
  直接拒绝（code=-1）；`/api/transactions updateAttrViewColRelation` 跨 avID 配置"双向"虽然返回
  code=0，但配置后人员库 relation 键的 `key.relation` 定义**丢失**（getAttributeView 读回 undefined）
  ——属破坏性操作，组织建模**禁止使用跨库 relation**。
- **detached 行不渲染**：`addAttributeViewBlocks isDetached:true` 提交后 `renderAttributeView`
  不返回该行——无文档的组织条目不能依赖 AV 行呈现。
- 同库 relation（此前相关人已实证）不受影响；组织与联系人若同库混行会污染名册投影（名册渲染全部行）。

**设计定稿（选项收窄后采用"组织文档 + 标记区块 + 插件 JSON 成员索引"）**：

- **组织** = 一篇思源文档（标题即组织名，支持改名）+ 文档内 `custom-lvct-org` 标记区块（形态与
  人物档案条一致：组织类型/部门数/成员数徽标 + 简要信息）。组织不进入联系人数据库——不与人员
  混行、不占用 fieldMap；组织列表 = 标记区块扫描（与 FUNC-01.8 锚点扫描同模式，支持续建找回）。
- **成员关系** = 插件 JSON `org-membership.json`（新键，schemaVersion 1）：`{memberships:
  [{id, orgDocId, personDocId, department?, title?, joinedOn?, leftOn?, status: active|former, affiliationKind?: work|education|unspecified}]}`——
  多人多组织多对多、同组织多段历史（以 membership id 区分）、离职/毕业置 former 不删除；
  id/personDocId/orgDocId 均须通过 ID 校验。严格展示、写入与迁移读取遇到非法条目、重复记录 ID、未知分类整体报损坏，不丢项后覆盖；宽松归一仅用于显式诊断。
- **B13.4 成员字段编辑（第 72 轮，2026-09-30）**：`updateOrgMembership(id, patch)` 锁内严格读 +
  写后回读；patch 只含白名单字段（department/title/joinedOn/leftOn/status/affiliationKind），**身份字段
  （id/orgDocId/personDocId）不可变**；日期必须为空串或 YYYY-MM-DD，非法写前拒绝（绝不静默改写）。
- **成员替换**：`replaceOrgMembership(formerId, successor)` 在同一次锁内把 active 旧成员写为
  `former + leftOn`，并追加同组织的 active 新成员；任一步校验失败都不写入，防止组织出现“旧人已离职但新人未登记”的中间状态。
- **B13 组织归档语义（第 72 轮，2026-09-30）**：标记区块值 `custom-lvct-org="archived"` 表示归档
  （活跃值为 `"1"`；AG-B13-001 收紧展示读取：其他值保留原文并报告未知，不再投影为活跃）。归档 = 重写标记块 IAL 值（文档与成员记录保留，
  可恢复）；归档组织不进关系图组织增强、不参与 B12 单位行投影，但成员记录仍可核对；
  新建组织同名检查含已归档组织（文档还在）。标记块为插件管理区块，归档/恢复重写为标准文案。
- **组织健康读取（AG-B13-001）**：标记扫描按文档和 IAL 分组并报告块数；重复标记、未知属性值、非法根 ID、不可达文档或不完整文档行都阻断完整列表结论，错误含待核对目标，不按空组织处理。合法无标记才为空列表。归档/恢复在组织专用锁内回读当前事实，写后再次扫描核对目标状态；回读失败不得宣称完成。不自动删除重复标记或把未知值迁移为活跃，人工修复保留原文。活跃单位投影先排除归档组织，再选择成员记录，避免被归档的首条成员遮蔽另一个正常组织。
- **共同背景查询**（同单位/同学校同事）= 成员索引 JSON 查询投影，不经 AV relation；
  "与我的关系"等既有 related 语义保持纯人物间语义，组织维度不写入 related。
  **B13.5b 查询口径（第 82 轮）**：`buildCommonOrgBackground` 一次遍历建「组织→成员」索引后按
  组织直取候选、同伴 Set 去重（不做全索引逐段扫描与线性查重）；输出语义=全量扫描等价
  （同伴顺序按索引首现序、每同伴收录一次取最早交集、无名同伴不进背景、组织顺序随本人归属记录）；
  大名册夹具 3000 同伴零重复零丢失有单测。成员长表分页/虚拟化归 H-04/H-06 通道。
- **捕获/搜索**：组织文档不出现在联系人名册与选人器；组织名搜索走标记区块扫描（后续增强）。

**B13.7 人物—组织双链区块（第一批，2026-10-01）**：人物文档内**单个**带
`custom-lvct-org-links` 属性的段落块（与 related 区块同构，幂等更新），内容 =
`**所属组织**：[组织名](siyuan://blocks/<orgDocId>)（部门 · 职位）、…`。口径为
**active 成员 × 活跃组织**（与单位行投影一致；former/归档组织不上文档——历史事实在
`org-membership.json` 与共同背景，文档区块只做「当前档案导航」；siyuan://blocks 链接使
组织文档获得原生反链，成员名单由反链面板/原生图自然承载，组织侧不写区块）。
变更挂接：成员添加/移除/字段更新、组织归档/恢复/改名后对受影响人物逐文档对账
（`refreshPersonOrgLinkSections`，单文档失败不阻断、失败仅告警、可由对该人物的下一次
组织操作补同步）；组织改名同步链接文本（链接目标 orgDocId 不变）。仅操作插件标记区块，
不触碰用户正文。

**迁移与兼容**：不迁移任何既有数据；`org-membership.json` 为全新键，旧版本工作空间升级后为空。

### 8.1 工作单位、学校与相对本人称谓（AG-B12-001）

本节先定义契约和纯函数，数据编辑与页面接入由 B12-002/B13-003 实现；不能据此宣称已支持界面编辑或导入。

| 资料 | 唯一事实源 | 展示/清空/旧库语义 |
|---|---|---|
| 工作单位 | `org-membership.json` 中 `affiliationKind=work` 的成员记录，组织标题来自组织文档 | 多条 active 均保留；former 与归档组织单列历史；改为 unspecified 只清分类，保留记录、日期和职位；不写人物 AV |
| 学校 | 同一成员索引中 `affiliationKind=education` 的记录 | 毕业用 former，未知日期保留空；同一大学可分别是不同人的工作单位或学校；不由组织名推断 |
| 未分类组织 | 缺 affiliationKind 或显式 unspecified 的成员记录 | schema 1 向后兼容，旧记录不猜成工作/学校；部门、职位、日期、历史照常保留；工作/学校查询不混入未分类记录 |
| 与我的关系 | 预留 `person-relationship-labels.json` schema 1：`{labels:[{id,selfDocId,personDocId,labels:string[],createdAt,updatedAt}]}` | 人工多值称谓，以本人文档 + 人物文档为唯一组合，不写 related、组织成员或别名；空数组表示显式清空，同一组合只一条；缺键为空，损坏/重复不当空 |

组织文档不携带工作/学校分类：这是人与组织之间的归属事实。投影保留 membership ID、组织 ID、职位/部门/时间和分类，不能按姓名去重或只选一条覆盖其他任职。不可达组织保留原 ID 并标未知；完整组织扫描失败时调用方保持整项未知，不用空 map 宣称“未填写”。档案条是可重建投影，不是第二事实源。成员替换只继承部门/职位等显式选择，不自动将旧人的工作/学校分类赋给新的人。

称谓解析严格验证三种稳定 ID、非负安全时间戳、updatedAt ≥ createdAt、非本人对自己的称谓、1–80 字符非空标签、最多 20 个去重标签。清空保留该组合的记录与时间戳，方便后续迁移比较。更换或清除本人后，旧称谓保留在原 selfDocId 下；新本人只看到其自身参照的称谓，不能自动搬移、颠倒或推断。未知本人身份时暂停相对称谓查询；已明确没有本人时显示“未指定本人”。共同组织背景与相关人均不能自动生成“同事/同学/朋友”等称谓。

已有 AV 的分组/标签/相关人、用户自建同名列以及 vCard ORG 不迁移为三项事实，不按列名或组织名隐式收编。分类沿用 schema 1 的可选字段；旧包缺字段保持未分类，新包非法分类在预览拒绝。

AG-B12-002 启用称谓键时采用本人锁→称谓锁的顺序。编辑须提交预览时的 selfDocId 及原组合记录快照，锁内核实当前本人、双方名册唯一绑定和原内容；换绑、解绑或并发编辑均拒绝覆盖。清空保存 labels=[]，不删除组合记录，旧备份不能恢复清空前的值；重复同值零写，保存后回读，结果未知先重读核实而不另建记录。

迁移包增加可选 relationshipLabels 模块，schema 1 原样保留组合 ID、双方 ID、时间和空值。只恢复当前本人参照且双方已唯一绑定的新增组合；其他本人历史逐项保留在待核实包，不自动换绑或转移。同 ID 或同组合不同内容保留当前值并报告冲突，未知写后回读可单模块核实重试。旧包缺模块兼容。已留在本地的旧本人历史继续保存，换回原本人重新投影。

联系人列表、首页、人物、卡片/表格及简报共用成员分类与称谓的派生快照；组织归属区分当前、历史、归档和不可达，不以旧单位字符串作事实源。每个子来源分别有 known/unknown，读取失败不显示为未填写，称谓另区分未建本人/本人自身。筛选只匹配已核实当前分类与当前本人称谓，未知不当空；保存视图可选 workQuery/educationQuery/relationshipLabel 只保存规则，旧缺字段无该限制。表格可选 school/relationship 列为投影，不写 AV。刷新重新求值，保留筛选及编辑草稿。

AG-UX-003 批量维护须先固定 itemId+docId、字段原值及锚点快照。当前页/全部筛选/手动选中为明确范围，筛选变化不暗改已确认队列；筛选外对象必须再次确认，取消零写。批量写前重新渲染核实每个原绑定，解绑或行换人则逐项未发送；分组并发变更与目标不一致时保留当前值。追加标签基于本次写前最新值求并集，不用旧列表回退他人新增。字段失败/未知保留原目标和原操作，重试先核实，只补未完成字段。

### 8.2 组织成员双链投影与手动补偿（AG-B13-006）

`org-membership.json` 仍为唯一成员事实，组织/人物文档只维护可重建的独立标记段落：组织文档 `custom-lvct-members="1"` 列出当前已登记人物成员，人物文档 `custom-lvct-orgs="1"` 列出当前未归档的组织归属。链接目标只用原文档 ID；部门、职位、期间和成员分类来自原成员记录，多记录保留。former 不生成当前投影，归档组织不生成当前成员投影，并从人物的当前归属段落移除；历史事实继续保留在 JSON 与详情。投影不写 related，不修改组织身份标记、AV 列或用户正文。

核对为只读：严格读取完整组织标记、成员索引和当前名册，生成事实快照与逐文档预览，分别显示一致、缺失、不同、未知。即使成员为空，已登记人物和组织也核对原投影，以便清理旧插件段落。活跃成员的组织失联、人物不在名册、重复人物文档绑定或来源读取失败时相关目标保持未知，不省略后宣称完整或写空。已归档、历史成员不作为活跃目标推断。

修复需明确选中预览中的目标，在成员存储锁内重新读取事实和标记，确认来源快照及原块快照仍一致，过期则要求重新预览。只处理 custom-lvct-members/custom-lvct-orgs 段落；重复标记、读取失败或不可达不自动删除/选首条。写后回读段落并再次核实事实来源，应用了写入但响应丢失可由原内容只读核实；未知不能自动追加第二块。已写 JSON 成员事实不因投影失败回滚，修复不增删成员。报告保留目标 docId、类型、状态和稳定重试键；请求键不包含姓名、电话或正文。跨 store/内核不是原子事务，来源在写入期间变化时明确标未知并重新核对，不能宣称已同步。

修复请求经 `org-projection-checkpoints.json` schema 1 持久核实：`{operations:[{id,docId,attrName,markdown,state: pending|rejected|verified,updatedAt}]}`，每个文档+投影属性仅保留最新一条，三个 ID/属性/时间与状态严格验证。写内核前保存 pending 并回读；未核实 pending 的预期内容前不发送另一条更新/追加/删除，即使重新打开设置或重新预览也如此。只在原预期内容已读到或明确内核拒绝后允许下一次修复；相应 verified/rejected 写后回读。checkpoint 只用于本工作区操作续做，不属于业务备份，不迁移到其他库；损坏/未知停止修复，保留原文件。写前 checkpoint 回读未知时本次内核请求尚未发出，仍需核实本地断点，不能宣称文档修复完成。

AG-B13-006 先提供共用核对/修复服务与设置入口；成员保存后自动报告和双方影响预览由 AG-B13-003 接入。组织创建/改名残留修复使用同一事实与投影边界，但其请求断点另由 AG-B13-001 完成。核对不宣称组织或成员原生文档已由迁移包备份。

### 8.3 成员维护的校验、历史与结果报告（AG-B13-003）

同一 orgDocId/personDocId 只允许一条 active；锁内添加发现已有 active 时返回原记录和原 ID，不追加，不静默覆盖其分类/职位。former 后再次加入创建新的成员 ID，保留旧期间；恢复原 former 是明确编辑 status=active 且 leftOn 为空，若已有其他 active 则拒绝。删除记录是明确确认的事实纠正，删除该段历史，正常离职应编辑为 former。接替一次 JSON 写入关闭原 active 并登记新人物，不继承未明确填写的成员分类。

写前验证稳定 ID、分类、真实日历日期（空串仍表示未知）、加入不晚于离开以及 active 不含离开日期；非法输入、重复 active 恢复与坏当前库零写入。不把内核 itemID 当文档 ID。新增或恢复 active 前严格核实目标组织未归档、人物唯一绑定当前名册；组织和人物参数顺序由公共入口固定，不按名称推断。

编辑、删除确认和接替保存携带原成员记录快照，在同一成员锁内规范化比较身份、分类、部门、职位、期间和状态。记录已变化则零写入，保留本地草稿并提示重新读取核对；不能把“保留草稿”当成可覆盖新事实的授权。旧服务调用未传快照时，公共服务采用其写前读取的原记录，同样防止核实身份期间发生的并发变化。

成员事实经锁内重读和写后回读成功后，按稳定 ID 核对受影响组织与人物段落，复用 §8.2 持久请求和逐文档结果。事实与投影分别报告：事实已保存，段落 applied/unchanged/failed/unknown；投影失败保留事实和目标，设置页可只补段落，不再次新增成员。成员事实保存未核实时不发文档请求、不宣称完成，保留表单并先重新读取事实。服务完成时发布生命周期内失效事件，两侧只重读已核实来源；卸载后迟到结果不更新界面。真实宿主多窗口一致性另验。

### 8.4 组织成员备份与现状优先恢复（AG-B13-005）

迁移包 schema 1 包含可选 `modules.orgMemberships`，内容为原 `org-membership.json` schema 1，含所有 active/former、多段历史、分类和稳定 ID。早期包缺该模块时保持兼容。导出严格读取，损坏或未知不输出伪空备份。组织原文档、标题、归档属性属于思源原生事实，须另随工作区备份；本模块不创建/改名/解档组织、不按同名映射、也不修改数据库锚点。

成员库增加可选 `tombstones: string[]`，旧缺字段等同空删除集合。明确删除一段成员历史时，在同一锁及一次 JSON 保存中移除记录并登记其原 ID；离职不登记删除标记。标记必须为合法稳定 ID，坏类型/重复标记/与当前记录冲突整体拒绝，不能过滤后覆盖。恢复时删除标记并集合优先，旧包不能复活该 ID；再次加入生成新 ID，原历史保留。删除标记亦随成员模块备份和预览计数。

保存回读未知保留未完成模块包，重试先核实已存在记录和删除标记，已成功项不重复。只恢复 JSON 成员事实，不重放文档投影操作断点；恢复后从设置只读核对并逐文档重建当前双链。归档组织不生成当前投影，历史不丢；插件包不宣称已包含思源原生文档备份。偏好、锚点及本工作区投影断点继续排除。

### 8.5 组织创建、改名持久断点与只读续做（AG-B13-001）

`organization-operations.json` schema 1：`{schemaVersion:1,operations:[...]}`。操作包含稳定 `requestId`、`kind:create|rename`、原 `notebookId/name`、已核实 `docId`（未创建为空）、`createdAt/updatedAt`，以及逐步 `create/title/marker` 状态 `unissued|pending|rejected|verified`。改名另保存原标题、物理路径、唯一标记块 ID/原 Markdown/原归档值和目标 Markdown；身份与原快照不可变。读取严格校验所有字段、重复请求、时间与状态组合，损坏或读取失败整体停止，不覆盖为新空库。全部 JSON 经 storage.ts 锁、规范化和写后回读；本工作区操作记录排除业务迁移备份，不能带到另一工作区重放。

创建先生成请求 ID，以笔记本和规范名称为锚点；在全局 `organization-create` 锁内核实已有组织（含归档）及未完成同名请求。同名仅防止误建，绝不据此对应旧请求身份。内核发送前持久保存 `pending` 并回读，创建 Markdown 的独立组织段落同一 IAL 同时携带 `custom-lvct-org-draft="<requestId>"` 与 `custom-lvct-org="1"`，由同一次 createDocWithMd 原子创建。该双属性形状须先由独立 UUID 工作区、随机端口的隔离内核 spike 验证再上线；实证记录单列，真实 Host 待验。只读续做按原请求标记查唯一块/根文档并核实原笔记本、组织唯一标记和名称，不按同名猜 ID。未知、响应丢失、未找到、重复或读取失败只核实、不重发；明确内核拒绝才可用原请求重试。原请求成功后 UI 按返回 docId 选中。已核实文档的后续改名不改变创建身份。

改名与归档共用 `organization-state-<docId>` 锁。锁内重新读取原标题、真实物理路径、唯一标记块原 Markdown 与归档值，先持久原快照再分步发送 title 和 marker；每步发送前保存 pending，发送后重新读事实，只有目标值已核实才记 verified。只补 unissued 或明确 rejected 步骤，pending 即使事实暂仍为旧值也不能自动重发。跨重启读取未完成操作，默认仅只读核实；明确点击补做才执行安全未发/拒绝步骤。创建 pending 不阻止只读列表，也不自动成为新请求。

## 9. 图查询快照（AG-B14-001/003/004）

本节是当前图查询入口的口径，替代上文 B14 历史实现中的仅人物引用白名单、人物裁剪后另叠组织、失效中心自动回退等展示规则；不修改组织、成员、本人或 related 的存储事实。所有查询只读，仅使用已实证的 getGraph/getLocalGraph 及现有名册、组织和身份读取入口，不新增内核参数或原生面板打开方式。

### 9.1 数据源与边

一次来源读取分别核实名册、组织成员与本人身份，记录各自 verified/unknown 和错误。登记集合为唯一绑定的人物文档与健康未归档组织文档；本人必须在名册中唯一绑定才可作为中心，不额外重复计数。重复人物 docId/itemId、人物与组织身份冲突、悬空成员、重复组织 ID 均有诊断；歧义目标不进入查询，不按姓名合并。组织或本人读失败允许展示已核实的人物关系，但标明未核实范围；依赖该来源的范围停止，不归一为空组织或空本人。

related 仅来自 AV 显式人物关系；member 仅来自成员 JSON 的 active 记录与健康未归档组织的 join，同组织同人多段合为一条展示边；ref 仅来自已核实内核图的文档块引用。边的 kind 必须明确，不由成员或引用推断 related。直接、二度、共同联系人和关系最短路径只消费 related 子图；引用图只展示 ref。无向展示去重按 kind 与两端稳定 ID，不合并不同来源的边，不推断关系强弱或引荐意愿。

### 9.2 范围、中心与组织聚焦

关系图支持 global（登记集合）、self/person（中心及显式 related 的一度或二度）、org（组织与其 active 登记成员）。引用图的 global 使用 getGraph 后过滤登记集合，self/person/org 使用原文档 ID 的 getLocalGraph 双向一度后过滤登记集合；始终说明这是插件引用视图，不是已打开思源原生面板，也不是整库图。组织聚焦在这份来源快照上收窄人物到所选组织 active 成员，不改写事实；中心保留且解释其不满足其他筛选的例外。归档、失联或未核实组织不自动换成其他组织；缺本人、缺指定中心、歧义中心、来源未知分别显示原因，保持原选择并提供切全局/重新核实出口。

搜索、分组、无关系筛选和组织聚焦属于显式查询条件，切换模式或范围保留条件。只适用于关系图的条件在引用图保持保存但标明未应用。无关系按完整已核实 related 图计算，不因隐藏对端而误报。查询请求携带当前来源代次、模式、范围与中心，旧响应或已销毁实例不能更新结果；刷新重新读取实际生效来源，失败保留明确未知状态。

### 9.3 确定排序、裁剪与计数

节点按图内度数降序、稳定 docId 升序排列；边按 kind、规范化两端 ID 排序，路径采用稳定 ID 邻接次序。筛选后重算展示度数，裁剪后再次重算。统一节点预算默认 800，包含人物和组织；先保留有效范围中心、关系查询中心/对比人物和所选组织，再按确定顺序补齐，预算不足则明确报未知而非静默丢中心。重复刷新及输入乱序不改变展示、查询与导出顺序。

快照记录登记数、来源图节点/边数、范围后数量、筛选后数量、实际展示数量、范围排除、筛选排除和预算裁剪数量。未知来源的总量显示未知；图外节点不一律称为“暂无引用”。裁剪提示给出实际预算、丢弃节点/边和收窄动作；无路径区分端点失效、当前范围无路径和经筛选/裁剪后未找到，不宣称现实中没有关系。

### 9.4 共用快照与文本替代

画布、文本和 Markdown 导出只消费同一 GraphQuerySnapshot，不再分别拼装组织层或重新读取数据。快照包含查询条件、实际范围/中心、来源状态、节点/边 kind、计数、诊断和 related 查询结果。导出按稳定 ID 区分同名人物，名称、筛选和诊断中的 Markdown 特殊字符/换行转义，不改变文档结构；未知结果明确标注，不导出成正常空图。

文本视图无需创建 Cytoscape 即可读取范围、来源、计数、截断、节点、边和路径，并用原生按钮经键盘打开人物、聚焦组织或定位画布；member/ref/related 和 person/org 均有文字标签。列表渐进展示不改变快照或导出范围；390px 允许换行，无横向溢出。移动前端由 getFrontend 判定，默认文本；切画布有显式动作。状态使用必要的 aria-live/alert，关闭人物 Peek 后恢复原触发按钮，来源节点消失时回到结果标题。跨页面来源上下文和真实系统返回仍交 AG-UX-002/Host Queue。

本节允许隔离实现与定向纯测试；真实原生面板打开、siyuan://blocks 成边、多窗口外部编辑、真机软键盘/系统返回继续分别由 AG-HOST-001/002/004 验收，不能以隔离夹具代替。

## 10. 导入来源、映射与会话队列（AG-IMP-001/002）

本节更新 §4 SQL 安全约束中“SQL 组装只允许出现在 services/contacts.ts#discoverImportCandidates 一处”的旧单文件限制：查询服务可按业务范围组装 SQL，所有内核交互仍只在 api 层。services/import-scan.ts 负责组织标记过滤 SQL、候选分页编排、客户端关键词/路径过滤和扫描状态；它通过 api/blocks.ts 的 listNotebookDocs 取得已校验文档 ID，通过 api/av.ts 换算绑定 ID，再调用 api/client.ts 的 querySql 发送查询。querySql 统一负责既有 /api/query/sql 端点的 { stmt } 请求、权限/超时/错误处理和返回容器校验；服务负责校验业务结果中的 root_id 属于本次候选范围。SQL 中的外部值仅允许经过严格思源 ID 校验的 ID，自由文本关键词和路径不插入 SQL。组件只调用服务或既有 api 封装，不组装 SQL、不直接发内核请求；domain 保持无 IO 的纯函数层。此分工不增加端点或请求参数，也不放宽 §4 的输入校验约束。

导入预览是瞬态转换，零写入；文档收编、vCard、粘贴/单人 TSV 和逐人补录共用来源、字段映射、忽略/待核对与稳定目标说明。只映射既有联系人字段，不把 ORG/ADR/PHOTO、单位/学校或称谓猜成 AV 字段。多 EMAIL/URL 只取首个，并提示其余值已忽略；缺年份生日和无法表示的日期保持待核对。粘贴/单人 TSV 只回填一个草稿，同字段不同值须单选，默认不选相互冲突的候选；多行人物表格不能悄悄压成一个人。

收编以 docId 为目标，不按姓名合并；同名文档分别列出 docId/路径。执行前冻结用户确认的文档 ID、来源笔记本、姓名和锚点，显示预期对象数。筛选/分页不改变已确认队列；新发现候选不自动加入。文档移出原笔记本、改名、成为组织文档、绑定行改变或删除时暂停相关项，要求重新核对，不改绑同名人物。vCard 沿用 §1 的原子请求标记与原请求断点，不重新设计建档语义；未知残留只能先核实，未发现原请求并不证明请求未应用，禁止换请求盲重建。

候选扫描复用已验证的 listNotebookDocs 稳定 ID 分段（ORDER BY id、每页最多 500、id > 上次已核实 ID），逐页批量换算绑定 ID。返回累计已扫描数量、候选、游标和 complete/truncated/failed；单轮预算与累计数量分开。满页不代表扫描完成；短页才表示耗尽。读取失败保留失败页之前的游标和已核实候选，不能显示为空或完整；显式继续重读失败页。改变来源笔记本、锚点、关键词或文件夹范围须新建扫描，不能复用旧游标。未扫描范围不进入“全选”或对象数；界面明确允许只确认已扫描候选，继续扫描也不自动勾选新增项。

收编执行按冻结队列串行、逐项保存绑定/字段状态；暂停只在项与项之间生效，不宣称取消已经发出的内核写入。绑定后必须按原 docId 回读 itemId，字段沿用逐字段回读报告；已绑定而字段失败不能显示“收编完成”。同请求重试先核实原绑定，已核实成功不再绑定；未知绑定只读核实，不因映射暂时没有结果重新发送。未执行项保持 pending，正常/部分成功/失败/未知/暂停分别可见，已成功项不因后项失败丢失。

补录冻结 docId/itemId 与字段基线，保存前重读唯一目标，只写本次明确填写的缺失字段。重试保留原输入与原基线，已经核实的字段不重写；外部补齐或更改的值报告冲突，不用旧整份人物快照覆盖。生日与农历标记作为同一选择核对；标签按当次最新值追加，不丢弃已有标签。AV 与插件锁不是内核 CAS：队列锁只协调本插件使用相同锁的导入请求，外部原生编辑在核实与请求之间的竞争及真实多窗口仍须宿主验收，不宣称跨端点原子写入。

队列/暂停/扫描游标只保留当前会话内存，不新增自管 JSON，不承诺刷新浏览器或重启自动恢复。关闭未完成队列时明确提示内存断点边界；取消预览零写入，执行后的放弃不删除已保存文档/行/字段。诊断只含来源类型、步骤、稳定 ID、状态与字段名，不导出姓名、联系方式、正文、路径或原始错误消息。没有新端点或新参数；新增真实端点必须先另行 spike。

## 11. AI 隐私预检、候选证据与接受草稿（AG-AI-001/002/003）

AI 是可关闭的增强；手动建档、双链识别、手动捕获和原逐人 checkpoint 不依赖 AI。读取预检只读明确指定的一篇来源文档，或用户提供的选段/粘贴文本；不扫描其他文档，不读取用户配置或密钥。名册仅用于本地对账，姓名、联系方式、稳定 ID 均不作为隐藏上下文发送。

已存在的内核通道是 POST `/api/ai/chatGPT`，请求体仅 `{msg: string}`。每次调用先生成不可变预检，显示最终实际 `msg` 全文、Unicode 字符数、UTF-8 字节数、来源 docId/范围、选定候选字段和去除策略；全文包含提示词，不能只展示原文摘要。用户可编辑/缩小原文，切换候选类别与联系方式去除，再重新生成预检；任何变更需重新确认。只有明确点击「确认发送本次文本」才消费该预检一次；旧接口无确认参数时拒绝请求，不静默兼容外发。

默认移除可识别的电话、邮箱，移除思源链接中的目标 ID、块 IAL 和嵌入引用；正文最多保留 6000 个 Unicode 字符，所有截断与去除计数在预检展示。自动去除是有限模式匹配，不能保证去除自由文本中的微信号/姓名/秘密；用户须核对最终全文。可关闭联系方式去除以提名资料候选。插件只能核实提交给本地内核的 `msg`；下游服务地址、宿主追加提示或历史上下文未读取也未验证，不显示伪造的远端地址或声称下游只收到 `msg`。

预检、原文、模型回复与候选仅留会话内存，不新增 JSON，不写诊断或控制台。错误仅输出固定类别（未确认、关闭、来源不可达、未配置、权限、超时、取消、协议或请求失败），不传递原始错误、模型正文、姓名、联系方式、密钥和路径。取消/超时/组件卸载/AI 关闭使请求失效；迟到响应零回填、零事实写入。宿主传输不能保证撤回已发请求，取消只保证忽略结果。

每个候选有稳定会话 ID、来源 docId/来源类型、原文片段和本地核实的字符位置（按 JS UTF-16 偏移），及 verified/weak/missing 证据状态。模型给的引用只有精确包含在本次实际发送原文中才可作证据；仅姓名匹配不能证明资料值、场合或跟进事实。重复相同建议合并，资料同人同字段不同值标记冲突，最多接受其一。同名用 docId/itemId 列出全部本地目标；新人及无唯一目标的资料/跟进仍显示为待绑定草稿，不能按姓名选第一人或悄悄丢弃。

全部 AI 候选初始未接受，逐项可接受、拒绝、编辑；编辑后取消原接受，需要再次确认。接受人物才影响参与者或新人输入，接受场合才回填日期/地点/备注；未接受的资料、跟进、关系不进入联系人事实、提醒或图谱。关系仅作为明确标记的草稿展示，零关系写入。资料/跟进需用户选择稳定目标（包括主捕获已成功建立的新人），主捕获全部完成后才执行；冻结候选 ID、docId/itemId、字段基线与输入，逐项保留 pending/applied/skipped/failed/unknown。已完成项不重放，未知跟进只回读核实、不盲重建，回读失败绝不当空库；字段补写复用既有逐字段回读与冲突检查。

捕获来源读失败显示 unavailable，禁止将其当成空链接成功预览；写入预览明确原文不替换，只追加/更新插件标记区块，日记、地点、人物投影沿用 §3 原逐人/逐投影 checkpoint。来源不可达或身份变化沿用原请求暂停与核实，不能新建请求绕过。

真实端点验证限全新 UUID 工作区和随机回环端口、虚构短输入、未配置状态，不调用外部真实服务。成功生成、下游服务范围和宿主取消行为仍须配置齐备后在 HOST 验收；独立回归或未配置实证不代表真实 AI 成功。

## 13. 返回上下文与数据变化事件（AG-B13-002/004、AG-UX-002）

人物入口只认稳定 docId，不能按姓名或 itemId 选择。返回上下文仅留当前会话：来源 view（home/people/graph/orgs/settings）、可选原组织 docId 或原文档 docId，以及界面保存的触发元素/滚动位置。组织卡片传具体组织 docId；组织→人物→同伴保持原组织来源，关闭人物只收起最上层详情，原组织搜索、当前/历史筛选、已加载页、滚动及触发焦点保留。关闭组织返回原组织卡片或原视图；触发元素不可达时聚焦原来源区域，不选择同名替代目标。首页/图谱人物入口的来源视图保持挂载；主动切换导航先走现有草稿/忙态保护再关闭覆盖层，不让 aria-current 与实际来源漂移。

共同背景按 peer.docId 重新核实唯一人物；同名、旧 contact 快照、未登记或重复绑定不能变成第一项跳转。文档档案条入口向同插件实例的工作台投递一次人物导航请求，冷挂载可读取待处理请求；关闭后打开原文档 ID，焦点尽量回到原档案条入口。请求只留会话、绑定实例与生命周期，卸载失效；无来源采用当前视图/首页的确定出口。浏览器/宿主系统返回、真实文档切页和多窗口焦点仍须 Host 验证，隔离 UI 不冒充 Host 通过。

lvct-data-changed 增加兼容版本 `version:1`、窗口来源 `sourceId`；revision 为来源内单调正整数，可选 topics（organizations/memberships/people/all）及稳定 docIds。无 version/sourceId 的旧事件继续支持；未知版本、非法 revision/ID 不刷新。每订阅按 sourceId+revision 去重，来源重启不因旧来源高 revision 丢新事件；连续变化合并一次刷新并保留已出现的偏好修订/错误信息，卸载后取消订阅和定时器。事件只是读取失效提示，不是保存成功证据；读取失败仍未知，不投影为空库。

组织刷新保留当前组织 ID、成员查询、筛选和已加载窗口；数据变化时重新读取相同窗口，短页才收缩页数，失败保持原列表并报告待核实。编辑中保留草稿并提示待刷新，不覆盖原记录快照。已删除/不可达的原组织明确显示失联，不自动跳到首个组织；刷新/重试均不重置滚动或触发焦点。真实两窗口传播及原生文档变化回调另列 Host。

### 13.1 姓名与别名身份核对（AG-ALIAS-001）

姓名与别名去除首尾空白、忽略大小写后共同生成候选，不给其中一种来源更高优先级。别名撞他人姓名、同名多行或旧库跨人冲突均须按稳定 docId/itemId 人工确认；不自动选择首人。索引指向未登记人物或同一 docId 多重绑定时显示不可核实，不能按未匹配新人创建。查询只读；旧互动和迁移记录不会因别名更改重新归属。

生产新增别名先核实当前名册唯一登记及人物文档可达，再在原别名存储锁内校验冲突、幂等追加和写后回读。坏库或读取未知停止，泛称、控制字符不接受。已有别名显示按记录 ID 更新，重复提交不会生成重复 DOM 项。人物解绑后别名历史保留，其识别不可用，不自动搬移或删除。

联系人列表和选人器分别批量读取一次别名索引并按 docId 投影；读取失败明确未知，姓名搜索和手动流程仍可用。搜索命中仅展示候选，不替代用户确认。捕获在锁内读取当前索引与名册，姓名/别名联合核对后仍检查原人物可达。AI、vCard、外部桥继续按各自已定契约处理，不暗中扩展为别名写入或自动合并。别名 schema 1、墓碑及迁移语义保持既有契约。

## 12. 外部桥最小安全协议（AG-P0-010）

`window.LvContacts.protocol=2`，能力仍仅 searchPeople/getPerson/ensurePerson/recordInteraction。v1 按名复用与只返回计数不足以表达安全边界，故安全语义升主版本；调用方必须检查精确支持的版本与能力，不用 `>=1` 猜测兼容。AG-BRIDGE-001 只形成最小草案与兼容建议，不增加业务或承诺完整跨插件协议。

姓名只产生候选，单个候选也不自动选中。ensurePerson(name,{docId}) 按稳定文档 ID 取已登记人物，姓名不改变该 ID 身份；无目标创建须提供非空稳定 ref，候选存在则停止，由调用方选择 ID。docId/itemId 必须为合法思源 ID，唯一人物/唯一绑定行经新鲜名册核实；未知或未登记文档不写互动，不把 itemId 当 docId，不收编未绑定文档。

新增工作区本地 `bridge-requests.json` schema 1：请求按 kind+ref 唯一，冻结 notebookId/avId/dbBlockId、建档姓名或互动人员集合/本地日期/备注，建档复用 ContactCreationRequest 的原请求 checkpoint 与 bindingState。互动逐人保存原 itemId、pending/applied/skipped/failed/unknown 状态；建档保存 pending/applied/rejected/unknown。全部 JSON 经 storage.ts 严格读取、规范化、排他锁和写后回读，缺文件为空，损坏/版本未知停止，不能覆盖成空库。记录不随业务迁移包导出，不读取其他插件存储。幂等身份不得删除以允许重放；用户手动移除该文件会失去去重保护，不属于支持的恢复途径。

业务请求发送前持久 pending；未核实持久化不发业务写。相同 ref 改输入或锚点报冲突，成功重放零业务写；并发桥请求在同一排他锁内重读请求库和名册，建档继续复用现有联系人创建锁与原子请求标记，互动复用现有事件存储锁及 personDocId+source=api+externalRef 身份。未知互动只严格读取事件库核实，不因暂未发现而重发；未知建档复用原请求安全核实/续做，不产生新的创建请求。明确拒绝与未发出的项可在同请求下重试。无 Web Locks 时仅本窗口排他，不能宣称跨窗口保证；原生编辑与多端点之间无 CAS，真实宿主竞争仍待验。

recordInteraction 返回 recorded/applied/skipped/failed/unknown/complete 与按输入序号排列的 results。非法 ID、未登记 ID、重复输入均有独立结果；重复输入 skipped，未知身份或读取失败 unknown。recorded 只计本次新增且回读核实的事件，已有事件与只读核实不计新增。默认 ref 沿用 bridge:<本地日期>:<排序去重的合法人员>；默认日期冻结到请求首次接收当天。显式 ref 建议使用调用方命名空间和稳定事件 ID；同键不同内容冲突，不覆盖旧事件。不能把 changed/partial/unknown 报成全部完成。

公开错误固定 code/message/writeState/retry，diagnostic 仅 operation/code/writeState；不透传原始 Error、cause、路径、姓名、联系方式、备注或 ref。正常候选/人物结果中的姓名与稳定 ID 是明确调用的数据，不写日志。未初始化、卸载、锚点变化及桥不可达保持独立失败，不影响手动联系人流程。外部桥只是本地公开协作接口，不是沙箱、权限或身份认证边界，不接收凭证、不发网络消息。

## 14. 工作区设置与原生属性视图恢复（AG-P0-020）

`contacts-settings.json` 是插件自管的关键锚点文件。读取结果必须区分：文件不存在或返回空串为 `missing`；通过 schema、ID 和字段映射校验为 `valid`；JSON/版本/字段形状不符为 `invalid`；宿主读取抛错为 `read_failed`。`missing` 才能进入初始化向导；`invalid` 与 `read_failed` 保留原文件、停止普通业务读写并显示恢复入口，不能把读取失败当成空库覆盖或新建。

`valid` 设置在挂载工作台前先只读核验笔记本、宿主文档、数据库块和 AV 定义。先按宿主文档查询 `type='av'` 的块及其 markdown 中的 `data-av-id`，再调用 `renderAttributeView`；若块不存在，不再把旧 `dbBlockId` 发送给内核。内核精确返回 `resolve attribute view carrier: block [...] not found` 时归类为 `anchor-missing`；权限、传输、协议、加密笔记本未加载等无法判断现场的错误归类为 `anchor-unknown`。`createIfNotExist` 只用于全新已存在载体的物化，不能修复缺失载体。

锚点恢复只读扫描全库候选，展示笔记本、宿主文档、数据库块尾 ID 和字段匹配数。用户选择候选后先预览字段与双向关系，再显式确认重绑；没有候选时才允许明确进入初始化向导。恢复期间工作台及其设置页快照均卸载，旧设置只存在于恢复服务的短暂上下文，禁止联系人列表、健康检查、捕获和外部桥继续请求旧 AV。恢复不会删除人物文档、互动/跟进等插件 JSON，不自动合并、不静默创建第二套数据库。

用户删掉 `contacts-settings.json` 与删掉“联系人总表”中的数据库块是两类现场：前者通常可由初始化向导扫描并复用原生数据库，后者必须走锚点扫描/重绑或显式新建。截图中的 block ID 只能作为诊断证据，不能当作字段 ID 或让用户手填恢复。
