## #35：VCF 兼容与诊断

现有代码已覆盖 BOM、空白 FN 回退 N、部分 QP 与 GBK 字符集，以及逐卡跳过无姓名卡片。先前合成样本复核发现三处独立缺口，现已完成纯域修复并加入回归：

| 样本形态 | 修复前表现 | 当前结果 |
| --- | --- | --- |
| QP 软换行与空格折行组合 | 名称多出字面 `=` | 已修复并回归 |
| `ENCODING=QP` 简写与无空格软换行 | 严格导入报损坏属性行 | 已修复并回归 |
| N 结构名中含转义分号 | 提前反转义后错误分列，姓名丢字 | 已修复并回归 |

重现入口为 [vcard-compat-research.mjs](../../scripts/spike/vcard-compat-research.mjs)，结果写入 [vcard-compat-research-results.json](../../scripts/spike/vcard-compat-research-results.json)。矩阵只用虚构数据与纯域解析，记录失败作为研究结果，不连接宿主或执行联系人导入。

修复后已运行 17 个场景：13 个既有基线、3 个合成候选和 1 个 UTF-16 文件解码边界全部符合预期（17/17）；`node --check` 通过，相关正式测试扩展为 31/31。脚本退出成功只表示合成矩阵通过，不代表已确认小米导出格式。

最小步骤：

1. 覆盖普通 UTF-8、BOM、FN/N 空值、转义分号、空格/制表符折行、QP 两种参数名及软换行组合，并核对有名后继卡不会被前卡误吞。
2. 分开判断文件字节解码和属性 CHARSET/QP 解码；当前文件入口是 `file.text()`。UTF-16、非 UTF-8 文件先研究可识别性和明确拒绝/选择编码，不能凭猜测自动修复姓名。
3. 设计源卡片序号、总卡数、无姓名跳过数、属性名/参数与固定错误类别的诊断；默认诊断不含姓名、电话、邮箱或原文。
4. 已将三处可复现缺口拆为解析修复并加入回归；后续沿用当前导入预览、同名确认、稳定请求和未知写入纪律。

退出条件：支持矩阵中预期姓名、顺序和卡片计数完全一致；拒绝项有明确原因；正常基线不退化；诊断可定位源卡片且不泄漏值。解析修复不能放宽损坏结构为静默部分导入。

Issue #35 的小米真实根因仍需保留原编码、参数、折行与空值结构的脱敏首卡及有名后继卡，或实际导入验证。合成样本缺口不能据此归因小米，也不能作为关闭 #35 的证据。

## #51/#54：先做多联系方式契约

当前电话、邮箱、微信、网站仍是 AV 单值。vCard 多 TEL 被拼接，EMAIL/URL 只取第一项，导出也只保留一个字段。直接增加输入框会把保存、搜索、迁移和导出缺口转移到新入口。

复用 [AG-RF-004](../AGENT-DEVELOPMENT-BACKLOG.md#ag-rf-004--issue-5154-多联系方式与两层自定义条目)，先验证候选结构 `contactMethods[{id,type,value,label,isPrimary,order,...}]`。本轮已完成[多联系方式研究报告](MULTI-CONTACT-METHODS-RESEARCH-2026-10-16.md)及[纯内存结果](../../scripts/spike/contact-methods-research-results.json)：28/28 纯域检查、7/7 临时预算通过，但 `candidateContractAccepted=false`，未接入生产存储或编辑器。以下决策完成前不接入生产契约：

1. **事实源和原生编辑。** 比较 AV 全量、人物原生文档标记块全量 + AV 主值、插件 JSON 全量 + AV 主值三个方案。保持“删除插件数据后档案仍可读”的边界是首要研究约束，暂不采纳 JSON 为唯一全量事实。三种方案都需定义原生编辑冲突与事实已保存、主值投影未核实时的恢复，不能双方静默覆盖；详见 [数据主权比较](MULTI-CONTACT-OWNERSHIP-2026-10-17.md)。
2. **旧值迁移。** 旧电话中的 ` / ` 可能来自历史拼接，也可能是用户原文。默认作为一条 legacy 原文值保留；拆分必须预览确认。同一确认请求重试沿用原身份；新文件重复/冲突进入预览，不按姓名或值自动认定身份。改值/标签/排序不更换条目 ID。
3. **主值与保真。** 每类型最多一个主值；用多 TEL/EMAIL/URL、重复值、未知类型、主值切换、清空、备份恢复验证。无法无损导出的类型逐项说明，不伪造标准字段。
4. **全部值搜索。** 次要值若存 JSON 或人物文档，现有主库 AV query 均会漏检，原生全文搜索也不等于插件全量方法搜索。比较可重建索引和有界扫描，记录 1 万人物/10 万条目的首次构建、查询、迁移时间与峰值内存；确定预算后才接主路径。
5. **失败与删除。** 明确记录缺失、未知版本、并发编辑、条目删除墓碑和旧备份恢复的行为；坏库或投影失败保留原事实与原请求。列表写入/恢复前核实原 `personDocId`、唯一 AV `itemId` 和锚点；人物解绑、行变化或锚点变化时停止投影，不按姓名重绑。

交付：候选数据契约、方案取舍、迁移预览夹具、多值往返/搜索测量、逐步骤失败报告，以及采纳/延期决定。S1 已完成有限 UTF-8 vCard 适配器 60/60 合成断言和独立反例复核 5/5；[S2](MULTI-CONTACT-RECOVERY-2026-10-17.md) 已完成严格快照与恢复候选矩阵 60/60、独立反例 21/21，不决定最终事实源。`AG-RF-004-N1` 已有 31/31 纯格式与隔离内核写读/重启证据，部分编辑器正文行为与同人物双页面刷新已观察；严格候选读取、复制和并发仍待验，整卡保持 `host_pending`。编辑器折行与不完整读取由 N2 先研究，再补有效身份夹具的 UI 旅程，随后推进 S3 能力对照、S4 全量搜索/实际 IO 和正式契约决策。不把内存结果当作生产 schema 采纳依据；退出条件仍是旧数据无损、ID 稳定、主值可核实、损失可见、失败不覆盖且搜索方案有测量支持。

联系方式方案通过后，再独立研究 `customFields[{id,label,value,parentId,order}]`：最多两层，同联系人内引用顶层父项，拒绝循环/悬空父项，删除父项先预览子项影响。首版不做无限条目树，不把互动、组织经历、跟进和备注迁移为通用层级。

## #48/#46：已关闭重复工单，宿主余项保留

#48 的一次性家庭种子、改名不补种、可恢复移除已在当前未提交工作区实现；#46 的历史成员边已有实现。入口核对已收口：Workbench 提供组织资料编辑器时只显示“新建组织资料”，独立管理器兼容旧宿主时保留快捷创建并显示“新建组织名称”标签，避免同一宿主出现两个新建入口。

入口回归覆盖忙态、错误、取消、桌面/窄屏和稳定组织 docId；本轮隔离 UI 已覆盖组织上下文返回、焦点、筛选和滚动保留。真实思源宿主、多窗口和移动真机仍需按下方旅程验收，不能仅凭隔离回归关闭 Issue。

专项验收可复用一个临时思源工作区与两个 Chrome 页面：

1. 初始化家庭并记录组织 docId、种子与成员事实；改名、刷新、重启，确认不补种。
2. 工作/学校成员 active → former → 新增 active，确认当前投影与历史边分别正确，former/mixed 可从线型、文字与导出识别。
3. 移除前取消零写入；确认移除后日常入口退出，原文档和全部成员事实保留。
4. 第二页面原地回读，再重启与恢复；使用原组织 docId，无重复种子、成员或边。
5. 组织 member 边不进入 related 的二度/最短路径；检查入口用途与卡片文字稳定。

#46/#48 的重复工单已关闭；关闭只表示避免重复跟踪，不表示 `AG-B13-007` 或 `AG-HOST-002/006` 已变为 `done`。原生图面板、真实用户库、跨窗口组织成员投影和手机真机继续由 Host Queue 跟踪。
