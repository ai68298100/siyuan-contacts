# 多联系方式事实源与数据主权候选比较（2026-10-17）

对应 `AG-RF-004`、Issue #51/#54、正式契约复评的 D1。本报告是当前工作树的只读源码研究，不采纳生产格式，不改 AV、联系人模型、插件存储或迁移包。两层自定义条目继续后置。

研究结论：存在不让次要联系方式随删除插件数据而消失的原生备选。“人物原生文档保存全部方法，AV 投影每类主值”应与“AV 全量”“插件列表全量”并列评估；暂不采纳 JSON 为唯一全量事实源。这只确定下一阶段的比较范围，不决定最终 D1。

## 当前承诺与已知能力

`DATA-CONTRACT.md` §0 规定结构化联系人档案保存在原生 AV，人物文档保存在人脉笔记本；卸载插件后仍在。插件自管 JSON 则可能随插件数据目录删除而丢失。必须区分“停用插件”“卸载但保留数据”“删除插件数据目录”和“删除人物文档/整个工作区”，不能用其中一种现场替代另一种。

当前 `phone/email/wechat/website` 是单值字段。`api/av.ts` 的 `phone/email/url/text` 写入形状均为一个 `content: string`，普通赋值请求不带 expected/revision；当前能力不能直接解释成多个有独立身份、标签、主值和排序的方法。把多个值拼为字符串不构成结构化多值。

人物备注已经通过独立标记、可见段落、DOM 文本编码和 SQL `content` 严格回读保存到人物文档。该证据说明原生可读正文可以成为插件功能的事实源；它只覆盖已定义的备注格式，不能证明新方法格式、规模、手工编辑兼容或持久恢复已经成立。

## 三种候选

| 候选 | 原生可读性与卸载/删除边界 | 锁、编辑冲突与恢复 | 搜索与备份成本 |
| --- | --- | --- | --- |
| AV 保存全部方法 | 全部值留在原生数据，可在原生表中阅读。独立“联系方式 AV”、每方法一行是一种候选；把 JSON 放 text 单元格、增加电话 2/3 等固定列不是等价方案，分别影响可读性和扩展上限 | 独立方法 AV 需要方法身份、人物归属、行生命周期和关系契约。若主库仍投影主值，仍有跨库部分成功；现有赋值没有 CAS，不能用插件锁隔离原生编辑。新表/行能力必须先 spike | 原生表查询不等于现有联系人主表 query 自动覆盖次要值；需跨库分页合并与完整性状态。完整工作区备份保留原生数据；插件 JSON 迁移包不包含原生 AV |
| 人物原生文档保存全部方法，AV 投影主值 | 方法正文明确显示类型、标签和值时，卸载后仍可阅读。只删除插件数据目录不会删除人物正文中的方法；保留“档案仍在”的用户结果，但必须修改“结构化字段全在 AV”的精确契约 | 可以借用唯一标记、归属验证和严格回读纪律。新格式、方法 ID、块移动/复制、重复标记、原生删块/改文和旧格式需另定规则。正文与 AV 仍非原子事务，不能把两个原生位置视为同一次提交 | 原生全文搜索可以看到正文，不保证插件的规范化方法搜索完整。逐人读取可能产生大量内核 IO，需测有界扫描/分页和派生索引。工作区备份保存正文；插件迁移包不能冒充已备份方法原文 |
| 插件列表保存全部方法，AV 投影主值 | 列表易表达独立条目；原生主表只保留主值。次要方法随插件数据目录删除可能丢失，是当前结构化档案数据主权的变化，不能称为透明兼容扩展 | 可复用 strict read、写后回读与 Web Lock；需同包络事实/请求或另行证明恢复顺序。JSON 与 AV 没有跨存储事务；原生用户编辑不会遵守插件锁。未知写入不能换请求 ID 重放 | 批量 JSON 便于扫描和建索引，但真实读/parse/序列化/写成本未测。需新迁移模块、版本说明、墓碑和恢复冲突规则；保留原生主值不是全量备份 |

“原生文档全量”不能通过只把隐藏 JSON 放属性、而正文仅显示主值来实现本报告的可读性目标。全部方法的值与基本含义应留在用户可阅读的正文；机器身份和格式元信息可另行研究。单块快照、逐方法块、列表或表格尚未选型，不能由本报告暗中固定。

## 最小可验证决策与退出条件

本轮只把原生数据保留作为比较约束，建立并列候选，暂不选择生产事实源。下一张原生能力实验卡可使用 UUID 临时工作区、两个虚构人物、各三条方法，沿用已实证端点；不得触碰日常工作区或真实联系方式。

1. 写入和重新加载：明确可读正文与稳定方法 ID，验证特殊字符、换行、标签、主值和顺序；保留旧 AV 字符串原文，不自动拆 ` / `。
2. 原生编辑与损坏：手工改值、删除/移动源块、复制标记、重复块和未知格式，区分合法缺少、冲突、未知与明确删除；不猜测第一块、不按姓名重连，也不自动复活用户删掉的源块。
3. 数据删除边界：只清除实验用插件存储，再从原人物文档和 AV 读取全部方法；确认保留全部值及用户可读性。该检查不能代替删除文档/工作区后的恢复保证。
4. 部分成功：源数据保存、AV 投影失败/响应丢失、原生第三值和行绑定变化分别报告；读到目标值可只读核实，读到原值仍不能证明未发。
5. 恢复与并发：重新加载后的未知请求、两个窗口及不遵守插件锁的原生编辑单独验证；若实验只完成单次写读，结果只能覆盖单次写读，不把它升级为重启恢复或并发保证。

原生方法格式及其限制经过实证后，才能据此比较 D1；后续仍须决定 D2–D8、旧入口、迁移与完整搜索。即使选定原生源，也可能需要插件侧派生缓存或工作区投影断点。删除这些派生文件不应删除源事实，但能否找回未完成请求必须有独立证据；不能宣称删 JSON 后自动恢复全部投影状态。

并行的 `AG-RF-004-S2` 只冻结一个研究包络，使用假 Plugin 与假 AV 注入严格快照、锁、失败和恢复情景，见 [严格快照与恢复候选实验](MULTI-CONTACT-RECOVERY-2026-10-17.md)。它可以否证不安全的状态机，不能决定 D1、证明原生格式可用、验证真实宿主持久化，或把 JSON 唯一事实源采纳为生产规则。
