# 多联系方式严格快照与恢复候选实验（2026-10-17）

对应 `AG-RF-004-S2`、Issue #51/#54。以下规则只冻结本次实验输入和状态机；不是生产 DATA-CONTRACT，不决定 D1 事实源。即使通过，也不能直接接入生产或声称已解决跨 AV/JSON 事务。

## 实验规范（先于实现）

使用独立 `researchFormat` 的单包络，在同一键内保存候选事实、墓碑和投影请求；通过假 Plugin 的内存映射复用 `loadJsonStrict`、`saveJsonVerified`、`withStoreLock`。不存在真实插件文件和 AV 写入，只有结果 JSON 是脚本输出。候选若采用原生文档事实源，需另做原生格式和宿主实验；本实验不能代替。

严格读取只接收普通 JSON 对象；拒绝未知版本/字段、字符串包络、缺键、非法 revision、人物/方法/请求重复身份、非法目标和状态。缺文件仅在明确新库初始化分支创建空包络，恢复和投影入口不能把缺文件当作空库。所有拒绝不修改输入，不产生业务写入。人物身份为稳定 docId，方法身份在人物内独立，不按姓名、值、排序或 AV 行生成；类型仅 phone/email/wechat/url，同 ID 不允许改类型。

值保留原文；拒绝空白值、Unicode Cc 控制字符和超限，不截断；标签可空但须有界。每人最多 128 条，每值最多 4096 字符、标签最多 128 字符；每类 0 或 1 个主值。order 为非负安全整数，同序允许且以 ID 确定次序。删除产生墓碑，同人物的墓碑 ID 不能再用作活跃方法；不自动晋升主值，归零投影必须是已确认请求的一部分。墓碑也须严格验证，禁止坏墓碑按空处理。

墓碑必须有合法所属人物/方法 ID、类型和非负安全删除 revision；同人物不重复，且删除 revision 不大于该输入快照 revision。不同备份的 revision 不能当作跨来源时钟：合并预览使用当前 revision 的下一代，无冲突的外来墓碑在候选输出重标为该代，禁止简单照抄外来未来 revision。预览不等于已提交恢复。

手动确认分支新增的墓碑必须来自本次删除的当前活跃方法，类型一致、deletedRevision 等于此次 factsRevision；不得为从未存在的方法伪造删除历史，也不回填旧代次。已有墓碑不可改变或移除。备份外来墓碑只经独立恢复预览处理，不走手动确认分支。

备份预览不包含工作区投影请求，旧包无方法不清空当前库。当前同 ID 内容优先且报告冲突；当前墓碑阻止旧条目复活。备份墓碑与当前活跃条目冲突时保留当前事实并报告，不从旧备份静默删除新事实。不同方法 ID 导致同类型多个主值时报告冲突，不静默降级其中一条。人物不可达则报告未解析，不按同名匹配；预览零写，预览结果必须再次满足完整严格校验。

冲突的外来墓碑不加入输出，报告其冲突；其余无冲突的外来墓碑必须保留，否则第二次恢复可能复活已删除 ID。合并后发生主值约束冲突时保留当前整个受影响类型，报告候选拒绝，不产出非法快照。

候选写入在同一键锁内严格重读，核对预览 revision，保存事实及投影意图后回读。请求 ID 和冻结 payload/目标的摘要共同识别同一确认请求；相同 ID 不同内容拒绝，原请求重复调用先核实而非重新保存。每个请求冻结 workspace/AV/item/doc/列/类型、baseline、desired；同人物/类型存在未收口请求时，新 ID 也不能绕过。

投影分为 prepared、issued、verified、rejected（仅明确未应用）等已定义状态。发送模拟 AV 写之前必须先持久化并回读 issued；任何事实/issued 保存未知，零 AV 写。prepared 不等于可以忽略当前原生值：先核对完整目标和当前值，目标变更停止，第三值是冲突。已为 desired 时只读收口；issued/未知重启后只读核实，看到 baseline 仍不能证明未发；仅原请求被明确拒绝且新鲜核实目标/基线后，才允许显式补做。事实已保存与投影未完成分别报告，不回滚事实。

默认恢复入口只读核实 AV，不发送投影写；核实后的状态可单独持久保存。只有显式投影操作可发送：prepared 在新鲜目标/基线核对后允许首次发送；rejected 在同等核对后允许补做；issued/unknown 一律不能重发。verified 的含义是原请求目标曾被核实，之后原生值变化不回放原请求。所有存储、超时和传输异常都不构成明确 rejected。

当前会话另持有保存未知屏障时，优先保守停止并只读核实；读到匹配请求的持久 verified 才清除该屏障，不得清掉另一个请求。部分保存未知场景未实现人工解除/完整重试体验，不把状态机实验当作完整恢复 UI。

`saveJsonVerified` 成功只表示一次回读与 expected 的 JSON.stringify 一致；不证明事务、CAS、磁盘持久化或后续不变。saveData 抛错可发生在已应用之后；回读失败立刻抛错且不二写；回读成功但不等会再次保存同包络，最多 2 次。实验需显示这些差异，不能把所有抛错叫作未发或可自动重试。

首次事实写的响应未知、且后续看不到原请求时，不能证明未应用或保证断点可自动找回；保留会话内冻结请求，只读核实，阻断换 ID 重做。进程/宿主迟到写、跨端 Web Lock 缺失、原生编辑没有 CAS 均列为生产未决边界，不能用内存锁或假 AV 把问题“证明解决”。

上述缺断点屏障只对仍持有原请求的当前会话成立；进程重启丢失全部会话信息且存储未找到请求时，实验不提供自动重做许可，也不能证明新请求可被全局阻断。规范化输入必须独立克隆并冻结后再进入异步步骤，不能依赖 storage 帮助函数替调用者做 strict parser 或防止引用被修改。

| 场景组 | 已验证的结果 | 保留的边界 |
| --- | --- | --- |
| 严格读取 | 坏库、未知版本/字段、空白/控制/超限值、重复身份/主值、未来或活跃碰撞墓碑被拒；输入独立克隆并冻结；只准空库初始化 | 只覆盖实验格式，不是生产联系人 parser 或迁移器 |
| 备份预览 | 当前同 ID 优先；当前墓碑阻止复活；无冲突外来墓碑重标并保留，第二次恢复仍不复活；删除冲突和双主值有报告；合并后重新完整校验 | 只做零写预览，不实现真正恢复提交、跨库身份匹配或生产备份版本 |
| 确认请求 | 排队前冻结 revision、事实和目标；陈旧预览/同 ID 改内容或改 scope 均拒绝；新增墓碑仅来自本次删除；未完成请求对应的类型事实不能被备份改掉 | 依赖参与同键锁的代码和单调 revision；不是 CAS 或针对不合作写者的隔离 |
| 存储故障 | 已写丢响应、回读失败、两次不收敛均不发送 AV；最多两次存储尝试按真实 helper 行为记录；已核实 verified 后只解除原请求屏障 | 首次写未知但未找到断点，屏障仅当前会话可用；完整人工恢复路径未实现 |
| AV 与重启 | issued 先持久核实；目标变化/第三值停止；AV 已写但回读失败保留 issued；重建会话后读 desired 零重放核实，读 baseline 仍未知；仅明确拒绝允许显式原请求补做 | 假 AV，不证明真实原生编辑竞争、原子提交或跨进程持久化 |
| 等待超时 | 仅调用者等待超时，底层任务仍持有锁；受控 gate 释放后第二操作才进入 | 不能取消底层宿主写；迟到宿主写和跨进程锁尚未解决 |

审查中实际补齐的候选缺口包括：未保留外来墓碑、合并后双主值、只检查 ASCII 控制字符、异步锁回调仍读原输入 revision、pending 的冻结事实与当前事实不一致、已持久 verified 但会话屏障未解除，以及未知首次写复用请求 ID 改投另一类型。前两项来自旧研究模拟，其余在本次候选初稿中发现并加入回归；这些修正均未进入生产代码。
