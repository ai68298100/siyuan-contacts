## 正式契约卡必须定下的最小决策

下表是评审建议，不是已采纳的生产规则。不同选择都必须能给出一个明确的输入、状态转移与结果；不能留给组件按情境猜测。

| 决策 | 建议的最小范围 | 验收门槛 |
| --- | --- | --- |
| D1：事实源与数据主权 | 把“AV 全量”“人物原生文档保存全部方法、AV 投影主值”“插件方法列表全量、AV 投影主值”并列评估，暂不采纳 JSON 为唯一全量事实源。原生文档方案可能保留删除插件数据后全部值仍在的用户结果，但新格式、编辑冲突、恢复和搜索尚须隔离实证；详见[数据主权候选比较](MULTI-CONTACT-OWNERSHIP-2026-10-17.md) | 文档能逐字段回答从哪里读、哪一侧可写、另一侧坏库怎么办，并区分停用、卸载、删除插件数据与删除原生文档；次要值不能误报为原生 AV 已保存 |
| D2：稳定身份、类型与约束 | 首轮只评估已有 `phone/email/wechat/url`；QQ、custom 可作为独立候选，不为满足 Issue 直接扩大枚举。新方法在用户确认的请求生成一次不透明 ID；旧字段用原 `personDocId + stable field slot` 的稳定迁移身份；类型改动是否沿用身份必须固定。值保留原文；检索规范化不能回写内容 | 改名/改值/改标签/重排不换 ID；同值跨人不合并；空白值、控制字符、长度/条数上限、未知类型、重复 ID 和重复 order 均有拒绝/兼容规则；超限不得截断成功 |
| D3：主值、删除与排序 | 每种类型允许零或一个主值；零主值时明确投影为空，不能默认拿第一条。切换主值是一个方法列表变更；删主值必须预览影响并要求选新主值或明确留空。次序显式确定、同序有稳定 ID 次序；删除保留墓碑，人物解绑保留历史但不投影到别人 | 新增非主值不改 AV；删除不自动晋升、不被旧备份复活；重新收编同一 docId 与新建同名人物的行为不同 |
| D4：原生编辑与旧入口兼容 | AV 当前值与最后已核实投影不一致即冲突，不自动覆盖或按值认领条目。显式“采用 AV 为该类型主值”与“以列表重新投影”都需新鲜预览；空值编辑不能暗示删除全部方法。手动、AI、补录及桥各自固定为主值补丁或待确认新增 | AV 外部更改/清空、旧版插件写入、陈旧表单、主值已删除和目标行重绑均不覆盖列表；未知当前库不能退回 AV 空列表写入 |
| D5：写入顺序与恢复 | 若列表为事实，先在单一方法库锁内 strict read+保存事实及待投影意图，再核实同一 docId/itemId/锚点/列和 AV 基线；逐字段投影并回读。事实成功、投影失败应分开报告。checkpoint 是否同包络或独立工作区库要选定，禁止依赖两次写入原子化 | 列表写未知零 AV 写；AV 响应丢失但目标已读到可零重放核实；原值仍在不证明未发；pending 只读核实，明确 rejected/unissued 才可补做；重启/两窗口不换请求绕过未知 |
| D6：旧值迁移、备份与版本 | 旧 AV 值保持一条，` / ` 只提示拆分，不自动推断。迁移预览零写，确认时核对原 AV/方法库基线。方法与墓碑业务备份纳入新模块契约，投影 checkpoint 不迁移；同 ID 内容冲突现状优先并报告，人物归属只认明确 docId | 坏库/未知版本保留现场；预览过期零写；旧包缺方法不清空当前库；旧备份不复活墓碑；原人物不可达不按姓名恢复到他人；旧版读新包须明确拒绝或采用已定义兼容出口 |
| D7：vCard 的保真层级 | 标准 TEL/EMAIL/URL 保留每条值和来源序号；先测 TYPE、PREF、分组标签和未知参数，再决定映射。以“语义往返”与“原始文件字节往返”分别承诺；没有映射的微信/QQ/custom/未知属性须保留到研究 loss report，不猜私有扩展 | 同一文件的多值可复得；重复值仍可预览而非静默合并；用户标签与标准 TYPE 不混为一个字符串；未支持项不能静默丢失；vCard 的同名不构成人物合并依据 |
| D8：搜索、隐私与预算 | 首轮可采用可取消分块扫描全部已核实方法；trigram 索引仅派生缓存，可后置。方法列表 revision/原生基线、锚点、名册与用户条件共同定义查询代次；结果区分自身命中和 related 展开。桥能力不因工作台搜索扩大而暗增 | AV 结果非空时仍找得到方法命中的其他人物；缺索引/改值/删除/跨窗口失效/取消/坏库不产生假空 complete。日志仅步骤/ID/状态，不含值、标签、原文；真实 host 预算独立记录 |

D1–D6 是落存储前门禁；D7 是任何多值导入导出前门禁；D8 是提供“可搜索全部联系方式”前门禁。不能通过只开放编辑器来绕过备份、旧入口或搜索的已知缺口。
