# 原生方法块范围发现与丢标记反例（2026-10-17）

对应 `AG-RF-004-N3`、Issue #51/#54。本轮只研究候选块如何被发现，以及原生内容失去身份特征后哪些信息仍可观察；不改变 N2 解析器，不采纳原生文档为生产事实源。

## 运行前冻结的规则

N2 的 `readDocument` 输入是已经选出的候选方法块，不是人物文档全部内容。将“带主 marker 的块”直接当全集，即使该子集被解析成 complete，也没有证明未选中的块不是损坏方法。本实验比较三个诊断视角：

1. 只选择主 marker 值为 1 的块，再调用原样 N2 读取器。这是明确标记的 **不安全对照**；其 complete/writeAllowed 只属于人为选择的输入，不能对外开放写入。
2. 全文档有界枚举后，选择带任一方法属性或正文格式前缀的可疑块。可疑不等于方法：普通笔记也可以使用同一前缀，必须严格核验，不能自动认领身份。
3. 在上述线索外加入本次实验基线已核实的块 ID。它能揭示已知源块丢属性、改正文和消失，但只是本次会话的观察历史，不是生产 manifest，也不保证卸载、删除缓存或冷启动后仍有这份历史。

研究夹具仅两篇虚构文档：甲含两条有效 hash 身份的单行 DOM 方法及普通正文；乙含普通正文与“联系方式：”前缀的普通笔记。依次通过真实 Kernel API 去除甲的一条方法主 marker、全部方法属性、可见格式，再删除已知块；每一步独立回读 SQL 全字段和直接子块。修改属于实验故障注入，不称为真实编辑器操作或移动。

完整枚举只表示本轮有界 SQL 已返回当前范围全部行，且直接子块集合与 SQL 的直接子块一致。它不是跨请求原子快照，更不证明历史全部方法仍可辨认。返回字段必须区分 `fullDocumentObservationComplete`、`selectedCandidateReadComplete`、`historicalMethodScopeVerified` 与最终 `writeAllowed`。历史全量未证明，后两个中的历史验证和最终写权限始终为 false。

所有属性和可见格式都被去除后，无历史冷读无法判定普通段落以前是否是一条方法。此时允许记录“当前没有可观察特征”的反例，不能猜测内容恢复身份。已知块消失也只报告未知缺失，不自动认定用户确认删除，不生成墓碑、自动复活块、修复属性、分配方法身份或写 AV。

查询采用固定预算及额外一行作为截断证据，超限或 SQL/子块不一致须报告不完整；人为截断输入仅属显式模拟，不能把 slice 后的结果伪装成完整宿主范围。不研究未实证的 moveBlock、嵌套移动、并发快照、大库扫描或生产恢复。

## 后续决策边界

实验已确认主 marker 选择会漏掉损坏源块，增加属性和正文前缀也无法辨认已失去全部特征的历史方法。生产范围设计不能以这类查询的空结果或剩余子集 complete 推导“全部方法为空”或“已完整读取”。保留已知 ID 基线可作为异常线索，但不能替代不随插件数据删除而丢失的原生范围协议，也不能授予自动删除或投影权限。

下一步优先独立验证“全部方法存于原生 AV，每条方法一行”的候选能力，再比较 D1：稳定方法身份、人物归属、完整分页、原生改值与删行的可观察性、删除插件实验缓存及重启后回读。先补各候选的证据差距，再决定事实源；本卡没有采纳新 AV 模型或生产范围/删除规则，#51/#54 继续开放。
