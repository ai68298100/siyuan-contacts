# 原生人物文档联系方式编辑器 UI 探针（2026-10-17）

对应 `AG-RF-004-N1`、Issue #51/#54。只使用 UUID 临时工作区、虚构人物和虚构联系方式；插件包来自当前 `dist`，没有连接日常工作区，也没有修改生产联系人模型、AV、迁移或发布文件。

## 宿主与入口

- SiYuan Kernel `3.8.8-alpha.2`，临时工作区 `C:\Users\Admin\AppData\Local\Temp\SiYuan-Lvct-Contact-UI-5ad90f02-2820-40df-9c63-44681aefc67b`，回环端口 `8934`。
- 安装并启用了当前 `dist` 插件包；浏览器入口为 `http://127.0.0.1:8934/stage/build/desktop/?id=<人物文档 ID>`。
- 两个人物文档：`20261017023221-o5hu049`、`20261017023221-7051ar8`；初始各有三条标记联系方式，共六条。
- Chrome 真实 `browser-desktop` 页面可见读取正文、块属性和人物文档结构。直接把内核地址交给扩展页会触发宿主 `Cross-site requests are not allowed`，本轮通过回环代理为隔离请求注入临时 Token；这是入口限制，不是生产数据证据。

## UI 操作结果

1. **读取：通过。** 编辑器显示微信、邮箱、电话三类标记块；`custom-lvct-contact-method-*` 属性、人物 owner、固定 source 和主值属性均在 DOM 中可见。
2. **手工改值：通过，但发现重写。** 在电话块的真实 `contenteditable` 表面选中并输入新正文后，页面与内核均回读新值，属性 ID、owner、source、type、label、primary、order 保留。编辑器把输入中的换行折叠成单行：

   ```text
   联系方式：电话标签：工作 / 主线主值：是值：+00 999 / +00 888编辑器改值
   ```

   该行为说明“多行正文承载值”不能直接视为编辑器稳定格式，必须在正式契约中决定单行编码或专门编辑器，并保留损失提示。
3. **UI 删除：通过。** 在第二个人物的自定义联系方式块打开原生块菜单，点击“Delete”；页面立即剩余两条方法，SQL 回读确认被删块不再存在。重新打开该人物文档后仍只有邮箱和电话两条，删除结果持久化。
4. **UI 复制父菜单：可达，复制载荷未核实。** 原生块菜单能打开“Copy”父菜单；后续本机前端代码复核确认，父项只展开子菜单，实际复制需要点击其中的完整块 Copy 子项。因此本轮不能声称已成功复制，也没有证明粘贴后的 owner、source、ID 边界或重复检测。

UI 夹具使用独立的 `ui-*` 方法 ID，不符合 N1 纯研究读取器要求的 `method-{hash(owner:sourceKey)}`。上述改值和删除结论限于宿主正文变化、自定义属性留存和持久回读，不能称为严格候选读取器端到端通过。

## 证据边界

本轮把 N1 的“真实编辑器读取、改值、删除和重载回读”从 `host_pending` 细化为已观察项，同时保留以下未验证边界：

- 未验证编辑器复制/粘贴后的身份留存、重复 ID 防护和跨人物归属。读取与刷新不得自动重写 ID/owner；只有显式采纳为新方法才讨论新身份。
- 后续同人物双页面实时刷新及第二页面重载已观察，邮箱恢复值已由 SQL 确认，见 [双页面报告](MULTI-CONTACT-NATIVE-MULTIWINDOW-2026-10-17.md)；同时写、删块竞争和原生桌面多窗口仍未验证。
- 未验证插件停用/清缓存后的 UI 回读、备份恢复、全文搜索、真机和真实用户工作区。
- 多行折叠是本轮宿主观察，不代表已选择生产格式；`candidateContractAccepted=false`、`productionChanges=false`。

因此 `AG-RF-004-N1` 继续保持 `host_pending`，父卡 `AG-RF-004` 继续保持 `candidate`；Issue #51/#54 不能因本轮 UI 子旅程关闭。
