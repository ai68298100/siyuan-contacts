# 原生人物文档全量联系方式可读性实验（2026-10-17）

对应 `AG-RF-004-N1`、Issue #51/#54。本文只记录纯函数研究格式和内存中的原生块模型，不改变生产 `DATA-CONTRACT`、联系人类型、AV、服务、组件或插件存储。父卡 `AG-RF-004` 继续保持 `candidate`。

## 研究问题与候选格式

目标是验证“停用插件或只清除插件数据后，人物原生文档仍能读到全部联系方式和值的含义”是否具备可读性和可核实的最小条件。本实验使用两个虚构人物，每人三条方法，所有值均为合成值。

候选每条方法占一个原生段落块：

```text
联系方式：电话
标签：工作 / 主线
主值：是
值：
+00 111 / +00 222
分机：7 | 备注：<保留> & 🙂
```

正文保留类型、标签、主值和 `值：` 后的完整原文；值中的换行、斜杠、尖括号、管道、冒号、HTML 字符和 emoji 都作为值内容。机器字段使用明确的 `custom-lvct-contact-method-*` 属性边界，包含研究格式、方法 ID、所属人物文档、固定来源键、机器类型、标签、主值和顺序。方法 ID 是人物文档 ID 与固定来源键的稳定摘要，按人物文档作用域隔离；它不由姓名、值、块显示顺序或当前数组位置生成。复制到另一人物、同时改写父文档和 owner 属性但复用旧 ID，均必须停在未知/冲突状态。

同一顺序时以方法 ID 作为确定性次序；旧单值电话中的 ` / ` 默认保留原文，不在没有预览的情况下拆成多条。标签暂要求单行，以避免正文头部和值边界混淆；带换行的标签被拒绝并报告。

## 结果

入口脚本：[contact-methods-native-research.mjs](../../scripts/spike/contact-methods-native-research.mjs)；结果：[contact-methods-native-research-results.json](../../scripts/spike/contact-methods-native-research-results.json)。

```text
node --check scripts/spike/contact-methods-native-research.mjs
node scripts/spike/contact-methods-native-research.mjs
```

结果：**31/31 通过，0 失败**；`syntheticOnly=true`、`candidateContractAccepted=false`、`productionChanges=false`、`kernelRequests=0`、`realPluginFileWrites=0`。

同一候选随后在隔离真实内核中做了独立写读、重启和实验缓存清理探针，见 [MULTI-CONTACT-NATIVE-HOST-2026-10-17](MULTI-CONTACT-NATIVE-HOST-2026-10-17.md)；本文数字只代表纯函数/内存模型，不与宿主结果合并。

覆盖内容：

- 两个人物各三条方法的可读正文写入/回读，含电话、邮箱、微信、自定义类型、标签、主值和顺序。
- 特殊文本、换行、Markdown 记号、` / ` 原文和 emoji 全量回读；同值跨人物不合并，方法 ID 仍按人物作用域独立。
- 块移动和同序重排不改变 ID；同序时 ID 排序稳定。
- 原生正文改值保留方法 ID；原生删块使该方法可观察缺失，但实验不把缺失自动升级为已确认删除墓碑。
- 固定来源键使删除中间方法或插入新方法时，剩余方法 ID 不漂移；跨人物搬运、owner 重写、坏文档/坏块、非法块 ID 和过大的顺序值均被拒绝或报告。
- 复制块但保留机器标记会报告重复 ID；未知格式、未知类型、错误父文档和多主值会报告为未知或冲突。
- 清除实验插件缓存后仍从人物文档回读全部六条方法，且共享值没有被错误重绑。
- 空值、带换行或 Unicode 行分隔符的标签、值中的 C0/C1 控制字符、非法文档/块形状和不安全顺序值被拒绝，保护属性/正文边界。
- `markdown` 与 `content` 不一致的块会被报告，避免把未核实的正文回读当成完整事实。

## 可得结论

在纯函数和内存块模型中，可读正文能够承载所有方法和值的含义；明确属性边界能够区分机器身份和正文。固定来源键、owner 校验和严格的块/文本边界可以阻止跨人物复用、删除/插入后的 ID 漂移及控制字符混入。原生编辑、复制、删除和未知格式不会被静默猜测，清除插件缓存也不会影响模型中的原生事实。这支持把“原生人物文档全量”作为 D1 并列候选继续比较，但不等于已经选定该事实源。

这不是生产格式选择。方法 ID、属性命名、逐方法块形状、标签单行限制和旧 slash 处理都仍是研究约束，不能直接接入生产联系人模型或 AV 投影。

## 未验证边界

- 本文纯函数模型没有访问真实 SiYuan 内核、编辑器、日常工作区或插件存储；真实隔离内核块写读证据单列在宿主探针文档，不由本实验数字代替。
- 本文纯内存实验不证明重启、双窗口并发或原生手工编辑后的持久性。后续独立内核探针已记录重启回读，UI 探针已有正文编辑与重载观察；有效候选身份的 UI 严格读取、双窗口同时写、迟到响应、部分写入和失败恢复仍未验证。
- 没有墓碑、迁移包、备份恢复、全文搜索、AV 主值投影、vCard 往返或大规模 IO 预算。
- 未决定人物文档正文与 AV 主值冲突时的事实源、主值删除和排序规则；未知/冲突只报告，不自动修复或按姓名/值重连。
- 固定来源键只是候选研究约束；真实宿主还需证明块移动/复制时 owner、来源键和属性不会被编辑器静默重写，并确认插入/删除后的 ID 迁移策略。
- 研究解析器拒绝 C0/C1 控制字符及 U+2028/U+2029（值允许 LF 换行）；真实编辑器对 CRLF、软换行、Markdown 转义和属性序列化的处理仍未验证。
- 清除实验插件缓存仅是内存模型步骤，不能替代“删除插件数据目录后真实宿主仍可读”的隔离验证。

因此 N1 的纯格式部分可记为 `done_isolated`，整张卡保持 `host_pending`；Issue #51/#54 和父卡 D1 仍开放。后续 [UI 报告](MULTI-CONTACT-NATIVE-UI-2026-10-17.md)已观察正文手工改值、删除和重载，[双页面报告](MULTI-CONTACT-NATIVE-MULTIWINDOW-2026-10-17.md)已记录实时刷新及最终 SQL 恢复值。UI 使用独立 `ui-*` 身份且正文折行，不能升级为 N1 严格解析通过；格式与不完整读取边界转入 N2。真实复制/粘贴、同时写/删块竞争、插件停用、搜索和备份仍待验，当前执行顺序以 `AGENT-DEVELOPMENT-BACKLOG.md` 为准。
