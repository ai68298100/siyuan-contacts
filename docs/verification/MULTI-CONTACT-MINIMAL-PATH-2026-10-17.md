### 人物补充资料

人物详情在个人备注之后提供“补充资料”：

- 添加、修改、删除多个同名或同值的条目，例如两个电话、多个微信、邮箱、QQ，名称和值均可自行填写。
- 可选顶层分组，例如“联系方式”，条目选择所属分组；最多两层，保留条目稳定身份和同级顺序。
- 删除分组时明确选择保留子条目并解除分组，或连同子条目删除；所有更改先保留在草稿，保存后生效。
- 关闭、切换人物、取消编辑和重新读取有未保存草稿守卫；读取失败、冲突或未知响应保留输入，不把失败读作空资料。
- 每人最多100项，名称80字符、值2000字符；允许空值和多行值。局域网普通 HTTP 下使用安全随机数生成条目 UUID。
- 阅读态支持按分组、条目名称或完整内容筛选，保留命中子项的组头、显示条目数；进入编辑恢复完整草稿，隐藏条目不会因筛选而丢失。非空内容可复制完整原值，失败时提示手动选择复制。

事实源是人物文档下唯一的原生段落，正文含可见 JSON 完整快照，带独立标记、版本与 `ownerDocId`。保存核对原块 ID 与完整编辑基线，写后回读同一块及完整目标快照；未知请求只核实原请求，不重复创建。清空保留原块的空快照。副本归属不符、重复标记或坏格式均拒绝自动认领和覆盖。

这些资料随人物文档备份，停用插件后原文仍在。首版不投影基础主电话/邮箱/微信，不进入全局搜索、快捷联系、AI、桥、vCard 或插件迁移包，界面就近说明此范围。原生编辑器不参与 Web Lock；基线检查和写后核实不等于内核原子 CAS。

实现：`domain/person-fields.ts` → `api/person-fields.ts` → `services/person-fields.ts` → `PersonFieldsEditor.svelte`，经 facade、Workbench 和 PersonDetail 接入现有关闭守卫。

### vCard 多值选择与损失报告

多 TEL/EMAIL/URL 的源序号、TYPE、重复值和空值在预览中可见，空值不可选。用户可以选择本次写入基础字段的值；默认保留电话兼容合并、邮箱/网址首个非空的旧行为。选择后的草稿用于实际写入和原请求重试，结果报告明确哪些候选未保存。诊断文件不包含联系方式。

这是导入主值选择能力；未选候选不会自动转换为补充资料。vCard 导出仍消费现有基础字段。
