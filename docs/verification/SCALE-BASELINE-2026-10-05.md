# 1k/10k 隔离规模基线

## 范围

本次只测已有的纯投影和客户端筛选路径，不连接思源内核、不读取用户工作区、不改变生产 API 契约。数据为合成联系人、组织标记和组织文档。

命令：

```text
pnpm spike:scale
```

## 结果

`12/12` 通过。基线预算为首屏投影 P95 ≤ 100ms、全量投影 P95 ≤ 2s、客户端筛选 P95 ≤ 100ms、单项堆内存增量 ≤ 128MB。

| 路径 | 1k P95 | 10k P95 | 结果 |
|---|---:|---:|---:|
| 联系人首屏投影 | 0.53ms | 0.46ms | 通过 |
| 联系人全量投影 | 1.30ms | 4.81ms | 通过 |
| 联系人别名搜索 | 2.16ms | 9.91ms | 通过 |
| 联系人分组筛选 | 0.56ms | 0.86ms | 通过 |
| 组织首屏投影 | 15.06ms | 0.96ms | 通过 |
| 组织全量投影 | 2.68ms | 59.12ms | 通过 |

脚本同时记录每项的堆内存增量、Node/平台/CPU 和预算结果，完整结果见 `scripts/spike/scale-baseline-results.json`。样本用于发现隔离实现的明显回归，不能推出真实思源 SQL 耗时、内核内存、浏览器长列表或真机软键盘表现；这些仍保留在 `AG-SCALE-001` 和 Host Queue。
