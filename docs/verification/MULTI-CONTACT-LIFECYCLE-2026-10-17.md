# 方法 AV 与人物联合生命周期研究（2026-10-17）

对应 `AG-RF-004-L1`、Issue #51/#54、D3/D4。本轮只验证现有端点在两个受控 AV 中的联合行为，不决定 D1，不接入生产方法库、投影、删除或恢复。

## 信息缺口与前置证据

[A1](MULTI-CONTACT-AV-ROWS-2026-10-17.md) 只删除了非主方法行；[S3-A0](MULTI-CONTACT-AV-CAPABILITY-2026-10-17.md) 只观察主表标量目标的解绑与重绑；[S2](MULTI-CONTACT-RECOVERY-2026-10-17.md) 是假存储/假 AV 的状态机研究。它们没有联合证明“主方法被移除后主表旧值如何保留”或“人物离开名册后独立方法集合如何保留”。

Chrome 控制面仍只有 IAB/MCP Apps，N2-HOST-UI-COPY 保持 `host_pending`。L1 不需要 Chrome，可以先独立补端点能力证据；它不能补上原生编辑、真正复制/粘贴或并发证据。

## 运行前冻结

使用全新 UUID 临时工作区、随机回环端口和持有的 Kernel 子进程，逐 HTTP 请求核实 marker、规范路径与监听 PID。所有人物和值虚构，主表和方法表都由本脚本创建。默认、import、`--dry-run` 不写文件、不发 HTTP、不绑定端口、不启动进程；只有 `LVCT_RUN_CONTACT_LIFECYCLE=1` 开启隔离运行。

只复用已有创建文档/AV、增列、显式 block 主键 detached 方法追加、人物绑定/解绑、官方映射、标量赋值、SQL、render、flush 和 Kernel 启停端点。不试删除/移动人物文档，也不推断未研究的端点参数。请求白名单、预算、超时和重定向拒绝必须由本脚本执行，未知写不重发。

两人物各有一条主电话和一条次电话，共四条方法，使用已有研究 hash 身份、ownerDocId/sourceKey 及八个 text 方法字段。同值跨人保留不同身份；`primary` 只是研究 text 中的 `0/1`，不是宿主内建主值概念。独立主名册 AV 绑定两人物并设 phone 列，初始各明确写入一条主值，共两次 fixture 标量写；后续不自动修改主表。

方法读取采用已实证 pageSize2、额外空页和 pageSize500 对照，核对原生 rowID、八方法字段、稳定 schema/view 和无实质过滤。默认空 Select 的运行时 ID 不能用于宣称全 cell 原样相等；保留完整原始响应，只对明确的方法语义范围作严格比较。人物文档是否可达、当前名册绑定资格、方法源是否完整读取分别报告，不能互相代替。

| 阶段 | 实际操作 | 独立回读及判定要求 |
| --- | --- | --- |
| 基线 | 新建两人物、主名册及独立方法 AV，显式写入主表 phone | 两人物唯一绑定，官方映射与渲染一致；四方法全部合法且原值精确；主表 phone 与指定主方法原值一致 |
| 甲主方法物理移除 | 仅按已核实方法 itemID 显式调用 remove | 回读剩余方法与主表 phone；记录甲次方法 primary、主表旧值及乙数据实际情况。不自动晋升、清空或修补；缺失只报 `unknown-not-delete` |
| 甲主名册解绑 | 仅移除甲已核实的主名册 itemID | SQL 核实甲文档是否仍可达；方法源和 owner 是否仍在；映射与渲染独立核实当前名册资格缺失。源可读不能成为投影许可 |
| 同 docId 重绑 | 显式重新绑定甲的原文档 | 记录实际新 itemID，不断言所有宿主必定换 ID；方法 ID/owner/source/原值与前阶段比较；旧冻结计划不能自动续写 |
| 内核重启 | 停止本轮进程，以原隔离工作区重启，只读 | 独立回读双 AV 与人物 SQL；方法语义、绑定事实和缺失报告与重启前一致；重启阶段零夹具修改 |

“旧冻结计划拒绝”仅是研究诊断器用真实回读作为输入后给出的结果，不是生产服务行为。冻结内容至少包括人物 docId、原主名册 itemID、方法 ID/归属/字段基线；基线变更、原主方法缺失、人物不可达或名册绑定不符均不得返回执行许可。旧主表 phone 即使相等，也不能证明原方法存在，或者授权认领另一个方法。

外层 `writeAllowed`、`tombstoneAllowed`、`historicalMethodScopeVerified`、`D1Adopted`、UI/并发验证始终 false。物理行移除是显式实验夹具操作；缺行不能证明真实用户删除意图，不能由观察结果生成墓碑、恢复方法、分配身份、转移归属或自动重投影。所有业务自动写恒为0。

### 旧冻结计划与检查

研究诊断器收集全部拒绝原因。移除主方法时，同时报告源集合不完整、源基线变化、冻结主方法未精确观察；解绑时另有当前唯一绑定缺失及已观察到解绑；重绑和重启时另有目标itemID变化、phone基线变化。不会因首先发现主方法缺失而跳过绑定检查。所有阶段的`productionGuardImplemented/writeAllowed=false`、`projectionWrites=0`。

纯检查34/34覆盖完整源下itemID变化，以及“观察过解绑但恢复同itemID”仍拒绝旧计划；这两个反例与本轮实际换ID分开记录。曾解绑的history只在实验进程内使用，不能称为持久恢复、跨窗口保护或CAS。

语法、默认/`--dry-run`及import检查通过；拦截fs写/建删、端口创建、子进程与fetch时，import、默认、显式gate加`--dry-run`均无副作用；非法工作区覆盖参数拒绝。只为新研究脚本运行定向验证，本轮没有复跑生产全套；上一轮生产`check`零错误/警告、`test`656/656保持为前轮证据。
