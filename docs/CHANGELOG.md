### 2026-10-14 联系人长列表与资源加载性能

本次按固定 1280×900 Chrome 视口、200 条分页、混合长文本/标签数据进行三次中位数 A/B 实测。5,000 条列表在启用窗口化后，首批卡片呈现 1,431.4→982.4ms、全量加载 12,322.2→1,698.5ms、扩展渲染 2,747.9→251.3ms；扩展 DOM 节点 176,276→945（减少 99.5%）；表格/卡片切换 2,175.0/4,248.6→44.7/49.3ms。首次稳定加载 CLS 两组均为 0.0028。合成滚动的偏移单独记录，不混作 CLS。此处数字为动态行高与触底锚点修正后的最终代码重跑中位数。

新增：联系人长列表窗口化

- 超过 600 条时，卡片和表格只挂载视口附近内容；筛选、排序、批量选择、分页和详情回焦继续使用完整名册。
- 性能采样改用混合高度联系人，并校验中段与底部的滚动位置和数据索引。

优化：图谱依赖与媒体加载

- Cytoscape 使用官方压缩 ESM 入口；入口 JS 减少 5,545 B、gzip 减少 1,685 B，构建仍保持单入口。
- 头像与 Logo 图片声明宽高并异步解码；组织 Logo 延迟加载，避免加载时布局变化。

修复：长列表窗口定位与焦点归属

- 禁用虚拟列表容器的浏览器自动滚动锚定，避免滚动中部时被推到列表底部；窗口即将卸载当前焦点项时，将焦点交给稳定列表容器。
- 移除未经验证的卡片 240px intrinsic 占位；移动空资料卡回到 140px 以内。
- 动态测量卡片行高并按稳定行锚点修正累计偏移；用户触底时保持底部位置，避免长资料加载后跳离末尾。

验证：390×844 手机视口下启用极端长姓名、邮箱和多标签数据，1,000/5,000 条卡片与表格的顶部、中部、底部窗口均通过定位断言。

限制与待办：路由级懒加载仍受单入口宿主约束，架构测试禁止运行期分块；上传头像/外链 Logo 未做格式转码，仓库也没有适合子集化的字体源文件；全部联系人仍需读取到内存。尚未有量化收益证据的重复样式/死导出清理本轮不做。
