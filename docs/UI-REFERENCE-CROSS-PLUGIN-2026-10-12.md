## 状态与文案边界

- 原型中的姓名、数量和结果仍是演示数据，不代表真实宿主读取或写入已经验收。
- 页面级失败优先说明未知范围、未修改范围和安全重试入口；不能把权限失败渲染成“暂无数据”。
- 空结果区分“空库”和“筛选无命中”；联系人原型分别提供新建/导入与清除/新建动作。筛选演示保持页面加载、失败等状态独立，并按稳定人物 ID 同步卡片与表格。
- 部分成功保留已读取结果，只重试失败对象；不会用一个全局成功提示覆盖逐项结果。
- 外部原型中仍为静态演练的按钮、示例数据和未接入宿主的能力没有直接复制到人脉生产实现。

## 未迁移内容

- 其他插件的业务字段、示例文案、紫色或橙色主题值不进入人脉。
- 复杂的批量配额、任务暂停和后台队列暂留在规划区，待人脉服务层和数据契约具备真实任务语义后再实现。
- 头像裁剪、图片格式校验和 CardDAV 同步的完整写入流程需要生产 API 与数据契约证据；原型只保留入口和状态表达。

## 验收要点

1. 桌面、移动端 390px、暗色主题下，白色卡面、文字层级和焦点环仍清楚可辨。
2. 联系人页输入搜索词后按 ID 同步筛选卡片和表格；无结果可清除并恢复焦点；空库能新建/导入；搜索不覆盖读取失败或加载状态。
3. 在真实 390px 视口确认搜索框与清除按钮至少 44px、顶部栏无横向溢出，普通 `/` 可聚焦且 Alt/输入法组合不会抢焦点。
4. `docs/ui-prototype.html` 的状态选择器用于评审页面形态，不作为真实功能验收结论。
5. 新增参考模式必须同步更新本记录、`UI-SYSTEM-SPEC.md` 和原型状态检查脚本，避免规范与原型分叉。
