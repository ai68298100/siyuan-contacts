## 1. 结论

小驴人脉已经从联系人 CRUD 发展成一套较完整的人脉工作台：联系人、关系、组织、本人档案、互动、提醒、跟进、原生任务块、捕获、AI 候选、vCard、备份恢复、资料体检和人员服务桥都已有实现。代码分层、数据契约和故障语义是当前项目的强项，核心域层测试覆盖很深。

当前最需要解决的问题是“实现很多，但完成定义分散”。隔离测试通过不能代表真实思源宿主、Android 真机、多窗口和集市发布已通过；现工作区还有未提交增量，桌面和移动 UI 回归各有 1 个失败。因此当前适合称为“功能丰富的 v0.4.1 开发基线 + 下一版收口阶段”，不适合直接宣称下一版稳定发布。

## 4. 产品主线和完成定义

产品主线应固定为：

> 第一次进入能安全建好数据主干 → 三分钟内完成第一个联系人 → 一次点击能记录真实交集 → 首页能解释“今天为什么联系谁” → 打开人物文档仍能回到同一事实 → 换设备或出错时不会丢数据。

每项开发都要回答五个问题：

1. 用户从哪个入口开始，完成后回到哪里？
2. 数据事实存在哪里，谁是权威来源，是否需要迁移？
3. 加载、空、失败、未知、取消、部分成功和重试分别怎么显示？
4. 桌面、移动、暗色、键盘和读屏是否仍能完成同一任务？
5. 隔离通过后，真实思源宿主、真机、多窗口和发布产物谁负责验收？

## 7. 每个任务必须留下的证据

- 代码任务：对应源码、域层测试、服务/组件回归和失败注入用例。
- 数据任务：DATA-CONTRACT 章节、迁移兼容策略、坏数据和未知结果行为。
