- “隔离测试通过”与“真实思源/真机通过”分开记录；没有宿主证据的项目保持 `Host pending`。

- 关闭待办前必须回填契约、故障用例、页面状态、`PROGRESS.md` 和必要的发布清单。

- K-11（P2 导出边界，关联 C-14/D-09）：人物简报下载文件名直接拼接人物姓名，姓名含 `/\\:*?"<>|` 或超长时可能生成非法/被截断的文件名，且失败没有可见状态。统一文件名清洗、长度上限、冲突命名和下载失败提示，覆盖中文、表情、重复姓名和移动 WebView。
- K-12（P1 读写契约，关联 C-27/H-19）：组织成员写入口只校验文档 ID 形状，未在服务层统一确认组织标记仍可达、人物仍在当前名册以及归档组织是否允许写入；跨窗口删除/归档后迟到的添加或编辑可能产生悬空成员。写前回读对象状态，返回 `stopped/unknown` 与逐项原因，补迟到请求、归档组织和文档不可达回归。

## M. 本轮新增：数据一致性、并发与性能复核（2026-09-30）

- M-01（P0，关联 C-01/C-13）：联系人创建流程 `services/contacts.ts:66-94` 与外部 Bridge 采用“读名册→查可续建文档→创建文档”的非原子检查；并发窗口/Bridge 调用可能同时通过检查，创建重复人物文档和名册行。按姓名/规范化键加锁并重读确认，返回幂等结果与冲突报告。
- M-02（P1，关联 C-24/C-19）：`services/migration-bundle.ts:60-82` 用 `Promise.all` 分别读取互动、跟进、节奏、提醒、收编索引和模板，未共享版本/epoch；并发写入时导出包可能来自不同时间点，恢复后关系不一致。增加跨模块快照锁或 manifest 起止 revision，并报告导出期间发生变化。
- M-03（P1，关联 C-24/C-31）：迁移包预览/导入对“模块字段存在但非法”与“模块缺省”区分不足，`migration-bundle.ts:85-99,120-180` 可能强制 cast 后跳过坏模块且不加入失败报告，出现部分成功无告警。按模块记录 omitted/invalid/accepted，预览和确认阶段都显示坏数据与策略。
- M-04（P1，关联 H-25/K-08）：组织归档/恢复 `services/org.ts:236-252`、改名 `284-305` 均为先读后写，无组织级锁、版本校验和写后断言；并发改名与归档交错可能以旧状态覆盖新标记。增加 per-org 锁、重读冲突和 postcondition，记录恢复/重试结果。
- M-05（P1，关联 G-14/G-15）：人物详情洞察 `services/insights.ts:22-35` 每次全量读取互动库和名册，时间线/共同出席反复扫描全部事件；事件达到 1 万/10 万时会放大延迟和内存。建立按人物/场合索引、窗口分页和失效策略，记录冷/热加载基线。
- M-06（P1，关联 C-25/C-29）：`api/client.ts:76-78` 的 `createDocWithMd` 直接信任内核返回字符串；联系人、组织、vCard 等调用方可能把异常或非合法块 ID 持久化为绑定关系。统一校验 ID 形状、创建后存在性和 timeout unknown，禁止 truthy 非 ID 进入事实存储。
- M-07（P1，关联 C-13/CODE-02.5）：关系写入 `services/relations.ts:62-83` 读取人物后计算，再直接 setCell，没有按人物锁/CAS；并发添加/移除关系时后写可能覆盖先写，造成丢边或误删。按人物串行化、重读合并、写后确认并补双方文档回链校验。
- M-08（P1，关联 C-22/C-29）：跟进任务同步 `services/followup-sync.ts:38-86` 没有按人物/任务同步锁，计划计算、区块追加和属性更新不是原子操作；并发对账或失败重试可能产生重复任务块，best-effort 删除也可能留下歧义。加入稳定幂等标记、串行对账、重复扫描和 ambiguity recovery。
- M-09（P1，关联 C-29/C-28）：`data/storage.ts:31-35` 的 `saveJsonVerified` 使用容错读取做写后验证，读取失败返回 null 时会被当成值不一致并重试同一写入，可能重复执行宿主 mutation。将验证结果区分 `verified/mismatch/read-unknown`，未知时暂停重试并要求回读诊断。
- M-10（P2，关联 C-10/D-11）：互动时间线 `domain/interactions.ts:240` 只按日期排序，交往报表 `review-report.ts:147` 只按日期和姓名排序；同日事件或同名联系人顺序依赖插入顺序，导出和复核结果不稳定。加入 occurredAt、稳定事件 ID 和文档 ID 的 tie-breaker，补重复生成一致性测试。

## N. 本轮新增：业务流程与跨窗口复核（2026-09-30）

- N-01（P1，关联 C-01/C-22）：跟进创建先写插件库再同步人物文档；`services/followups.ts:createFollowUp` 在同步失败时返回复合错误，但用户重试可能再次创建相同计划，形成重复本地事项。为跟进使用稳定幂等键和“已保存待同步”状态，重试只补文档块并回读确认。
