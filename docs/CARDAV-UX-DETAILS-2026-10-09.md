# CardDAV 同步体验细节补充（2026-10-09）

本补充基于 DAVx⁵、Nextcloud Contacts、Google CardDAV、RFC 6352/RFC 6578 的同步流程整理，重点覆盖设置、状态、冲突、错误、空态和恢复动作。它用于后续 CardDAV 接入前的交互和数据模型设计，不代表当前已经支持在线同步。

## 一、设置页面的建议结构

建议把“通讯录同步”拆成三个层级，不要把所有选项放在一个开关旁边：

1. **同步账户**：服务名称、服务地址、用户名、鉴权状态、最近连接结果。
2. **地址簿/集合**：每个地址簿独立展示名称、联系人数量、权限、是否启用、最近同步结果。
3. **同步策略**：同步方向、字段范围、自动同步周期、冲突处理、删除处理和隐私预览。

账户级操作和地址簿级操作要分开：

| 操作 | 作用 | 反馈 |
| --- | --- | --- |
| 测试连接 | 验证地址、TLS 和鉴权 | 只更新连接状态，不改变联系人 |
| 刷新地址簿 | 重新发现服务端地址簿 | 更新集合列表和权限 |
| 同步当前地址簿 | 只处理当前集合 | 显示下载、上传、冲突、失败数量 |
| 同步全部地址簿 | 处理当前账户下已启用集合 | 显示每个集合的独立结果 |
| 重新初始化地址簿 | 清理该集合的本地同步游标后重新核对 | 必须先显示本地未上传改动数量 |
| 断开账户 | 删除凭据和同步绑定 | 不应默认删除本地联系人 |

“刷新地址簿”和“同步联系人”是不同动作。前者只重新获取集合及权限，后者才读取或提交联系人；这样可以避免用户点击刷新后误以为联系人已经同步。

## 二、同步状态模型

地址簿和联系人都应保存可解释的状态，避免只显示一个“同步失败”：

```text
未配置 → 待同步 → 同步中 → 已同步
                         ├─ 部分成功
                         ├─ 存在冲突
                         ├─ 权限失败
                         ├─ 网络失败
                         └─ 需要重新发现
```

每个地址簿建议显示：

- 最近成功同步时间；
- 最近一次尝试时间；
- 待上传、待下载、待删除数量；
- 冲突数量和失败数量；
- 权限（可编辑、只读、共享可编辑、共享只读、未知）；
- 最近错误的可读说明和下一步操作。

状态文案要直接说明动作：

- `同步中`：显示已处理数量，提供取消；
- `部分成功`：显示“已处理 X 条，Y 条需要重试”；
- `存在冲突`：按钮为“查看冲突”，不要只显示红点；
- `权限失败`：按钮为“重新授权”或“改用只读”；
- `网络失败`：按钮为“重试”，并保留上次成功数据；
- `需要重新发现`：按钮为“刷新地址簿”。

## 三、只读和共享地址簿

只读状态可能来自服务器权限，也可能是客户端选择的单向策略。两者需分开表达：

- **服务器只读**：服务端禁止修改；详情页禁用编辑、删除、合并、加入分组，并说明“复制到我的地址簿后可编辑”。
- **客户端只读**：服务端可能允许写入，但本插件不会上传本地修改；允许用户切换策略并预览待上传变更。
- **共享可编辑**：显示“修改会同步给其他共享成员”。
- **共享只读**：显示共享来源和拥有者。

地址簿列表应显示来源标签（本地、个人、共享、系统、外部），联系人详情页也应保留来源。隐藏编辑按钮会让用户困惑，建议保留按钮但置灰，并在旁边解释原因。

删除或停用地址簿前，确认对话框至少显示：联系人数量、未上传变更数量、冲突数量、是否只解除绑定、是否删除本地副本。默认选择“仅停止同步并保留本地数据”。

## 四、冲突体验

服务器返回 `412 Precondition Failed` 或发现本地 ETag 过期时，应进入“并发修改冲突”，不能直接显示通用网络错误，也不能整张 vCard 覆盖服务器内容。

冲突详情分三列：

| 上次同步版本 | 本地版本 | 服务器版本 |
| --- | --- | --- |
| 用于说明双方从哪个共同版本开始分叉 | 当前未上传修改 | 其他设备或用户的最新修改 |

处理方式：

1. 保留服务器版本；
2. 保留本地版本并重新提交；
3. 按字段合并后提交；
4. 跳过本次，稍后处理。

姓名、公司等单值字段需要二选一；电话、邮箱、地址、标签等多值字段可以逐项保留。未知的 `X-*` 字段默认保留服务器值，并提示“本插件无法编辑此字段”。处理完成前不能静默丢弃任意一方数据。

## 五、错误分类和恢复动作

建议内部使用错误代码，界面显示可执行的说明：

| 错误代码 | 用户看到的文案 | 恢复动作 |
| --- | --- | --- |
| `AUTH_REQUIRED` | 登录已过期，请重新授权 | 重新授权 |
| `ADDRESSBOOK_NOT_FOUND` | 地址簿已不存在或地址已变化 | 刷新地址簿 |
| `READ_ONLY` | 此地址簿没有写入权限 | 切换只读或复制到个人地址簿 |
| `SYNC_TOKEN_INVALID` | 服务端同步游标已失效，需要重新核对 | 重新初始化 |
| `ETAG_CONFLICT` | 服务器上的联系人已被修改 | 查看冲突 |
| `VCARD_INVALID` | 服务端返回的联系人格式无法解析 | 查看原始数据/跳过此条 |
| `NETWORK_TIMEOUT` | 服务器响应超时，本地数据未改变 | 重试 |
| `SERVER_5XX` | 服务端暂时不可用 | 稍后重试 |
| `CERTIFICATE_ERROR` | HTTPS 证书无法验证 | 查看连接设置 |

重试要区分安全和不安全场景：GET、PROPFIND、REPORT 失败可以重试；未知结果的 PUT/DELETE 不能盲目重发，应先重新读取 ETag，避免重复创建或误删。

## 六、空态和进度反馈

- 未配置账户：说明“当前仅支持 vCard 文件交换；配置 CardDAV 后可进行在线同步”，同时提供“了解同步字段边界”链接。
- 已配置但没有地址簿：提供“刷新地址簿”与“检查权限”，不要显示空白列表。
- 地址簿为空：显示“服务器地址簿为空”，不要误导成“同步失败”。
- 首次同步：先显示隐私预览和字段范围，再显示“将新增/更新/忽略 X 条”。
- 同步中：显示当前地址簿名称、处理进度和取消按钮；禁止重复点击产生并发任务。
- 同步完成：显示新增、更新、删除、跳过、冲突、失败的数量，并可直接进入对应列表。

## 七、与当前项目的落地优先级

### P0：接入前即可做

- 设置页增加同步状态文案和 `.vcf`/CardDAV 能力边界；
- 设计地址簿权限标签和来源标签；
- 错误文案采用可恢复动作；
- 删除/停用地址簿默认保留本地数据；
- 首页显示冲突和失败入口，而不是只有最后同步时间。

### P1：同步数据模型

- 地址簿级 `syncToken`、`ctag`、权限和状态；
- 联系人级远端 UID、href、ETag、上次成功 vCard 快照；
- 冲突记录保存本地版本、服务端版本、共同基线和处理结果；
- 多值电话、邮箱、地址、组织字段结构化保存。

### P2：接入后优化

- 支持按地址簿暂停/恢复；
- 支持自动同步周期和 Wi-Fi/网络条件；
- 支持未知扩展字段保留；
- 支持冲突批量处理和同步日志导出。
